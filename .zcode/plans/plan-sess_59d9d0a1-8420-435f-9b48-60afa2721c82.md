# 《Space Power》按系统目录解耦重构方案

## 目标与原则

把 27 个扁平编号模块重组为 9 个系统目录，并把 `stepSim` 巨石函数（555 行）拆成各系统的 step 函数。**行为零改变**：

- 所有函数名、全局变量名**一律不改**（保持 grep 可达、localStorage 存档兼容）
- 代码移动一律**逐行原样搬运**，行内版本标记（DS195/KIMI155/TIER1 等）全部保留
- 每个新文件头部加一行拆出来源标记，格式沿用项目约定：`// RF1: 拆自 js/03-ships.js L335-401,纯移动无逻辑改动`
- 不引入 ES module（`file://` 下被 CORS 拦死），维持"body 末尾按序 script 标签"模式

## 新目录结构与完整映射

## stepSim 拆解设计（core/05-sim.js）

编排层保持原 20 段**精确顺序**，段号注释对照原 07-missiles.js 行号：

| 段 | 去向 | 内容 |
|---|---|---|
| S1-S3 | sim 内联 | 感知节拍(detT/detectLoop)、网分配节拍、`taskProcess` |
| S4 | physics/31 `stepShipsMotion` | 舰船运动主循环（编队/命令/刹车/战斗转向/积分，早退 continue 语义保留） |
| S5-S11 | weapons/56 `stepProjectiles` | 上限裁剪→拦截弹预收集→guideMissiles→updateNets→来袭走廊→五弹型主循环→过滤 |
| S12-S13 | sim 内联 | selMissile/pendingMine 清理、hitFX 衰减 |
| S14-S17 | weapons/57 `stepWeaponSystems` | 冷却→自动索敌→CIWS→MAC 自动开火 |
| S18-S19 | sim 内联 | `rangeTargetAI`(typeof 守卫)、`enemyAI`(selfPlay 门控) |
| S20 | sim 内联 | 胜负判定 |

拆解后 07-missiles.js 只剩引导函数（54-missiles.js），stepSim 不再长在武器文件里。

## 分阶段执行（每阶段一个 git 提交 + 验证门）

**Phase 0 安全网**：`git init` + `.gitignore`（out.png/__v.html/demo_*.json）+ 基线提交。编写 `tools/verify.sh`：按 CLAUDE.md 的探针配方生成 `__v.html`（追加探针 script），headless Chrome `--dump-dom` 提取结果。探针内容：
1. **全符号 typeof 扫描**——用 `grep -hE "^function |^const |^let " js/**/*.js` 在基线生成全量符号清单注入探针（try/catch 包裹，TDZ 会报 THREW）。这一项专治"某个 script 中途抛错导致后半文件静默丢失"——移动重构的头号失败模式
2. 运行期检查：无 window error、舰船数>0
3. 行为浸泡：手动 `stepSim(CFG.step); simTime+=CFG.step` 循环 5000 步，检查无 NaN 舰船、敌方 AI 有开火记录
4. 脚本化操作链：选舰→moveFormation→orderMissileSalvo→再步进 3000 步→查靶场统计 rangeTally 计数>0（证明 选择→命令→发射→引导→命中→伤害记账 全链路通）
5. 截图存档供人工比对

在基线跑一遍存参照输出。

**Phase 1 纯移动**：按映射表逐行段搬运建 36 个新文件，`let cv,ctx` 与 adminMode 三全局收编进 core/01，重写 index.html 的 script 列表，更新 icons_preview.html，删除旧 js/*.js（git 留痕）。验证门：符号扫描全绿 + 探针输出与基线结构一致 + 行数对账（旧文件行数总和 ≈ 新文件总和 − 头注释行）。

**Phase 2 stepSim 拆解**：按上节提取 4 个 step 函数与薄编排层。验证门：探针复跑（浸泡步数加到 10000）+ 与基线结构输出逐项比对（因 Math.random 存在，比对结构性指标——各类弹丸数量级、无 NaN、靶场记账>0——不比浮点坐标）。

**Phase 3 文档收尾**：重写 CLAUDE.md 的文件地图/载入顺序/各系统章节路径引用，补"系统目录=类别"约定与状态归属表（谁声明哪个全局）。最终全量探针 + 截图人工过一遍，提交。

## 明确不做的事（本轮范围外）

- 不合并 netGeom 与 recomputeNetOff 两份同族几何（有行为风险，仅同目录放置）
- 不重构 initFleet 的全局 reset 为钩子机制（原样保留+注释清单）
- 不统一 canvas 战术色与 CSS token、不填 TIER_MUL 数值、不改任何玩法数值
- 不改 `icons_preview.html` 之外的任何 HTML id（19/20 的裸 getElementById 绑定依赖 id 稳定）

## 主要风险与对策

1. **script 中途抛错静默丢函数** → 探针全符号扫描（含 TDZ 检测）每阶段必跑
2. **搬运丢行/重复** → 只做行段原样复制 + 行数对账 + git diff 逐文件复核
3. **同文件内顶层顺序破坏**（03 的克隆语句、07 的 GUIDE_SEEK）→ 映射表已标注，拆分时克隆段跟表走
4. **随机性导致无法精确 A/B** → 只比对结构不变量，不比数值轨迹
