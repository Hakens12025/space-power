## RF7 选定链 / 火控计算机方条 备忘(2026-08)

**Shift+中键短按 = 选定入链**(xhQuickEngage 的 append 参数,70-input 抬手时传 `mmb.shift`)。语义:目标追加进当前编辑序列(无编辑序列则等价新建),自动进入序列态;**重复点同一目标去重**(只提示位次,不重复入队)。改前短按压根不看 Shift,按住 Shift 点第二个目标照样 fcNew 新建——追加从来没触发过,这是"Shift 选择没做好"的根因。无 Shift 短按 = 快速交战(fcNew)、长按轮盘、右键(移动/路径点)全部不变。

**序列态 = 主体舰选中且 `fcEditId` 指向自己的序列**,两个入口:Shift+中键选定、火控计算机点方条。表现:83-hud 的 `drawFcChain` 画蓝色数据链(铁路线:主线+每 16px 垂直枕木短刺+目标节点空心圈,`#4fe0ff` 复用 canvas 侧既有强调青),链序 = 舰→T1→T2…,**只画当前编辑序列**;暂停的序列链压暗。挂在 84-scene 的 drawLocks 之后、drawTargeting 之前。退出:再点同一根方条(`fcSetEdit(s,null)`,它本来就支持 null)。

**数据链会流动(RF7d)**:底轨降为暗实线,上面叠一层亮虚线,`lineDashOffset` 随墙钟递减 —— **负的 offset 让虚线朝路径终点走**,方向即 舰→T1→T2(与 `pts` 构造顺序一致)。符号是拿离屏 canvas 实测定的(`off=0` 首个亮点 x=10,`off=-8` 变 x=18),**不是推出来的**:正负搞反了画面同样自然、方向却恰好相反,这类错误肉眼审不出来,只能测。整条链一次成 path(分段画会让虚线相位在每个节点重置,流看着是断的)。用墙钟不用 `simTime`:这是命令可视化不是模拟实体,暂停时该继续流,x50 倍速下也不该变成频闪。**暂停的序列不流动** —— "在但不参与解算"用静止表达最清楚。探针 FLOW6_FLOW 沿链采样像素、推进 0.3s 比较亮段起点位移,断言的是方向符号。

**火控计算机 = 五根竖直方条 + 简要详情**(88-selpanel 重渲,旧富列表的 `.fc-seq` CSS 只藏不删)。一根一槽,`FC_MAX_SEQS=5` 是每舰序列硬上限——**fcNew 触顶返回 null,全部调用点必须处理**(xhQuickEngage 与 radOpen 已接;radOpen 靠既有的 `if(!q)return false` 天然兜底)。方条内容只有序号/模式字/目标数;详情只画序列态那一条(用户定案:信息简单即可)。

**轮盘贴合**(89-radial,纯常量+缝隙):整圆模式楔子取消 1.2° 缝(`sm=split?RAD_SEAM:0`),边线互相贴住双描成径向分隔线,整环读成一体;分环模式左右半径对齐(左半原内缩 10px 读成另一个控件,现同为 62-132),断口 16°→8°、渐隐随之减半。左半层级判据从「更窄+更暗+换色相」收成「更暗+换色相」。FLOW5 的点击坐标拿 radialHit 当预言机,几何改动自动适配,无需改探针。

**序列态跟随选中,不赖在舰上。** `fcEditId` 原本是舰上的持久字段(当初"每舰记自己的编辑序列"的产物),于是上一次建序列留下的上下文会在你下次点这艘舰时被当成序列态复原——表现就是"点一下舰船自动进了火力通道"。现在 `fcEditFollowSel(sub)` 每帧(挂在 command/74 的 `xhTick` 里,排在 `!sub` 早退【之前】:没选中任何舰才是最该全清的一种情况)把非当前主体舰的 `fcEditId` 一律清掉。进入序列态只剩两个显式入口:点方条、或 Shift+中键选定那一下。轮盘开着时不动上下文——`radOpen` 的三种上下文判定依赖它,中途抽走会让"追加"静默变成"新建"。
**关键口径:`fcEditId` 是纯 UI 编辑上下文**,`weapons/58` 的 `stepFireControl`/`fcSolve` 一处都不读它。退出序列态只是面板不高亮、地图不画蓝链,**序列照常解算照常开火**(FLOW6_NOAUTO 用 `fcActive=true` 钉住了这条,免得有人误以为"退出通道=停火"而去改错地方)。

**面板稳定写入(RF7c):按钮闪烁与"菜单按不动"是同一个根因。** `#fcList` 是全项目唯一同时满足「每 20 帧整体 `innerHTML=` 重建 + 带 `:hover` 规则 + 靠事件委托接收点击」三条的容器。光标下的节点每拍换新的 → `:hover` 丢失又命中 → 3Hz 闪烁;而重建若插在 `mousedown` 与 `mouseup` 之间,浏览器把 `click` 派发到两者的**共同祖先**(容器),委托里 `e.target.closest('[data-fc-act]')` 取到 null,这一下点击被静默吃掉("有时候"按不动 = 重建恰好插进去的概率)。修法是 `setHTMLStable(el,html,force)` 两道防线:①内容一模一样一个节点都不动;②光标正指着可点元素(`[data-fc-act]:hover`)时推迟重建,离开后下一拍补上——只挡"指着按钮"那一刻,光标在面板空白处不影响读数刷新;点击后必须立即回显方条高亮,那一次用 `force` 绕过第②道。**往周期性重渲的容器里加 `:hover` 或事件委托之前,先想一遍这条。**

探针:FLOW6 六条(选定链含去重与无 Shift 对照 / 上限 5 / 方条点击进出 / 序列态不自动进 / 面板稳定写入 / 链渲染不炸)。稳定写入那条必须【双向】判定——只测"连刷不重建"的话,一个永不刷新的实现也能骗过它,所以同时判"内容真变了必须重建"。教程已同步(按键表 Shift+中键行、火控计算机一节)。



## SN6 三级星图 备忘(2026-09-19)

新文件 `80-viewtier.js`,与 `80-camera` 共用编号 80(相机只管"怎么换算坐标",它管"这一档缩放在看哪一带";
先例是 `85-settings`/`85-tutorial`)。设计与推导在 `demos/sensors/态势感知V3.html`,这里是移植。

### 一句话

**三层 = 距离梯子上的三个带,层界与缩放的两头【全部由梯子推出】,一个 km/px 都不许写死。**

| 层 | 带 | 主圈(落点让它占短边六成) |
|---|---|---|
| 战术 | 近战 | 主炮射程 |
| 舰队 | 交战 | 雷达发现 |
| 战区 | 接敌 | 被听见 |

层界 = 相邻两个落点的**几何中点** ⇒ 落点必然落在自己那一层里。实测:落点 1033 / 4477 / 8609 km/px,层界 2150 / 6208。

### 为什么不能写死 km/px

演示页那边原来按"舰体 / 舰队图标画多大"定层界,实测战术层视野只有 15 万公里、连主炮射程那一圈都放不进;
而雷达发现与被听见读着最舒服的那一段,两个跳层钮**都落不到**。
玩家在地图上读的是**圈**,不是船 —— 船画成什么样本来就该按屏幕像素自动切,那是另一回事。

### 缩放的两头也是推出来的

- **拉到最近** `kMaxNow()`:让**近防内圈**(引擎里真正按真实尺寸画出来、而且最小的那个圈)的直径占画面九成。
  ⚠ **第一版的锚是错的,是用户实报后量出来的。** 照搬演示页写成"DD 的主炮门直径占 30~60px" ——
  那条规矩在演示页成立,因为那一页把主炮门画成一个你要读的圈;**引擎根本没画它**,锚是悬空的。
  代价实测:总缩放范围从旧实现的 **100,000 倍**塌到 **148 倍**,滚两下就到头(用户:"缩放能力不足")。
  换成近防内圈之后是 **500 倍**,而且这个锚是实的。
  教训:**把一个写死的常量换成"推出来的"之前,先量一遍它推出来的那个区间有多大** ——
  推导站得住不等于结果能用,而"能用"这件事只有量过才知道。
- **拉到最远** `kMinNow()`:我方**最大发现包线**(最吵的发射机 × 最好的耳朵)占画面九成。
  ⚠ 它**刻意不读任何接触的位置**:拿"最远那个接触"去定取景的话,缩放的尽头就会把它的距离漏出来,
  而被动接触的距离正是模型说"不知道"的那个量。包线是我自己的属性,不泄露任何东西。
- 钳位只许走 `vtClampK` 一个口(滚轮与跳层都走它)。两处各写一份上下限是本项目最爱漂移的一类。

### 不硬切

画法走**连续权重** `vtWeights`(和恒为 1、处处连续),换层是交叉淡化;
只有标签与跳层钮的高亮用**离散层** `vtTier`(带迟滞 0.12),免得停在层界上来回闪。
底色与网格墨色都从同一组权重来(`vtBg` / `vtInk`),两边不会分家。

### 网格:嵌套多级(nested grid),不是单级自适应

用户报的第二件事:"缩放的时候会丢整体感知……2、4、6 光秒变成 5、10 光秒,之前的线段就丢了,
无法从疏密的角度给人一种空间关系"。**他是对的,而且根因是一个集合论上的性质。**

- 原来是**单级自适应**:按当前缩放挑一个"好看的步长",用的是 **1-2-5 序列**(工程上叫 Renard 优先数)。
  那是给"只画一级"用的标准做法,但它**不是嵌套序列** —— 5 的倍数不是 2 的倍数的子集,反之亦然。
  实测:扫一遍全缩放范围换档 8 次,其中**3 次粗线一根都不在新集合里**,整张网格重画。
- 要的那个性质叫**嵌套 / 层级细分**(nested grid, strict refinement hierarchy):
  **第 n 级的线必须是第 n+1 级(更细)那一级的子集**。渲染上的标准做法是**同时画若干级、按屏幕密度给透明度**
  —— Blender 视口网格、CAD 的 infinite grid 着色器、slippy map 的 quadtree 分层瓦片都是这一套;
  图表领域的同名物是 major / minor ticks with decade subdivision;地形渲染里的近亲是 geometry clipmap。
- **能嵌套的序列必须是整除链。** 实测三条:`1-2-5` 断链两处 ✗;`1-2-4-8` 全链嵌套但十进制标注难看;
  **`1-5-10`**(`GRID_L(i)=10^floor(i/2)*(i 奇?5:1)`)全链嵌套、相邻比 5/2 交替、标注干净 ← 选它。
  换完之后实测:公里网格 / 光秒网格 / 战区距离环三条,扫全程**断链 0 次**。
- **疏密是免费得来的。** 因为嵌套,一条粗线同时属于它自己那一级和所有更细的级;逐级全画、alpha 叠加之后,
  越粗的线被画的次数越多 ⇒ 自然越亮。major/minor 的层次不用另调一套亮度,它是"嵌套"的直接结果。
- 战区层的**距离环走同一条阶梯**(用户举的 2/4/6 光秒正是它):缩放时已有的环原地不动,
  只在它们中间淡入更细的环。

⚠ 顺带订正一个我上一版的误判:我一度以为"网格变粗"是因为一格瞄了 120px(旧实现是 28~70px)。
密度确实有影响,但**换档的节奏两者都是 8 次、每档存活约 2 倍缩放,本来就一样** ——
真正的原因是缩放范围塌了(见上一条)加上这里的断链。**先量再改,别按第一印象改数。**

判据 `FLOW57_GRIDNEST` 五条,两个变异被抓到(阶梯退回非嵌套 / 只画一级)。
**反向对照内建在判据里**:同一段检查同时跑新阶梯与 1-2-5,前者须 0 次断链、后者须有断链 ——
不这么写的话,一个恒返回"没断链"的检查器同样能全绿。

### 顺带修的一个老毛病:天不该有尺度

接上三级星图之后,战区层上**整片星空塌成画面中间一小块、边界清清楚楚** —— 星云与星点原来都乘 `cam.zoom` 跟着一起缩。
正确的模型是:三层视图换的是**地面**的画法(网格、刻度、圈),**天是同一片**,它无限远、不该有尺度。
改成屏幕空间 + 固定换算的视差漂移(`STAR_DRIFT`),按视口取模。
⚠ 星云**不许平铺**:那是 40 个随机色斑画在一张 1024 的图上,四条边不接缝,平铺时接缝是几条笔直的对角线,
比露边还难看(第一版就是这样,截图上当场看见)。改成**一张**拉到比视口大四成、在那四成余量里滑,永远盖满、永远不露边。
(星云后来被用户否掉、整段已删,见上一节末尾的 ⚠;天现在只剩星点。)

⚠ **星点是每次开页面现 `Math.random` 出来的**(`core/99` 的 `stars`),SN6 之后又画在**屏幕空间**里
—— 于是它会随机落在任何一个按像素取样的判据的取样点上。`FLOW41_FMPLOT` 的"站位小圈亮度"原来取
20 个采样点的**最大值**、判 `<100`:同一份代码连跑 5 次,4 次 83、1 次 125(一颗星正好压在采样圈上),
**判据自己随机翻红**。改成取**中位数**(圈在 335 / 圈不在 24,比最大值 406 vs 83 还干净)——
20 个点里被星打中的只有一两个,中位数不动。这是 `FLOW31_FOLLINE` 那条"行峰值改行积分"的同一条教训:
**随机星场上不许用单点绝对阈值**;要么换成对少数离群点不敏感的统计量(中位数 / 积分),要么做成开关前后的差值。

### 判定

`FLOW55_VIEWTIER` 五条,四个变异**全部被抓到**(层界写死 / 改掉拉到最近的上限 / 权重和不为 1 / 把钳位拆掉):
① 梯子一动 T1/T2 必须跟着动、还原后逐位复原(**写死 km/px 的实现在这一步露馅**);② 三个落点各落在自己那一层里;
③ 权重和恒为 1 且非负(九点取样);④ 缩放两头都有依据;⑤ 钳位真的接在滚轮上(往两头各滚 50 下都停在限上)。

### 三层地面:每一层有自己的语言

三级星图换的**不是同一张网格换个颜色**,是【地面的画法】:

| 层 | 地面 |
|---|---|
| 战术 | 公里网格 —— 这一带读的是射程与队形 |
| 舰队 | **光秒网格 + 边缘刻度** —— 读起来是一张图不是一块格子布;这个尺度上有意义的单位是光秒 |
| 战区 | ~~以我方重心为心的距离环 + 方位辐条~~ **SN7d 已删**:现在与舰队层是同一张光秒网格(固定资产 + LOD),刻度写「光秒」,见上面 SN7d 一节 |

三者按 `vtWeights` 的权重**叠加**淡入淡出。距离环刻意以我方重心为心而不是画面中心:它要回答的是"相对我"的距离,
而且这样做**不读任何接触的位置**(同 `kMinNow` 那条纪律)。

⚠ **程序星云已删**(那是 40 个随机色斑画在一张 1024 的图上)。用户 2026-09-19:"背景的各种五彩斑斓色块是什么,不要这个"。
它本来就不属于这套视觉 —— 层次感由底色 + 各自的地面语言给,再糊一层随机彩斑只是噪声,而且在战区层上会露出它自己的边界。

## SN6 LOD 聚合层 备忘(2026-09-19)

新文件 `82-lod.js`,与 `82-ship-icons` 共用编号 82(它决定"这一档缩放下,每艘船还画不画")。

### 三层,按【屏幕像素】切,不按视图层切

舰 → 舰队框(一支编队的屏幕直径 < 60px)→ 舰队组(两个框的屏幕间距 < 48px)。
**为什么不绑在三级星图的层上**:船画成什么样本来就该看它在屏幕上占几个像素 ——
同一层里,队形散开时该展开、挤在一起时该塌。绑层会让"我明明拉近了却还是个方框"。
塌/不塌、聚/不聚都带迟滞(记住上一帧的结论),否则滚轮停在阈值上会来回闪。

更糟的是**结果看来路**:从战术直接跳战区,过冲先冲过层界、再靠迟滞留在第 3 层 —— 同一个画面、同一个落点,钮却是对的。
(本项目的铁律:同一个画面状态不许因来路不同给出不同读数。)文件头那句「画布一变,层界自己跟着动」此前并没有兑现。

**修法**:`vtApply` 记下这次是按哪个短边推的(`_vtShortAt`),`vtFrame` 每帧比一次,变了就重推。现在任何画布上落点处的画法权重都是 0.95 属于目的层。

**判定**:`FLOW69_TIERLAND` —— 三种画布 x 从每一层出发 x 按每一个钮(27 种走法),落地后离散层 / 亮着的钮 / 画法权重都属于目的层;层界随画布变。
变异(去掉重推)被抓到,而且读数里直接看得见来路依赖(`1→3 层=3`、`2→3 层=2`)。

**为什么原来的判据没抓到**:探针的视口是 762x484,短边 484 —— 比 750 小,落点反而离冻住的层界更远,怎么按都对。
**与画布尺寸有关的东西,判据必须自己换几种画布去量**(FLOW68 ④ 是同一条做法)。

**修完之后「两层差异不大」还剩下的那一半**是结构性的,不是 bug:① 两个落点的比例尺只差 1.92 倍(雷达发现 65 万 vs 被听见 125 万);
② 引擎的战场只有 100 万公里宽,舰队层落点的视野已经是 360 万 x 200 万 —— 两层里所有东西都是画面正中的一小团;③ 每层看不同的东西(SN8 的 B 方向)还没做。
见 `todo-plan.md` 2.11 I 与第 3 节。

## SN9 舰体大小随缩放变 备忘(2026-09-21)

用户:「拉近了船不变大,拉远了船不变小。没有办法做出很直观的空间关系」。改前舰体是固定屏幕尺寸的贴纸,地图在它底下滑。
他记得「之前针对这个问题做过什么工作」—— 那是演示页的 `lodHullLenPx`(舰体按命中半径放大),搬 SN6 聚合层时只搬了聚合那一半,这一半一直挂在待办里。

### 标准叫法

制图综合里的**夸张算子**(exaggeration,McMaster & Shea 1992)+ **按缩放插值的符号尺寸**(Mapbox 样式规范的 `interpolate` / `exponential`,地图上的路宽与图标都这么画)。
真实舰体约 1 km、舰间距约 2 万 km,任何可用的缩放下船都是亚像素 —— 船**必须**画得比真实大,问题只是夸张多少、随缩放怎么变。

### 为什么不照搬演示页

演示页那一版只治一半:79 km/px 以内才开始放大,**拉远不缩**(钳在固定图标上)。而且它的最近缩放是 60 km/px,引擎是约 15 km/px(由近防内圈推出),
原样搬过来 CA 拉到最近是 130 px。

### 拍板的律(三选一,用户选了第一个)

缩放范围约 360 倍,图标能接受的尺寸范围只有 4 倍左右,所以「按世界尺寸同步缩放」(指数 1)只能在一个 4 倍的窗口里变、窗口外两头钳死。

| 方案 | 律 | 结局 |
|---|---|---|
| **亚线性、全程响应** | 系数 = (缩放 / 战术落点的缩放)^0.4,钳在 [0.5, 1.9] | ✓ 139 → 3926 km/px(28 倍)每滚一格都在变;缩放翻一倍船大 1.32 倍 |
| 世界锚定 | 指数 1 | 船与间距的比例恒定,但只在 365 → 1388 km/px 里变 |
| 照搬演示页 | 只放大不缩小 | 治不了「拉远不变小」 |

常数只有一张表:`82-ship-icons` 的 `HULL_ZOOM={A,MIN,MAX}`;唯一的出口是 `hullZoomF()`。CA(T2)舰长 12.6 → 25.3(战术落点,与改前相同)→ 48 px(演示页预算 B5 的 `HULL_PX`)。

### 三条要记住的

1. **系数是全场同一个数,不读任何一艘船的字段。** 所以它不泄漏情报:没认出的敌舰照旧 `UNK` + T2,只是跟着大家一起变。
   演示页那一版按 `size` 放大,才需要专门立「没认出的不放大」那条规矩;这一版没有这个口子 —— **别把 size 乘进来**(变异 m9 钉着)。
2. **锚点从视口现量**(`vtFitKmpp(vtMainR(1),VT.LAND)`):战术落点随画布短边变(1600x1000 是 500 km/px、800x480 是 1042),
   写死公里数的话「落点上的船 = 改前的大小」只在一种画布上成立(变异 m4 钉着)。
3. **跟着舰体走的东西要一起乘**:残骸、`shipIconR`(标签间距 / 选中圈 / 吸附圈 / 轮盘内圈都读它,自动跟)、尾焰长度、被照射告警圈、锁定圈、移动虚影。
   **不跟的**:陈旧 / 失联的记号(`CONTACT_MARK_R`)—— 它不是船,是「我不知道这是什么」的记号;速度箭头、血条。
   ⚠ 残骸只包舰体那一笔:同一个变换里的裂纹用的是传进来的 `r`(已含系数),一起包进来会被乘两次(第一版就写错了)。

### 判定

`FLOW68_HULLSIZE` 四组:① 律(落点上恰为 1、翻倍 = 2^A、两头钳住、60 档全程单调且相邻不跳、CA 最大不超过 48.5 px);
② 七样东西在三档缩放下量到的都是同一个数(钩 `drawHull` 读调用那一刻的真实变换、钩 `arc` 读半径、钩 `moveTo/lineTo` 量焰长);
③ 迷雾(没认出的画 UNK/T2、系数与我方**逐位**相同;反向对照:认出后大小舰必须不同);④ 两种画布各自的战术落点上系数都是 1。
十二个变异全部被抓到,每个只翻该翻的那一格(m4 写死锚点连带翻 ①②,因为判据自己的期望值也是从落点现量的)。

⚠ 变异测试顺带炸出一条老判据:`FLOW6_PULSE` 按写死的 13 px 采样告警圈,而圈现在是 13 x 系数 —— 没变异时它过,只是因为那条判据的缩放下系数恰好接近 1。
已改成跟着 `hullZoomF()` 采样。**给画面加一个「会改变东西画多大」的系统时,先 grep 一遍判据里写死的像素半径**(与 SN6「聚合会污染别的判据」是同一类)。

### 刻意没动

聚合阈值(`LOD.FLEET_PX` / `GROUP_PX`)是按改前的固定图标定的:拉远后图标缩到一半,舰队其实可以更晚才塌成框。没改 —— 先看手感。
点选半径 `60/cam.zoom`、轮盘内洞 62 px:最大图标半径约 22 px,都装得下。

## SN8 换挡感 + 聚合动画 备忘(2026-09-21)

用户:「三个视角的切换感觉不是特别优秀,就像是很简单的换了一下颜色,有没有更酷的方案」。他是对的 ——
SN7d 把战区层的放射环删掉之后,舰队层与战区层是同一张光秒网格,剩下的差别只有底色、线色和刻度上的字。

### 标准叫法

**语义缩放(semantic zoom)**:不同缩放级别显示的是不同的【信息】,不是同一批东西换个尺度、换个颜色;
制图学里叫**地图综合(cartographic generalization)**。游戏里的范本:《最高指挥官》的战略缩放(单位无缝变成图标)、
《家园》的传感器管理器(拉远后换一套画面语言)。提了三个方向,用户拍板**先做 A 和 C**:

| | 内容 | 状态 |
|---|---|---|
| A 换挡感 | 跨层那一下像仪器切了模式 | ✓ 本轮 |
| B 每层看不同的东西 | 舰队层的合成包线、战区层的航迹尾巴与信息时延读数…… | **等拍板**(每层放什么是玩法决定,记在 `todo-plan.md`)|
| C 聚合动画 | 舰船收进舰队框 / 从框里散开带过渡 | ✓ 本轮 |

### A 换挡感(`80-viewtier`)

- **四边刻度尺 `drawEdgeRuler`**:屏幕空间的仪器边框。刻度 = 当前这一层网格线与画面左缘 / 顶栏下沿的交点,长短三档(跟着嵌套阶梯的三级走);
  战术层顺带写公里读数(舰队 / 战区层的光秒读数仍由 `81-background` 的 `vtGridLs` 写,位置对齐)。**换层时刻度从 0 重新长出来**(0.45 秒)。
  它的起点 `VT_RULER_T0` 与大字**分开记**(SN8b):手动缩放跨层时刻度尺照样重长一次 —— 它的单位真的换了(公里 ↔ 光秒),长出来是在说这件事,不是在弹特效;
  跳层途中路过的层不算(`vtFrame` 开头记的 `jumping`,要在推进动画**之前**记:动画走完的那一帧 `vtAnim` 会被清掉,而那一帧的换层仍属于这次跳层)。
- **换挡大字 + 扫描线 `drawTierFx`**:打目的层的名字「FLEET / 舰队层」,两条扫描线从中线向上下扫开(拉远)或从上下合拢(拉近),0.7 秒内淡出。
  **触发点只有 `camJump`(跳层钮)一处,起跳那一刻就直接报【目的层】**(SN8b,用户 2026-09-21 拍板,两条):
  ① **手动滚轮缩放跨层不弹** —— 那是连续的操作,你自己正盯着画面在变,再弹一个大字是打断;
  ② **战区直接跳战术(或反过来)不弹中间那个舰队层** —— 镜头只是路过它,你要去的不是那儿。
  第一版挂在 `vtFrame` 的「离散层变了」那一处,两种情形都会弹。同层再按一次(只是把镜头摆回落点)不算换挡,也不弹。
  ⚠ 大字放在上方三分之一处:第一版放正中,而画面正中是镜头盯着的舰队,截图上当场盖住。
- **跳层镜头带过冲**:`camAnimStep` 的缓动换成 easeOutBack(系数 1.15,对数空间里冲过头约 5%),时长 340 → 420ms。
  顺带修了一个老毛病:到点原来走 `exp(log(k1))`,一来一回差出最后一两位;现在到点**直接落在** `k1` 上(判据逐位比的时候才对得上)。

### C 聚合动画(`82-lod`)

聚合的【结论】(谁被收进哪个框)**照旧是即时的** —— 拾取、判据、迟滞都读它,不受动画影响。动画只管「画成什么样」:
每艘船记一个收拢度 `_lodE`(0 = 在自己的位置上,1 = 完全收进框里),每帧朝结论走一步(0.25 秒,墙钟)。

- 收拢:船的图标滑向框的位置并淡出,框同步淡入(`a.alpha`)。
- 散开:框当场消失,船从框原来的位置滑回来并淡入。`_lodW` 记的是框的**世界坐标** —— 记屏幕坐标的话,过渡期间镜头一动船就飘。
- render 的舰船循环改调 `lodDrawShip`,不再直接调 `drawShip`。
- ⚠ **第一次见到的船直接落到结论上**(不播动画):开局、换局、判据里现造的船都不该先「收拢一次」。
- ⚠ **`e<=0` 时原样调 `drawShip`,不包那层 `save/translate`**:有几条判据按 canvas 指令计数,多一次 translate 就是一次假红。

### 性能(SN7d 的教训直接用上了)

全部是轴对齐 `fillRect` + `fillText`,不画 path、不画圆、不建渐变。真实 GPU、**DPR=2** 复测九种情形(含「反复跨层,特效一直在播」
「舰队反复收拢散开,动画一直在播」)**全部 240fps、零慢帧**。

### 时钟

三样全走墙钟(界面不是模拟:暂停时照样要有,倍速一提也不该变快)。判据在同一毫秒里连调,走墙钟一步都推不动,
所以 `drawEdgeRuler(nowIn)` / `drawTierFx(nowIn)` / `lodBuild(dtIn)` 都收一个可覆盖的时钟 —— 与 `camZoomStep(dtIn)` 同一条惯例。

### 判定

`FLOW67_TIERFX` 四组:A1 **手动缩放连跨两层大字一次都不触发**(刻度尺要重长)、**战区直跳战术起跳即报战术层、途中确实路过舰队层而大字的层号一次都没变过**、
同层再按不弹、画出来的是目的层的名字、0.7 秒后一笔不画(跳层那一段是改 `vtAnim.t0` 让 `vtFrame` 自己按墙钟算进度 —— 走的是生产路径,不是手摇 `camAnimStep`);A2 刻度尺换层那一刻 0 根、随后长出来、全是矩形、战术层写公里;
A3 过冲存在且终点逐位等于落点;C 结论即时而画面 0 → 0.5 → 1 带过渡、半程船被平移到中途、首见不播、静止时不包过渡变换。
六个变异全部被抓到;SN8b 再加四个(离散层一变就弹 / 同层再按也弹 / 途中路过的层让刻度尺重长 / 大字报的是出发层),也全部被抓到。

⚠ 判据自己踩了一次:A3 那格的读数第一版在拼字符串时现读 `cam.zoom`,而后面 C 段已经改过它 —— 判定是 true、打印却是 false。
**判据里的量当场记进变量,别在拼读数时再现读。**

### 顺手删的

`lodHidden`:render 改调 `lodDrawShip` 之后零读点(用户 2026-09-20「没用的都删」)。

## SN7d 网格改成固定资产 + LOD,战区层的放射距离环删掉 备忘(2026-09-21)

用户两条:「缩放的时候依然卡卡的,特别是最大的战区级别,移动地图有很大的延迟」;
「网格直接用固定资产,就不要战区级别以舰船为中心的放射地图了,固定资产 + LOD 来表达地图,依然区分战术-舰队-战区」。
**两条是同一件事:卡顿 100% 出在网格层,其中放射距离环是最大的一块。**

### 怎么量出来的(这次前两种量法都量不到)

| 量法 | 结果 |
|---|---|
| 无界面 Chrome,JS 里给每层套计时 | 战区层每帧 0.25ms,零慢帧 —— **量不到**(画布指令只是被录下来,光栅化不在 JS 时间里)|
| 真实 GPU + 真实时间(CDP 驱动,量 rAF 到 rAF 的帧间隔),DPR=1 | 全程 240fps,连交战场景也是 —— **还是量不到** |
| 同上,**DPR=2**(`--force-device-scale-factor=2`,画布 3164×1808)| **舰队层平移 25~33fps、战区层缩放 30~75fps**,大半的帧超过 25ms ← 在这儿 |

逐层关闭归因(DPR=2):关星空 / 关热区没有变化;**关网格 = 240fps**;只关距离环 = 75 / 240;只关光秒网格 = 61 / 86。

**根因**:DPR=1 时 1px 的线走 GPU 的发丝线快速路径;DPR=2 时同一条线是 2 物理像素宽,而几百条线被合成**一个包围盒盖满整屏的大 path** 去 `stroke` ——
浏览器把它整屏光栅化成一张遮罩再上传,每帧、每一级各来一次。几十个大圆的距离环同理,而且更贵。

工具留在 scratchpad 没进仓库;方法记一笔:Node 22+ 自带 `WebSocket`,`chrome --headless=new --remote-debugging-port=N` 之后
用 `Runtime.evaluate(awaitPromise)` 在页面里跑 rAF 循环、量帧间隔,就是一个不装任何依赖的真实帧率探针。

### 改成什么

- **放射距离环整个删掉**。它不是固定资产(圆心跟着舰队重心走,舰队一动整张图跟着挪),又是全场最贵的一层。
- **战区层与舰队层是同一张光秒网格**(同一份资产,LOD 自己退到更粗的那几级)。区分三层靠:底色(`vtBg`)、墨色(`VT.INK`)、
  刻度写法(舰队层 `ls` / 战区层 `光秒`)与单位(战术层是公里网格)—— 不靠换一种几何。
- **线的画法**:每条线一个**轴对齐的 `fillRect`**(坐标取整,对齐逻辑像素),不再合成大 path 去 `stroke`。轴对齐矩形直接走 GPU 批处理。
- 网格线的位置只由世界坐标决定(锚在世界原点、步长走嵌套阶梯),与相机、与任何一艘船都无关 —— 这就是「固定资产」:
  平移、缩放、换层,地上的线**原地不动**,变的只是哪几级淡入淡出。

**改后同一套测量(真实 GPU、DPR=2):七种情形全部 240fps、零慢帧。**

### 刻度只许一层写,而且跟着离散层 `vtCur` 走

舰队 / 战区交叉淡化的那一段两层同时在画,而它们是同一张网格 —— 两层都写刻度的话 `0.5 ls` 与 `0.5 光秒` 会叠在同一个位置上。
线两层都画(那才是交叉淡化),刻度只让一层写;哪一层写跟着 `vtCur`(左上角层名与跳层钮高亮读的那个量,带迟滞),
不按权重大小挑 —— 迟滞带里会出现「层名写着舰队层、刻度却写光秒」。

### 判定

`FLOW57_GRIDNEST ③` 从「距离环走同一条阶梯」改成**三层都是固定资产的画法**:逐层量 `drawGrid` 发出的指令 ——
`arc`=0、`lineTo`=0、线全是 `fillRect` 且条数有界、刻度恰好一种写法。**判结构不判毫秒**:这次的卡顿在探针(DPR=1、软件光栅)里
耗时只有 0.3ms,判耗时的话这条永远是绿的。三个变异全部被抓到(线又合成大 path / 战区层又画回一圈环 / 两层刻度叠在一起)。

⚠ 判据自己踩的两次:
1. **取样缩放写死 4477 km/px** —— 层界跟着视口走,探针那个小视口里 4477 已经是战区层占优,舰队层那一格当场假红。改成从 `VT.T1` / `VT.T2` 现算。
2. **只在三个层带正中取样,「两层刻度叠在一起」的变异抓不到** —— 层带正中另一层的权重早就是 0 了。补了一个落在交叉淡化带里的取样点(层界的 1.2 倍)。

### 顺带修的一个老 bug:舰队框写成「编队[object Object]」

`82-lod` 的分组键拿的是 `fmOf(s)` 返回的**编队对象**而不是 id:标签印成 `编队[object Object]`,而且 `next.fleet[fl]` 把对象转成字符串当属性名,
**所有编队的迟滞状态撞在同一个键上**。SN6 起就是这样,只是那时开局没有编队、画面上看不见;SN6b 开局就有编队之后,这次截战区层的图才露出来。
`FLOW60_START ②b` 钉着它(拉远后舰队框须为 `fleet:1`),变异被抓到。

### 教训

**性能问题要在用户那种显示配置下量。** 高分屏(DPR≥1.5)会让 2D 画布的一批「本来很便宜」的操作掉出快速路径:1px 的线、整屏大 path、大圆。
DPR=1 全绿不代表没问题。

## SN7b 星空逐颗画导致周期性卡顿 备忘(2026-09-20)

用户实报:「为什么现在网页卡卡的」。**是 SN6 三级星图那一轮我自己带进来的回归。**

### 怎么量出来的(平均值会骗人)

先给每个绘制层套计时、各种情形各跑 150 帧:**平均每帧只要 0.3~1.1ms**,看不出任何问题。
再按真实帧循环(模拟 + 渲染 + 面板 + 快照)逐帧计时、把超过 8ms 的帧单独拎出来:
**每隔一两秒就有一帧渲染要 15~100ms**,90 秒里 47 个,而且**开局放着不动就有**;逐层归因,几乎全部落在 `drawStars`。
「卡卡的」是**慢帧的频率**,不是平均耗时 —— 只看平均值这个问题根本不存在。

### 根因

SN6 把星空从世界空间改成屏幕空间(为了修「拉远后星空塌成画面中间一小块」)。旧实现有一句视口裁剪
`if(sx<-2||sx>W+2||…)continue`,常用缩放下 1200 颗星只画得到一小部分;改成屏幕空间取模平铺之后
**1200 颗每帧全在视口里**,每颗还各切两次 `globalAlpha` —— 每帧 1200 次 `fillRect` + 2400 次状态切换。
交替改状态会打断画布的批处理,命令缓冲被周期性撑爆、同步冲刷一次就是一个卡顿。

### 修法

星空在屏幕空间里除了一点视差漂移之外是**静止**的,所以照热区层(`HEAT`)的同一个做法:
两层各预渲染成一张离屏贴图(`STAR_TILE`),只在视口尺寸 / DPR / 星表变了时重建;每帧按漂移量取模、贴 1~4 次铺满视口。
画面与逐颗画等价(`sx = mod(基准 - 漂移, W)` 就是整层平移 `mod(-漂移, W)`);贴图按**物理像素**建,否则高 DPR 屏上星点会被放大成一团糊;
压在贴图边上的星在对边补一笔,平铺接缝处才连得上。**改后同一套测量:90 秒慢帧 0 个。**

### 判定

`FLOW65_STARS` **刻意不判毫秒** —— 耗时随机器与是否走 GPU 变,判它只会得到一条随机翻红的判据(本项目的性能台一律只报数不判红绿)。
判的是**结构**:每帧发出的绘制指令数是个确定的量,逐颗画是 O(颗数)、贴图是常数。
① 每帧主画布 0 次 `fillRect`、2~8 次 `drawImage`;② 第二帧**不重建贴图**;③ 贴图里真的有星;④ 视差还在且近层漂得更快。
三个变异全部被抓到(每帧重建贴图 / 两层漂移相同 / 逐颗画混回来)。

⚠ ② 第一版只比「是不是同一个 canvas 对象」,**没有牙**:每帧重建时复用的就是同一个对象,而每帧往离屏画布上画 1200 颗,
卡顿原样回来、主画布上却一次 `fillRect` 都看不到。改成盯**贴图自己的上下文**发了几笔。

### 教训

**把「按视口裁剪的世界空间元素」改成「屏幕空间元素」时,先数一遍每帧的绘制次数** —— 裁剪是隐形的性能预算,
改坐标系的同时就把它拿掉了,而画面看起来完全正确。

## SN7 定位几何小窗(缩圈图)备忘(2026-09-20)

## SN6f 接触显示:一个状态机、五态互斥 备忘(2026-09-20)

用户实报:「只要存在某种热源的三角箭头,就不显示热区……现在会出现一种**只显示椭圆和陈旧、但是不显示热区**的情况。
我总觉得这几种信息显示在做进引擎之后就**没有对过,全是揉在一起的**」。—— 字面意义上的事实。

### 根因:两套状态机各驱动一半显示层

| 状态机 | 依据 | 分出来的态 | 哪些层听它的 |
|---|---|---|---|
| 旧的(SN4) | `seenBlue` 的年龄(多久没被**光学或照射**扫到)+ `lit` | 实况 / 陈旧 / 幽灵 | 舰标、记号 |
| 新的(SN6) | 椭圆 `cov` 的 `fix` / `n` | 定得出 / 定不出 | 热区、椭圆 |

两边各自都对,合起来就是谁也没设计过的组合。用一段真实序列逐拍 dump 量出来的:
`转静默后 40s lit=1 fix=false 通道=lis | 旧状态机=stale || 热区=■ 记号=■stale` —— **热区 + 陈旧同时画**;
静听交叉定位握着 `fix` 而 `seenBlue` 在老化时则是**椭圆 + 陈旧、无热区**(用户报的那个)。
「有三角箭头就没热区」也不是规则,只是 UNK 图标(`lit=1 & fix`)与热区(`lit>0 & !fix`)碰巧互斥的副作用。

### 现在:`contactState`(sensors/21)一个函数,全部从 `cov` 派生

| 态 | 条件 | 热区 | 椭圆 | 舰标 | 记号 | 虚线不确定圈 |
|---|---|---|---|---|---|---|
| `none` | 从没发现 / 失联超过 30s | · | · | · | · | · |
| `heat` | `lit>0` 且定不出位置 | ■ | · | · | · | · |
| `live` | 定得出位置、这一拍有量测 | · | ■ | ■ | · | · |
| `coast`(陈旧)| 定得出位置、但量测断了(`n=0` 且超过 1.5 拍)| · | ■ | · | ■ | · |
| `ghost`(失联)| `lit=0`、曾经定位过、30s 内 | · | · | · | ■ | ■(许可)|

四个显示层(`83-hud` 热区 / 椭圆、`82-ship-icons` 舰标 / 记号)与 `82-lod` 聚合**只许问它**,不许各写一份条件。

- **命名对齐**:`coast` = 雷达航迹管理的标准词 **coasted track**(滑行/外推航迹):航迹还在、但这一拍没有量测更新它,
  不确定度按过程噪声长大。`23-cov` 的 `FADE_LOST` 注释用的就是这个词。UI 文案仍叫「陈旧」。
  旧口径的「陈旧」(多久没被光学/照射扫到)在 SN6 里**没有对应物** —— `lit>0` 的接触按定义就是此刻有信号的。
- **陈旧态不另画不确定圈**:椭圆自己就在长大(`FADE_LOST` 复利),它就是「我有多不知道它在哪」。
  再叠一个「速度×年龄」的圈,就回到 SN6e 订正过的「两个圈各说各话」。失联态已经没有椭圆了,才由速度×时长给圈。
- **`coast` 带 1.5 拍迟滞**:量程边缘的接触会隔拍掉一次量测,不带迟滞的话舰标与记号每秒互换一次。
- **`seen*` 的刷新规则跟着换**:从「这一拍有光学或照射量测」改成「这一拍**定得出位置**(`c.fix && c.n>0`)」,写进去的是估计 `c.x/c.y`。
  旧规则两头都错:光学单站远距离只给方位(`fix=false`)却把**真值坐标**写进 `seenPos`;多站静听交叉明明定位了却不刷新。
  DS183 那条纪律原样成立 —— 单站静听永远 `fix=false`,进不来。
- **聚合层只聚 `live`**:陈旧/失联是记号、热区是场,收进一个「群·N」菱形里就把那层意思抹掉了。

### 判定

`FLOW63_VIEW`:**A 半**逐态构造、量五层(拦 `ctx.ellipse` / `drawHull`(只数红方)/ `ctx.arc`+`setLineDash` / 热区读 `HEAT.img` 的真像素),
每一态必须恰好画表里那几层;**B 半**跑一段真实序列(开局静默 → 开照射 → 转静默 → 靶也静默 → 失联,93 拍),
逐秒量,任何一拍落到表外组合就红,而且**必须真的走过** heat / live / ghost / none(全程停在一个态上也能「从不违规」)。
四个变异全部被抓到(没有 coast 态 / 陈旧也画虚线圈 / 椭圆层只认实况 / 热区层不问状态机)。

## SN6e 幽灵/陈旧 = 记号,不是图标 备忘(2026-09-19)

用户拍板:「陈旧就用以前幽灵的表示方法来表示,**不要用图标来表示,以免出现语义混淆**」。

### 原来错在哪

这两档改前只是把**完整的舰船图标**压了透明度、加了虚线,后面整条绘制链照走:
舰体轮廓(带真实朝向)、速度箭头、尾焰、高度标记、当前命令连线、舰名。

于是一个「我已经失去接触」的东西,在画面上仍然是**一艘船** —— 图标说的是
「我知道这是什么、在哪、朝哪开」,而这一档我全都不知道,手里只有一个过期的点。

**更糟的是那几样读的全是真值**,而且实时更新:

| 画的东西 | 读的字段 | 泄漏的是 |
|---|---|---|
| 速度箭头 | `s.vel` | 它**此刻**的真实速度与航向 |
| 尾焰 | `s.flame` / `s.sideFlame` | 它**此刻**在不在点火、点哪个舱 |
| 命令连线 | `s.orders[0].pos` | 它**接下来要去哪** |
| 舰体朝向 | `s.facing` | 它此刻的船头指向 |

接触早就断了,这四样还在跟着真值走。**四条各自独立的迷雾泄漏,而画面看起来完全正常。**

### 改成什么

照设计页(`demos/sensors/态势感知V3.html` 的 `lit===0` 那一支)的记号画法:

- **一个半径 7 的空心小圈** = 「这儿曾经有个东西」,圈本身不承诺形状、朝向、舰种
- 外面一圈**不确定圈**,半径 = 最后已知速度 × 信息年龄 —— 它越大,我越不知道它现在在哪
- 一行标签:`⏳陈旧 60s` / `⏳失联 22s`,写清哪一档、过期多久
- 幽灵暗红、陈旧琥珀,两档仍分得开

画完**直接 `return`**:后面那一整条属于「实况舰船」的绘制链一笔都不走。

⚠ **残骸(`s.dead`)也走这条路**:接触断了就不该知道它已经炸了。「还在那儿」与「已经没了」
正是这一档要表达的那个「我不知道」。

⚠ 原来尾部那句配对的 `ctx.restore()` 一并删掉了 —— 记号那一支现在 save/restore 自成一对,
留着就是一次不配对的 restore,会把状态栈掏穿。

### 订正:两个圈是【两种东西】,画法必须分开

用户实报第二轮:「为什么会存在两个虚线圈,一个会随着缩放变化,一个不会」。**他说得对,是第一版引入的。**

| 圈 | 半径的单位 | 随缩放 | 它说的是 | 画法 |
|---|---|---|---|---|
| 不确定圈 | **世界公里**(最后已知速度 × 信息年龄)× `cam.zoom` | **会变** | 我有多不知道它现在在哪 | **虚线** = 这是个估计 |
| 记号本体 | **固定屏幕像素** `CONTACT_MARK_R=7` | **不变** | 这儿曾经有个东西 | **实线** = 这是个符号,不是估计 |

第一版把**两个都画成虚线**,于是它们读起来是同一种东西的两个尺寸。更要命的是不确定圈有 **8000km 的下限**,
常用缩放下算出来是 7~19px —— **正好和记号一样大**,两个同心虚线圈叠在一起,什么都读不出来,只剩「为什么有两个圈」。

三条修法:①记号改实线;②不确定圈保持虚线;③**不确定圈只在明显大于记号时才画**(`rad > CONTACT_MARK_R*1.8`),
缩到记号量级就省掉 —— 那时候「我不知道它在哪」的范围本来就小于符号本身,画出来是噪声。

判据 `FLOW62_MARK` 三条(拦 `ctx.arc` 与 `ctx.setLineDash`,逐个 arc 记下半径与当时的虚实):
①近处两个圈画法不同;②缩放减半 ⇒ 记号不变、不确定圈减半;③拉远 ⇒ 该点上只剩一个圈。
三个变异**全部被抓到**(记号又画成虚线 / 去掉抑制规则 / 不确定圈不随缩放)。

⚠ 判据自己踩了一次:②的两档缩放第一版取 `0.0012→0.0006`,后者算出来 9.6px **正好被③那条抑制规则吃掉**,
于是「减半」这一格测成了「消失」—— **量的是抑制门槛,不是缩放比例**。两档都必须落在不确定圈还画得出来的那一段。

### 判定

`FLOW47_FOG` 跟着改:它原来数的是 `ctx.translate`(舰体图标的变换),而这两档现在一个 translate 都不发。
现在**两个计数分开留着,「是记号还是图标」本身就成了判据**:

- 记号数 `ctx.arc(x,y,7)`(与不确定圈、半径 13 的告警圈都分得开):陈旧/幽灵在外推点上各 1 个
- **外推点上的舰体变换必须是 0**
- 非 GM 下**舰体图标总数从 4 改判为 2**(蓝方观测者 + 实况接触)—— 改前那多出来的 2 正是
  「把一个失去接触的东西画成一艘船」

变异(记号画完不 `return`、图标照画)被抓到。

### 还留着的一条(记在 todo)

**实况**红方接触的命令连线仍然画着(`s.orders[0]`)—— 位置我确实知道,但它的**命令**永远不该知道。
与本条同类,只是那一档没在用户这次的说法里,没动。

## SN6b 平滑缩放 + 右下角工具栏 备忘(2026-09-19)

### 平滑缩放(cursor-anchored smooth zoom)

用户实报:"现在的地图缩放是一刻一刻的,我想要平滑缩放"。**他说的不是倍率,是时间。**
滚轮一格在 Windows 上 `deltaY=100` ⇒ 倍率 `1.0016^100 ≈ 1.17`,而这一下原来是**一次性写进 `cam.zoom`** 的,
中间没有过渡。标准形态是:滚轮只改**目标**,`cam.zoom` 每帧朝它指数逼近,并把**滚动那一刻光标下的世界点**
钉在光标下不动 —— 这套叫 **cursor-anchored smooth zoom**(Google Maps、Blender 视口、各家 CAD 都是它;
区别只在阻尼是指数还是弹簧)。实现在 `80-camera.js`:`zAnim` / `ZOOM_TAU` / `zoomAt` / `camZoomStep`,
每帧一步挂在 `vtFrame` 里,排在跳层动画 `camAnimStep` 之后。

四条边界,每一条都对应一个真实的失败形态:

1. **在对数空间里插值**才是匀速的(每一瞬放大同样的倍数)。线性插 k 会开头一晃、后面磨蹭 ——
   与 `camAnimStep` 同一条口径,那边先踩过。
2. **锚点每帧重解**,不是只在终点对一次。只在终点算的话,过程中画面会先飘走再回来。
3. **连滚几格叠在【目标】上**,不是叠在当前值上。叠在当前值上的话动画会被下一格截住,越滚越慢、
   停在半路 —— 手感比不平滑还差。
4. **别人一碰相机它就让位。** 每帧记下自己写进去的 `cam.zoom/x/y`,下一帧发现对不上 = 有人从外面动过
   (平移、键位推镜头、开局取景、编辑器、回放、判据),当场把动画丢掉。跳层则是显式抢占(`camJump` 里 `zAnim=null`)。

⚠ **第 4 条是实测撞出来的,不是想出来的。** 刚接上平滑缩放时,一条滚轮判定(`FLOW5_OVER` 的"环带外照常缩放")
留下了一个**没收敛的动画**,此后每一帧 `camZoomStep` 都把 `cam.x/y/zoom` 按那一刻的锚点覆写回去 ——
于是 `FLOW6_FLOW` / `FLOW12_GHOST2` / `FLOW22_APPEND` / `FLOW31_FOLLINE` **四条按像素取样的判据同时量到 0**,
而它们被测的代码一行没动。症状读起来像"连线没画出来",根因是"画面被拽到别处去了"。
**给相机加任何持续若干帧的动画之前,先想一遍:这期间别人写相机怎么办。**

⚠ `camZoomStep(dtIn)` 收一个可覆盖的 dt,平时不传(走墙钟)。判据里必须传:探针在同一毫秒内连着调它,
走墙钟的话 dt 恒为 0,一步都推不动。动画步进函数留一个可覆盖的时钟是常规做法(`camAnimStep` 收的 `p` 同理)。

判据 `FLOW59_SMOOTHZOOM` 五条,五个变异**全部被抓到**(退回直接写 cam.zoom / 锚点只在终点对 /
叠在当前值上 / 去掉让位 / 跳层不抢占)。

### 右下角工具栏 `#tools`

用户拍板:"战术-舰队-战区三按钮放在右下角,大小和形状参考态势感知V3。信号视野按钮也放在右下角,
在三按钮的下面"。所以 `#segTier` 从顶栏**搬到** `#tools` 里(顶栏那一处删掉),**id 未变** ——
`85-settings` 的事件委托与 `80-viewtier` 里写高亮的那行都不用改。

形状照演示页:`.btn.tiny`(padding 2px 5px / 10.5px)+ 连体 `.seg`(`border-radius:0` + `margin-left:-1px`,
只有最外侧两角是圆的)。引擎这边 `.hbtn` 的底子是 32x32 的顶栏钮,所以在 `#tools` 里整组压小。
亮起来那个钮要 `position:relative;z-index:1`,否则中缝会把它的高亮边框切掉一半。

## SN6 信号视野(右下角工具钮)备忘(2026-09-19)

`#tools` 是画布右下角的一排小开关(index.html;样式在 css/app.css;事件走 `85-settings` 的委托 + `on()`)。
**第一个钮:信号视野。** 图层 `drawSignalView` 在 `83-hud`,画在**接触层之前**(它是底图)。

### 一句话

它回答的不是"我看得见谁",而是**"此刻我方这支舰队有多亮"** —— 画我方每艘舰的【被探测范围】。
这是全局唯一一处**把感知模型反过来用**的显示:别处都在画"我方的接触",这里画的是"我方给对方的信号"。

| 圈 | 什么时候有 | 颜色 |
|---|---|---|
| 被看见 | **恒有**。光学/红外是纯被动,与对方是谁无关(谁的眼睛都一样) | 暖(255,154,85) |
| 被听见 | **只在这艘舰在发射时**。silent 是绝对射频静默,响度恒 0 | 冷(84,224,208) |

半径**直接读感知层的量程律**(`visRangeOf` / `hearRangeOf`),不另算一份 —— 圈与判据必须是同一个数。
本项目在 SN4 之前正是栽在"UI 画 150k/250k、判据却是 254k~316k"这类分家上。
被听见按**基准接收机**(`recv=1`)算:它回答的是"一部标准的耳朵能在多远听见我",
不是"某艘特定的敌舰能不能听见我" —— 后者要读敌舰的 `recv`,**那是我方不知道的东西**(同 `kMinNow` 那条纪律)。

### 为什么是渐隐的一团,不是一圈线

探测本来就**没有硬边界**:那个半径是信噪比过门限的【名义】距离,外面一点点并不是突然什么都收不到。
画成一圈实线会让玩家读成"跨过这条线就安全",那是假的。所以画成从中心往外渐隐的填充,
名义半径上不画线、只给**选中舰**留一行标注 —— 标注是地图上唯一说得出"这个渐隐到哪儿为止"的东西
(整支舰队都标的话,一堆数字摞在一起,一个都读不出来)。

⚠ `createRadialGradient` 在渲染红线里是**每帧路径禁用**的。这里不违反:渐变按颜色**缓存**(`SIG_FADE`),
而且建在**单位空间**(0..1)里,每次只是 `translate` + `scale` 变换过去 —— 全局一共建两个,此后一帧都不再建。

### 可读性门 `sigLegible`

两条都不画:①挤成一点(直径 < 24px);②**整张画面都在圈里面**(圆周与画面没有交点)。
后者画出来只是一片平涂的底色,读不出任何东西,还把别的东西压暗。

### 判定与两条教训

`FLOW58_SIGVIEW` 五条(全部按像素取样):①钮关着一个像素都不变;②光学圈内是**暖**的;
③光学圈外、被听见圈内:**静默时全 0、同一点切到照射后是冷的**(单变量对照 —— 只改发射档,别的一律不动);
④读不出就不画;⑤两个半径与量程律**逐位相同**。四个变异**全部被抓到**。

1. **探针的视口是 762x484,不是 1280x720。** 第一版把缩放写成 `4e-4`、取样点写死像素偏移,
   结果被听见那一圈(500px)**把整个画面吞了** ⇒ `sigLegible` 判"读不出"不画 ⇒ 判据自己把自己判红。
   改成从视口**现算**(`0.60*halfD/rHear`)之后才稳。**按像素取样的判据,取样几何必须从视口推出来,不许写死。**
2. **假变异。** 第一版的变异 a 是"把 `if(rfLoudOf(s)>0)` 这道守卫删掉",跑出来判据全绿。
   查下来那**根本不是变异**:静默时 `rfLoudOf` 恒 0 ⇒ `hearRangeOf` 返回 0 ⇒ 半径 0 本来就画不出东西,行为一模一样。
   真正该测的是"**有没有读发射档**",所以换成"把半径当这艘船一直在照射来算" —— 一跑 ③ 当场翻红。
   **变异测试自己也要验:一个改完行为不变的"变异"证明不了判据有牙,它只证明那行代码是冗余的。**
   (那道守卫留着,因为它写下了【意图】:是"这艘船此刻在不在喊"决定这一圈存不存在,不是"半径算出来碰巧是 0"。
   源码里就地写了这条注释,免得下一个人当死代码删掉。)

## RF9 实时状态:速度 / 加速度读数 备忘(2026-08)

右栏 `#selInfo` 加两行:**速度**(`V.len(s.vel)`)与**加速度**。加速度那行的数值是 physics/30-motion 每 tick 记的 `s.accNow`,即 `Math.min(s.thrust*power, need/dt)` —— 取的是**钳位之后**的真实值。显示额定 `s.thrust` 会与画面矛盾:接近期望速度时钳位一生效推力就小了、尾焰在收,读数却还满格。

**引擎种类逐行列**(`engRows`,88-selpanel)。四种,配色与 82-ship-icons 的尾焰同源:`主推`(蓝,`s.engMain`)/`反推`(橙,`s.engRetro`)/`侧推`(黄,`s.engSide`,横向机动 `power=0.6` 所以数值是额定的六成)/`姿态`(暗色)。

**`侧推` 与 `姿态` 必须分开,这是本轮的关键判断。** 两者都点亮同一个 `s.sideFlame`,但来源完全不同:30-motion:55 的横向机动**产生加速度**,而 30-motion:25 与 31-step-ships 三处转向(顺航向对齐 / V 转向 / 战斗转向)**只改 facing、不动速度矢量,加速度是 0**。混在一起会让玩家以为"在转向 = 在加速"。判据是 `s.sideFlame && !s.engSide` —— 侧焰亮着但 steerToVel 没标横推 = 纯姿态。所以 `engSide` 只在横向机动那一支置位,四个转向点一个都不碰。

**四个读数字段在 31-step-ships 的每 tick 复位点清零**(与 `flame`/`sideFlame` 同一行),**不能在 steerToVel 里清** —— 有几条分支(空闲锁定漂移 / 编队旗舰调头)整拍不调 steerToVel,在那里清的话读数会冻在上一拍。

探针 FLOW9_ENG 四态全覆盖,且判的是**数值关系**不只是文案。

**RF20 改定行仪表灯(取代"逐行列")**:原版把在用的推进器逐行列出(`.eng` 是 `display:block`),三角模型下多舱常同时点火、又随 RF12 迟滞脉冲点/熄,行数在 1~3 之间跳、下方整个面板跟着上下蹦(用户实报)。改成**四盏灯常驻(主推/反推/侧推/姿态)、只变亮暗**(`opacity .22 ↔ 1`):行数恒为一,布局几何永远不变,状态变化读成"灯亮了"而不是"版面动了"。用户明确否掉"有几个推进器就留几行" —— 常驻空行同样浪费,灯才是对的。三个实现要点:①暗灯保留本色只压透明度 —— 全灰会读成"没有这个部件",半隐的色才读成"有但没点火";②**不加 transition**:`#selInfo` 整块 innerHTML 周期重建,新节点不动画,写了也是假的;③`.v` 右对齐 + 灯排在数值之后 ⇒ 灯钉死右缘,数值宽度变化只向左伸。语义全部不变(钳位后真实加速度 / 姿态灯亮+数值 0 = 纯转向)。**FLOW9 同步改读 `.eng-l.on` 灯组** —— 灯常驻后"文本包含主推"不再有判别力(四个灯的字永远都在),并加"灯总数恒为 4"判据(灯增灯减就是回到版面跳动的老毛病)。
