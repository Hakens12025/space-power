# js/sensors

感知系统(`js/sensors/`)的历史备忘。总览、跨系统约定与文件地图在仓库根 `CLAUDE.md`。

## TK 航迹表:感知从舰船对象上搬走,每方一张表(2026-09-23 起,进行中)

**这一节是冻结的契约。** 改 TK 系列的任何一步之前先读它;与它冲突的实现以它为准,要改契约先问。
契约全文(英文,含逐行出处)与编排者的决定是这一轮工作流的产物;这里是它们落进仓库的那一份。用户原话:「全部做,不要分裂真值,统一系统」。

### 先给业内叫法

| 我们的东西 | 业内叫法 | 出处 |
|---|---|---|
| 每方一张航迹表 `TRK` | **track file**(航迹文件 / 航迹数据库) | 雷达数据处理;Blackman & Popoli, *Design and Analysis of Modern Tracking Systems*, 1999 |
| 整件事 | **多目标跟踪(multi-target tracking, MTT)** | 同上 |
| 量测直接按真值归到源对象上 | **oracle association**(真值关联 / known association) | 仿真里的标准简化 |
| `lit` 与身份分两栏 | Link-16(MIL-STD-6016)的 **Track Quality** 与 **Identity** 是两个字段 | `lit` 是 TQ 的类比 |
| 身份三档 未知 / 疑似 / 确认 | **分类可信度阶梯**;最接近的标准是美海军反潜的 possible / probable / certain | ⚠ 不是 STANAG 1241 / APP-6 里的敌我属性 |
| 三条认出来路 | ESM / SEI(辐射指纹,可被欺骗)、NCTR(照射回波)、VID(光学轮廓) | 见下面 ID3 一节 |

**完整形态有、我们刻意不做的**:① 数据关联(波门 gating + GNN / JPDA / MHT);② 航迹起始与确认(M-of-N);③ 航迹删除(coast 计数或航迹分数);
④ 身份置信度融合(贝叶斯 / Dempster-Shafer);⑤ 重新捕获的接触换新航迹号。我们有的只是状态估计那一块(SN6 的误差椭圆 = 信息矩阵滤波)。
后果写明:**航迹不分裂、不合并、不会张冠李戴**;一个(阵营, 源)终身一条航迹。

### 表的形状

```
const TRK = { blue: new WeakMap(), red: new WeakMap() }      // js/sensors/24-track.js(TK1 新建);TK4a 在同一个字面量里加 vis:{blue,red}(WeakSet)
航迹 = { src, by, lit, cov, lastT, lastPos, lastVel }          // 键序固定,只有 trkNew 造;TK2.6 追加 idc:false,TK4c 追加 tn:0
```

- `src` 源对象(只设一次);`by` 观测方 `'blue'|'red'` —— **刻意不叫 `side`**,这样航迹永远满足不了 `x.side!==side` 这种敌我过滤;
  `lit` 0..3 原样存;`cov` 就是 `newCov()` 那个对象,**按引用**持有(stepCov 原地改,`cov.ch` 每拍换新);`lastT/lastPos/lastVel` 是最后一次定位的时刻 / 估计位置 / 真速度拷贝(-1e9 / null = 从没定过)。
- 旧字段 → 新位置(TK1~TK3a 过渡期经转发访问器仍可读写,TK3b 改成墓碑、一碰就抛,TK3c 删):

| 舰上旧字段 | 航迹字段 |
|---|---|
| `litBlue` / `litRed` | `TRK.blue` / `TRK.red` `.get(s).lit` |
| `covB` / `covR` | `.cov` |
| `seenBlue` / `seenRed` | `.lastT` |
| `seenBluePos` / `seenRedPos` | `.lastPos` |
| `seenBlueVel` / `seenRedVel` | `.lastVel` |

TK3c 之后舰船对象只剩物理真值;TK4a 之后弹丸也不再带感知(`visBlue/visRed` → `TRK.vis` 两个 WeakSet)。

### 表的规矩(每一条背后都有一个具体的坑)

1. **键是源对象,不是 id。** id 会重复:`shipSeq` 每局归零、判据把 id 改成 `'s901'`(FLOW54)、航线细化沙盘的船叫 `'__rr'`。
2. **不重新赋值、不清空、不遍历。** 没有 `trkReset`。`tools/judge/90-render.js` 的 FLOW63 先 `initFleet` 再把换局前的船放回来(:635 / :677),清表会让放回来的船全变成 none。旧引用(`RDOC.foe`、`lockedTarget`、`projectile.target`、`xh.snap`、判据手里的船)继续拿到冻结的旧答案,与今天一致。
3. **表里不存顺序,枚举只走 `trkEach` / `trkList`**,按物理登记表的顺序(`ships[]`;TK4b 起接 `rocks[]`)。所有平局裁决(`d<bd`、`sc>bs`、稳定排序后取 `[0]`、`botFocus` 的第一个严格最大)与浮点累加顺序(红方信念的重心、热区场)因此不变,下游的随机数取数顺序也不变。
4. **造船那一刻两边都建航迹**(`trkAdopt`,eager);**读永远不建**(`trkOf` / 门面 / `trkEach` 只查)。只有生产者写(detectFor 经 `trkEnsure` / `trkStep`),外加判据夹具。
   TK2.0 起 verify.sh 钉着:`trkEnsure(` 与 `TRK.blue.set` / `TRK.red.set` 在 js/ 里只许出现在 sensors/24 与 sensors/21。
   eager 不许退回按需:`58:161` 的 `lit<2` 与 `56:223` 的 `<3` 是裸比较,没有航迹时 `undefined<2` 为假 ⇒ 火控门【放行】。
5. **`lit` 原样存**(不从 cov 现算、不做类型归一);**cov 按引用**;cov 上不加任何键(FLOW48 的键普查与字面量唯一性检查照旧成立)。
6. **"自己这一方"在查询那一刻判**(`src.side===side`),不在建航迹时判 —— 判据会翻 `.side`(`40-formation.js` :591 / :713 / :729 / :1762)。
7. **存在 ≠ 知道。** `if(trkOf(...))` 当"我们知道它"用,是泄漏形状的 bug;知道 = `trkState(tk)!=='none'`,`trkEach` 已经替你滤掉了。审查时 sensors/24 与门面之外的 `trkOf` 真值判断一律打回。
8. **门面的名字永久不改**:`litOf` / `contactIdn` / `contactAge` / `contactState` / `contactPos`。weapons/52:5、54:77、56:196 的 typeof 守卫在名字缺席时回落到【真值】位置,R2 检查器只证明名字在某处声明过,证明不了它还是那个意思。
9. **不许把 ships[] 的遍历与 trkEach 的遍历混用并假定两者一致。** trkEach 跟着调用那一刻的 `ships` 走(判据会重绑它;航线细化沙盘会临时换成单船克隆 —— 在沙盘里 trkEach 什么都不给,无害,因为那里没人枚举)。
10. **航线细化沙盘的克隆船从 TK1 起没有感知**(for...in 拷不到不可枚举的转发字段)。今天是对的:它的 `lockedTarget` 恒 null。沙盘里永远不跑感知、不设锁定目标。 TK3c 起船上根本没有感知字段,克隆也不在表里(`trkOf` 给 null ⇒ 等级 0),`TK3_NOFWD` ④ 钉着。
11. **(TK3c 已删,留作教训:以后若要再往船上挂访问器,仍只许这种形状)转发访问器(TK1~TK3a;TK3b 的墓碑沿用同一份)只许是一份冻结的 `TRK_FWD`,用 `Object.defineProperties` 挂到每艘船上**,所有船共用同一组 get/set 函数对象。不许写成 makeShip 字面量里的 `get litBlue(){}`,也不许每船一个闭包 —— 契约设计时在 node v24.13 里用真的 makeShip 字面量量过:那样每艘船都掉进字典模式(`%HasFastProperties` 为 false),全引擎的舰船字段都跟着变慢;共享冻结描述符则三型同 map、快属性。TK1 在 Chrome 里用 digest 的 MAPS 行复核。
12. **击沉泄漏保持原样**(决定 10):消费方按真值 `.dead` 过滤(经 `trkGone`),沉船的航迹冻在最后一拍,可能一直是 live。关掉它是另一项要拍板的行为改动。

### 身份三档(TK2.6 落地,那一步行为不变)

- 界面叫 **未知 / 疑似 / 确认**(用户已认可),代码常量 `ID_UNK / ID_SUS / ID_CON`。
  **「疑似」是分类可信度(≈ 美海军反潜的 probable),不是 STANAG 1241 里表示敌我属性的 Suspect** —— 那边的 Suspect 与 Pending / Unknown / Assumed Friend / Friend / Neutral / Hostile 并列,说的是"敌意程度",我们说的是"认不认得出它是什么"。
- 存三件事、每件一个事实、**类型不存**:`cov.idn`(至少疑似,stepCov 闩住,与演示页共用)、`cov.idBy`(最近一次认出的那一拍里第一个认出的通道,FLOW82 / FLOW86 钉着)、`tk.idc`(确认闩:光学或照射认出过、且接触还握着;lit 归 0 时清)。
- 类型是纯函数:未知 ⇒ null;疑似 ⇒ 对方**声称**的(诱饵的 `spoof`,否则 `{kind, cls, tier}`);确认 ⇒ 真的。石头从不发射,所以永远到不了"疑似"。
- `stepCov` 加一个可选第 5 参 `idOut` 与一行 `if (sh[3] && idOut) idOut[ch] = true;` —— 记下【每一站】认出过的通道,补上"一站静听、另一站照射,同一拍里却只算疑似"那个先到先得的盲区。
- 从"≥ 疑似"切到"== 确认"的每一个消费方都是**单独的行为改动**,各要一次拍板、一条判据、一份新的基准摘要。

### 同种子逐位 A/B:`tools/tk_ab.sh`(TK0 做的尺子)

```bash
tools/tk_ab.sh 1a887a8        # TK 系列的金标准
tools/tk_ab.sh HEAD           # 自己比自己:尺子本身稳不稳
tools/tk_ab.sh 1a887a8 40     # 每局 40 分钟 —— 建议每一步都用这个:20 分钟的对局还没交火(见"覆盖的洞")
```

它在临时目录里 `git worktree add --detach` 出基准树,把**当前**的 `tools/tk/` 拷进去(两边用同一把尺子),两棵树各跑三个探针、逐行比对、打印第一处不同,不论成败都删掉 worktree 与临时页。
三个探针都贴在 `head -n -2 index.html` 后面、放在各自树的仓库根(临时页 `__tk.html` / `__tkdraw.html` / `__tklad.html`,不与 verify.sh 的 `__v.html` 撞名;但两者别同时跑,PERF 会失真)。

| 探针 | 量什么 | 输出 |
|---|---|---|
| `tools/tk/digest.js` | 对局与靶场各 5 个种子、每局 20 分钟(可改)的整局摘要:每 60 模拟秒一行 FNV-1a(舰船真值 + 两方感知 + 弹丸 + 红方信念与条令 + 接触降速 + 胜负)与累计随机取数次数 | `env seed t hash draws` / `SELF_DOUBLE` / `SELF_SEED` / `PERF` / `MAPS` |

尺子自己的纪律(每条都是一次"尺子不准"):
- **摘要不调 `render` / `xhTick` / `matchTick` / `updateTop`**:render 从模拟的随机流里取数(83-hud 的命中碎屑)、还读墙钟;夹在两次摘要之间调一次 render,就把后面模拟看到的随机流挪了一位。画面改用画布调用日志,不用截图(同一份代码连截两张都不一样)。
- **`initFleet` 不清的全局由摘要补清**:`detT`、`netAllocT`、`acc`、`missileGroupSeq`、`netSeq`、`fmSeq`(它在 initFleet 里就要取号,所以在 initFleet 之前清)、`TC.band/hold/eff`、`rate=20`、航线细化队列。自检 `SELF_DOUBLE`(对局 seed 1 隔着另外九局再跑一遍)专抓漏清。
- **每次 Chrome 用全新的 `--user-data-dir`**:靶场参数存在 localStorage 里,verify.sh 的判据会改写它(决定 12)。
- **冻结帧循环**:tk_ab 在 `<body>` 后插一行把 `requestAnimationFrame` 换成空操作。实测不冻时,解析器在 core/99 与探针之间让出,真 `frame()` 偶尔先跑一帧(星空贴图、LOD 过渡起点都记在那一帧上),HEAD 对 HEAD 的画布日志调用数 1223 / 3633。

## SN4 感知重做:三通道八字段 → 两通道四字段 备忘(2026-09)

### 一句话

**一艘舰只有两种看见别人的方式:看(光学/红外,纯被动)和雷达(一部设备两种模式:静听 / 照射)。**
描述它的字段从八个减到四个:`size`/`stealth` 属于【被看方】,`emit`/`recv` 属于【探测方】。

### 为什么重做(两条,都不是"代码不好看")

1. **旧模型有两套真值,而且分家是完全静默的。** `projVisibleTo`(弹丸可见性)手抄了一份自制的可见半径公式,
   与 `detectFor` 的通量判据从来不是一个数;舰队卡的辐射条又抄了一份能量式;UI 画 150k/250k 的圈,
   而回波门限 `1e-22` 算出来的真实照射距离是 254k~316k —— **圈与判据从来就不是同一个数**。
   感知系统里这类错误不报错、不变红,数错了界面照样全绿。
2. **八个字段里有派生关系与重复语义。** 探测下限是探测力的派生量(只填一半这层关系会静默断掉);
   而船体信号基数与雷达截面两个数各自裹着"体型"这件事,调一个不调另一个就能造出"雷达上很大、红外上很小"
   这种没有物理含义的舰。

### 三条量程律(实现只有 `sensors/22-percep` 一份,常数只有 `SENS` 一张)

| 通道 | 衰减 | 公式 | 谁说了算 |
|---|---|---|---|
| 光学/红外(纯被动) | `1/d²` | `r² = K_IR × lum`,`lum = size × (1 + 引擎档 + 发射档)` | **与探测方无关** —— 谁的眼睛都一样 |
| 雷达·静听(被动) | `1/d²` | `r² = K_RF × emit_t × 发射档_t × recv_d` | 目标喊得多响 × 我耳朵多好 |
| 雷达·照射(主动) | `1/d⁴` | `r⁴ = K_ACT × emit_d × recv_d × (size_t × stealth_t)` | 我的雷达 × 目标反光 |

于是三条指数律:**照射量程 ∝ emit^(1/4)、被听见的距离 ∝ emit^(1/2)、静听量程 ∝ recv^(1/2)**。
两个探测方字段是**互相对立**的:把 `emit` 翻倍,自己的照射量程只涨 19%,被别人听见的距离却涨 41%。
**手电效应**(基准舰自照 15 万 / 被听 60 万 = 4 倍)是整套设计的灵魂,它就出在这两条指数不同上。

### 三态发射档取代两个布尔

`emitMode ∈ {silent, paint, jam}`,**唯一写入口**是 `21-detect` 的 `setEmit`(非法值当场抛);
UI 文案唯一出处是 `emitLabel`,三态循环是 `emitNext`。裸赋值一律视为 bug。

理由是物理的:一艘舰只有**一部**发射机 —— 照射与干扰是它的两种工作模式,发射机去造噪声的时候就没法照射。
旧的两个各自独立、可以同时开的布尔在这一点上是错的。三态的取舍到此闭合:
**看得清 / 不被听见 / 不被锁定,三者只能取其二。**

- `silent` 是**绝对静默**(射频响度恒 0)。旧模型那个约 5 万公里的船体泄漏圈已删 ——
  热循环里"射频响度非零"那道早退要真的省下东西,这一档就必须真的是 0。
- `jam` 每拍削弱对方的 `trk.act`(照射回波),**只削回波**:噪声淹不了红外(旧实现连红外一起削,是错的),
  也不可能让"正在大声喊的人"变得更难听见 —— `jam` 的射频响度是 `paint` 的两倍,被听见的距离是 1.414 倍。
- `jam` 档**自己也拿不到火控级**(`senseKACT` 只对 `paint` 给系数)。
- 削减落点只有 `senseApplyDwell` 一处,**别在 21-detect 再乘一次**(乘两次等于把干扰强度平方)。

### 接触阶梯:取值与字段名一个字没动,派生方式换了

`litBlue`/`litRed` 的 **0/1/2/3** 是二十个文件、几十处读取的契约面,武器门控与迷雾渲染全绑在上面:

```
1 探测级  光学【或】静听单独过 LIT1(照射刚建立、还没到 LIT2_ACT 时也算)
2 识别级  光学【与】静听交叉过 LIT2   或   照射驻留过 LIT2_ACT
3 火控级  照射驻留过 LIT3;照射一断,驻留掉到 ACT_DOWN 之下就降回 2
```

**纯被动也能到识别级**(交叉判据)沿用旧内核。滞回改成对两条被动通道**对称**判 ——
旧实现只判红外那一路,那是旧模型"射频通道单独恒点不亮"留下的不对称;新模型两条被动通道地位完全相同,
只判一路会让"靠静听点亮、随后滑进光学盲区"的接触瞬间熄灭再点亮,画面上就是幽灵闪烁。
等级只**即时上升**,下降只有两条路(算到彻底归 0,或断照把 3 打回 2),不许逐级滑落。

`trkB`/`trkR` 的三个键换成 **`opt` / `lis` / `act`**。
⚠ `lis` 与 `act` 是**同一部设备的两种模式**,不是两条通道,别读成"又变回三通道了"。
`seenPos`/`seenVel` 只由**光学或照射**刷新,**静听不刷新** —— 被动射频给的是一条视线不是一个点,
拿它写 `seenPos` 等于凭空把距离变出来,而陈旧/幽灵接触正是照着 `seenPos` 画的:迷雾当场失效,画面却完全正常。

### 每一个常数都能回答"凭什么是这个数"

锚点推导逐条写在 `20-signature` 的文件头。几条关键的:

- **`size` 的 0.70/1.00** —— 舰体结构 hp 的 2/3 次方(截面积 ∝ 体积^(2/3)):`550^(2/3)/900^(2/3)=0.719`。
  旧模型手调出来的比值恰好是 0.70,**两条独立推导对上了**,所以沿用。
- **`ACT_REF=150000`** —— 基准舰的照射量程,同时就是 83-hud 一直在画的那个 DD 圈。
  CA 的 `emit=recv=3` 让 `(3×3)^(1/4)=1.732` 把它抬到 26 万,贴住那个 25 万圈。**圈与判据这次钉死成同一个数。**
- **`IR_REF=180000`** —— 让静默熄火的 DD 恰好在 150,598km 被看到,与 DD 主炮射程 15 万同量级。
  含义是"一艘完全静默的船,要等到进了主炮射程才刚被光学发现",**这正是隐蔽接近有意义的前提**。
- **引擎功耗压到"满推让量程 ×2"**。旧模型的引擎辐射常数压在船体上是 36 倍,满推 DD 亮到 82.8 万(比地图还大),
  等于"一点火就全场可见",`size` 根本说不上话。

**`size` 一个数同时喂光学与雷达**,所以"大船两头都显眼"是这个模型的结论而不是巧合;
**`stealth` 只乘雷达反射、不乘红外**(外形骗得了雷达,骗不了热辐射)。
合成反射 DD = `0.70×0.60=0.42`(旧雷达截面是 0.60),DD 相对更隐蔽 —— 这是"一个 size 两头都算"的刻意结果。

### 主炮有效射程从感知层摘下来

`macEffRange(s)` 改成 **`paint → macRadar` / 否则 `macRange`,二选一不取 max**,两块都在 `weapons/51-defs` 的武器表里。
**为什么不能继续取 max**:新内核的照射量程是"按目标反射率现算"的动态量(同一门炮打 DD 和打 CA 得出的数不一样),
拿它当火控射程等于把武器与感知又焊回一起 —— 射程会随着"在看谁"而变,
而 `fcGate` / 目标轮盘 / hover 圈三处读数都没有"看谁"这个参数。
数值上对现有舰种**零变化**:DD 两块都是 15 万,CA 是 15 万→25 万,与改前 `max(炮, 感知半径)` 逐位相同。
表级不变量:**同一件主炮的 `macRadar` 必须 ≥ `macRange`** —— 开照射反而射程变短说不通,而且不会报错,
只会静默给出一个更小的数,`fcGate`/轮盘/hover 圈/规格条跟着一起错。
无主炮的舰(CV)由 `resolveLoadout` 显式烘成 0:"没有炮"就该读成"射程 0",比给一个 15 万的假射程诚实。

### 性能:重写顺带快了 2~2.6 倍

`tools/train/perf_sense.js`(node,纳秒级;**只报数、不判红绿**)。100 舰 / 5000 对,同机同命令:

| | p50 | p99 | min | ns/对 |
|---|---|---|---|---|
| 旧(三通道,已删) | 966.3 µs | 1518.1 µs | 634 µs | 193 |
| 新(两通道,SN4) | 421.4 µs | 573.8 µs | 402 µs | 84 |

**新旧对比看 min**(同一段代码跑间方差约 ±13%)。min 快 1.6 倍量的是纯算术;
p50/p99 的额外收益来自**热循环里不再分配** —— 没有垃圾就没有 GC 抖动,
四轮重测 p50 只在 417~426 之间晃(旧实现三轮是 966/827/764)。

怎么做到的(四条,改这块之前先读):

1. **所有除法与开方搬进 `sensePrepare` 的 O(N) 段**,热循环里一次都没有;
   照射那一路**比四次方**(`d²·d² < r`)以避免开方。
2. **剪枝上界在 `d²` 空间取 max,而照射的界必须先开方换算过去。** 只按被动两路取 max 是**错的**:
   一艘静默熄火的冷目标光学暗、射频恒 0,整目标会被早退跳过,照射驻留永不积累 ——
   **主炮对所有不发光的目标静默哑火**,而 `litBlue` 全程是合法的 0/1/2,没有 NaN、没有异常、没有一行日志。
   `FLOW52_COLD` 守着这一条,别把那个开方"优化"掉。
3. **热循环体与单点查询谓词是同一个函数**(`sensePairGrades`)。
   判定因此可以直接断言"单点查询与热循环对同一对给出相同的三档"(`FLOW51_PAIR`:三者 packed 全等 72/72 组)。
   ⚠ 单点谓词会覆盖共享缓冲,**绝不许**在扫描循环中途调用。
4. **衰减按累计 dt 解析跳步**(`x ← x·D^dt + g·(1−D^dt)/(1−D)`),不做 N 次一秒步进。
   所以 `core/05` 的节拍必须把**真实经过的模拟秒数**透传给 `detectLoop`:传 `CFG.step=0.02`
   会把一整秒的衰减当 0.02 秒算、驻留一路涨穿;传常数 1 又会在倍速/长帧下把真实时间抹平。

信噪比分档(强 = 16 倍门限通量、良 = 4 倍)取代连续 SNR:于是 `1/d²` 通道的强/良落在量程的 25%/50% 处,
`1/d⁴` 通道落在 50%/70.7% 处 —— **同一个信噪比含义、不同的衰减律,数字不同是对的**。

`Float64Array` 缓冲是**纯 scratch**:`sensePrepare` 每次调用整体重填,没有一格内容能活过一次调用。
所以 `96-spawn` 运行期插船、`32-route-refine` 临时换 `ships` 都**不需要任何失效钩子**。
扩容按 2 倍走(刚好够会让每加一艘船都重建十几个数组),缩容不做。

## SN6 误差椭圆落地:驻留阶梯换掉,契约面一个字没动(2026-09-19)

### 一句话

**接触不再是三个水池,是一个位置估计 + 一个各向异性误差椭圆;等级 = 椭圆落在哪道门里。**
`litBlue`/`litRed` 的 0/1/2/3 语义与字段名一个字没动,所以 74 处读点一处都没改 —— 变的只是派生它的那一层。

模型的设计、推导与试验场在 `demos/sensors/态势感知V3.html`(自检 48 条 / 交互自检 62 条),
引擎这一侧是移植:纯函数层新建 `js/sensors/23-cov.js`,`21-detect` 的驻留段换成它的 `stepCov` / `covLit`。

### 为什么换(三条,都是 SN4 自己的备忘里记过的病)

1. **等级是来路的函数。** SN4 的派生规则"只即时上升,下降只有归 0 与断照 3→2 两条路"让 2 级成了棘轮:
   同一个点、同样的发射档,从没被照过读 1 级,被照过 30 拍再转静默则**永久停在 2 级**("照一下就永久拿到导弹门")。
   SN6 里等级是椭圆的纯函数,同一个画面状态只有一种读数,棘轮自动消失(`FLOW44_SENSE` 第 ⑥ 段钉着这一条)。
2. **"发现得到"与"算得准"是同一个旋钮。** 单半径模型里精度律 `σ_θ = TH0·(d/R)^k` 的 R 一放大,
   每一个距离上的精度都跟着放大 —— 想要战场级的发现距离,就必然把火控解算送到武器射程的几十倍之外。
   SN6 拆成两套:`*_DET`(发现半径)与 `*_REF`(定位精度尺度)。⚠ 引擎原来的 `IR_REF/LIS_REF/ACT_REF`
   语义上一直是**发现半径**,所以 SN6 把它们**改名**为 `*_DET`(值一个没动),腾出 `*_REF` 给定位尺度。
3. **"被动只给方位"原来要靠一张旁路的表**(`esmFixes` + `updateESMFixes` 的三角公式 + 渲染层一个专门的函数)。
   SN6 里它是模型的一部分:静听量测纵向直接给 `COV.HUGE`,解出来自然就是"细长到没有位置"的接触,
   多站交会也不需要专门的公式 —— 信息矩阵逐项相加就是交会。那一整套旁路连同它的阈值一起退役。

### 数值的唯一入口是【距离梯子】,六个常数由它反解

玩家看得见的每一级距离(发现 / 交会可用 / 认出 / 火控)是字面量,模型常数由 `ladApply()` 反解写入。
在 `SENS`/`COV` 里手填那六个数会被覆盖。落地的这一组(演示页 2026-09-19 定案,尺度预算 22 成立 / 0 超支 / 2 待定):

| | 参考对 DD 看 DD |
|---|---|
| 光学发现(冷 / 满推) | 24 万 / 48 万 |
| 雷达发现 | 65 万 |
| 开雷达被听见 | 125 万 |
| 照射→定位 / →跟踪级 / →火控 | 51 万 / 35 万 / 14.3 万 |
| 光学单站 定位 / 导弹门 / 主炮门 | 8 万 / 5.6 万 / 2.3 万 |

**往返是最重要的一条判据**:反解写进模型的常数,再用正向公式(`ladPair`)量回来,必须等于梯子上写的那个数。
落地时拿它与演示页逐位对表:15 个模型常数 + 60 个梯子读数(4 个舰种对 × 15 级)**全部逐位相同**,8 条不变量一致。

### 跟着换的四处数值/场景(每一处都有连带面)

- **CA 的 `emit/recv` 3.0 → 2.0。** 3.0 是为了把照射量程抬到 26 万贴住 UI 那个 25 万圈,代价是被听见的距离是 DD 的 3 倍 ——
  一个舰种就把整条梯子的上端拖大 3 倍(尺度预算 B7 舰种差超支)。压到 2.0 之后差距留在一层之内。
- **靶场三个靶从 `x=150000 / y=±120000` 挪到 `x=55000 / y=±80000`。** 判据吃的是到蓝方 CA 的**斜距**:
  原来 219k / 202k / 250k,而 SN6 里 CA 照一艘 DD 拿到火控级只有 **172,829** —— 三个靶一个都够不着,
  而 `fireMAC` 首行就是 `q<3` 就 return:**开局直落靶场,主炮一发都打不出来**。新斜距 116k / 109k / 152k,
  最远那个余量 12%,而且 152k 恰好坐在主炮射程 150k 上。⚠ 这不是把数调到能过判据:椭圆模型里火控距离
  几乎不随 `emit×recv` 变(2/2 到 4/4 只在 17~21 万之间),怎么调雷达都够不着 20 万,**能动的只有靶的站位**。
  它同时取代了 SN5 那条"CA 的 `emit×recv >= 7.87`"靶场约束(那是驻留模型下同一件事的说法)。
- **光学亮度里的雷达废热乘 0.15。** `optLum` 原来把发射档**原样**加进亮度 = "开雷达和点主推一样亮",
  于是照射一开光学量程就 ×1.41,静默与照射在光学这条通道上几乎没区别。量级上雷达几百千瓦、引擎吉瓦级。
- **干扰从"每拍削一个水位"改成"把这一拍的回波误差按烧穿距离放大"。** 烧穿距离由既有的 `ecmPower` 推
  (`JAM_REF / sqrt(ecmPower)`,DD 73,030 / CA 56,569),**不新立一张每舰种的表** —— 两张表必然漂移。
  演示页手填的是 73,000 / 56,500,这条式子与它差 0.05%。

### SN5 的"被动先于主动"被**取代**了,不是被违反了

SN5 那条不变量(任一照方对任一**主推中**目标的照射圈须小于该目标的光学圈)是 SN4 标定下的关系:
当时雷达 15~26 万、光学满推 36 万。SN6 的梯子**刻意**把雷达放到 65 万、光学满推 48 万 ——

### 热区是一片【场】,不是"画淡一点的椭圆"(订正,2026-09-19)

第一版我画成几圈同心椭圆,被用户当场指出不对("我要的是一坨的那种")。照演示页的 `heatBuild` 重新移植之后,
这一层有四条硬规矩,每一条都对应一个被实测否掉的做法:

1. **各向同性**。一个半径,不读短轴、不读倾角。半径取**等面积圆** `sqrt(r1·r2)`:椭圆的面积一分不差地留下,朝向丢掉。
   条状是**武器层**的语言(它说"方位准、距离不准",那是给火控看的);观测层只回答"这儿有反常热信号",
   借了另一层的形状,玩家就会从带子的走向去读视线方向,而这一层根本没打算给出那个。
   ⚠ 也不能只取长轴:被动单站的长轴在光学够不着之后**恒等于哨兵值**,常数里榨不出梯度,"越近面越小"整段不发生。
2. **半径对数压缩** `R = AMAX·0.75·ln(1+geo/AMAX)`。硬截断 `min(r1, k·AMAX)` 会让远处面积恒定 —— 又是一段没有梯度的平台。
3. **团心按不确定度偏开**,方向随时间缓慢转。这是这一层存在的理由之一:模型里估计位置**等于**真值,
   圆心画上去就是把坐标直接交出去。偏开之后读法变成"显示的是后验里的**一个采样**,不是它的均值",
   而采样偏多少正好就是你不知道多少;偏移幅度正比于半径,所以**越准中心越往真值缩**。
4. **域扭曲 + 缓慢翻涌 + 峰值饱和** ⇒ 团块不规则、读不成几何形状,最亮处是高原不是点。

实现上是一张**低分辨率离屏画布**(格子 7px)+ 贴回来时的双线性插值当免费模糊,所以不违反 render/84 那条红线
(shadowBlur 与 createRadialGradient 一个都没用);按签名缓存,ImageData 与浮点缓冲跨帧复用;
没有未定位接触时整段早退(最常见的情况)。

⚠ **两条残余,记下而不是假装没有**:
(a) 这是**读不出**,不是**没有** —— 场仍按真实后验铺,长时间盯着仍能看出大概。彻底的解法是把估计误差放进模型
    (让 `c.x/c.y` 按协方差抖一个偏差),那会连带改掉"武器打的是估计位置"的手感,属于另一轮,记在 `todo-plan.md`。
(b) 半径是压过的,所以图上这片比真相**乐观**。

判据 `FLOW54_HEAT` 钉四条,全部做过变异测试(对数压缩退回硬截断 / 等面积圆退回只取长轴 / 团心偏移归零 / 圆拉成条,
四个变异**全部被抓到**)。其中第三条第一版写成"绝对偏移 > 一个格子"是**没有牙的** —— 把偏移幅度直接归零,
判据照样全绿,因为域扭曲本身也会把重心拱开几个像素。改成判**偏移 / 团半径**才分得开这两件事。
顺带踩到:算重心时格子中心在 `(gx+0.5)·CELL`,漏掉这半格会凭空造出约 0.1 个团半径的"偏移",归零对照当场假红。

## ID1 身份只有一个出处:`contactIdn`(2026-09-21 全库审查 R1)

标准模型里**航迹质量(等级)与识别(身份)是两个独立属性**,内核也是这么做的:`cov.idn` 由「哪条通道在识别距离之内」锁存,接触丢了才清(`23-cov` 的 `identDist`)。

**后果是梯子上「认出」那一级在引擎里是死的。** CA 照一艘 DD:跟踪级(lit2)的门 43.5 万,雷达认出 15.1 万、光学认出 9.4 万。

现在 `contactIdn(s,side)` 与 `contactPos` / `contactState` 是一家三口;`shipIdentHull` / `shipIdentTier` / 舰标名字 / `xhName`(日志、轮盘、缩圈小窗的外传名)/ 信息卡 / 舰队卡分级徽标全部问它。
顺手:信息卡的方位 / 距离改按 `contactPos` 报(原来是真值);新增 `litOf(s,side)` 收掉四处 `side==='blue'?x.litBlue:x.litRed`。

- ⚠ `lit===0` 那一档轮廓**不**打码(改前的 `q===0` 分支原样):编辑器与 GM 下画的是没有接触的红舰,要看真轮廓;非 GM 下 lit=0 的船根本不画舰体。
- ⚠ `sigClassLabel`(没认出时写「大 / 中 / 小型热源」)读的是真 `size`。演示页明确否过这条(光学上可观测的是亮度不是体型),引擎里还留着 —— 没动,记在这儿。
- `FLOW77_IDN`:等级不授予身份(2 级 / 3 级而没认出 ⇒ 五样全打码)、认出后全部翻真(反向对照)、端到端(跟踪门内、认出距离外的 DD 仍是 UNK,两个距离从梯子现量)。

## SN6d 接触位置唯一化:`contactPos` 一个出处(2026-09-19)

### 起因:一次实测出来的泄漏

审计时量的,不是读出来的:

```
靶·B litBlue=1 fix=false(= 只有热区,画面上没有舰标)
A 光标放真值上 targetAt=靶·B          ← 吸住了
  吸附半径=55px = 世界 165k km
B 单变量对照 同一艘船 litBlue 1→0:targetAt=null(门在,只是门槛按 lit 不按定位)
```

**开局画面是三坨热区、一个敌舰舰标都没有,但把光标扫过空处就能把敌舰真实位置扫出来。**
渲染层 SN6 堵的正是这个洞(`drawShip` 那道 `covB.fix` 门),**输入层没跟上** ——
这与本目录 SN5 备忘第五节记下的那个缺口是同一句话:**判据要问的是「我有没有它的坐标」,不是「等级到几了」。**

### 更深的一层:全库四处各自算位置,两个不同答案

| 在哪 | 用的位置 |
|---|---|
| `82-ship-icons` `drawShip` | 实况 **`s.pos` 真值**;幽灵/陈旧自己外推一遍 |
| `82-lod` `lodBuild` | **`covB.x/y` 估计** |
| `83-hud` 热区 + 椭圆 | `c.x/c.y` 估计 |
| `70-input` `targetAt` | **`s.pos` 真值** |

今天两个答案数值相同(`covSolve` 只算不确定度、**不模拟估计误差**),所以看不出来 —— 但**门槛早就分家了**。
等估计误差进了模型,这就是"画一处、点另一处",`82-lod` 注释里自己写的"最难查的那种错"。

### 改法:契约层加一个函数,三处都读它

`contactPos(s, side)`(住在 `21-detect`,与 `contactAge`/`contactState` 同一节):

```
自己的船        真值
实况接触        c.fix 为真才有位置,给【估计】c.x/c.y;定不出位置 ⇒ null(归热区层)
幽灵 / 陈旧     最后已知 + 速度外推;缺接触记录 ⇒ null(SN2c 那条 fail-closed,不许拿真值兜底)
```

三条迷雾门(蒸发 / 缺记录 / 定不出位置)全折进这一个 `null` 里。调用点:
`drawShip`(画在哪)· `targetAt`(点在哪,**门与命中点都换**)· `lodBuild`(聚在哪)·
`74-targeting` 吸附复查(原来复查的是 `litBlue`,于是一个吸住之后失去定位的接触会一直挂在准星上)。

⚠ **刻意不读 `adminMode`** —— GM 是 UI 概念不是感知事实,要旁路的调用方自己旁路(两处本来就各有一条 GM 分支)。
⚠ **残留:Z 轴取 `s.pos[2]`(真值)**。椭圆模型是二维的,高度不在模型里 —— 原样保留的既有行为,记在 `todo-plan.md`。
⚠ `lodBuild` 那道 `covB.fix` 过滤**刻意保留**:这一层只聚"已定位"的接触,幽灵/陈旧虽然 `contactPos` 给得出外推位置,
  但它们不该被收进接触群(那是另一档信息,画法也不同)。

### 判定

- **`FLOW4_FOG` 从两档改成三档**,中间那一档正是这个泄漏:`lit=1 & fix=false`(只有热区)**必须吸不上**。
  原来它的对照组是"只翻 `litBlue` 0→2" —— 门的变量换了,对照组就必须跟着换,否则测的是一件已经不存在的事。
  ⚠ 构造"实况"接触还得给 `seenBlue` 一个新鲜时间戳:`contactState` 的 live 要求 `age<=5`,而 `makeShip` 的初值是 `-1e9`。
- **新增 `FLOW61_PICKPOS` 四条**:①实况读【估计】而不是真值(把 `c.x/c.y` 刻意偏开真值)、画点=点选点、**真值处点不到**;
  ②只有热区 ⇒ 画不出也点不着;③幽灵走外推点,画点=点选点;④缺接触记录 fail-closed。
  四个变异**全部被抓到**(输入层退回旧门 / 渲染层实况退回真值 / `contactPos` 不看 `fix` / 缺记录拿真值兜底)。
  ⚠ ① 的偏移量必须**从吸附半径现算**(`60/cam.zoom`):第一版写死偏 50k/30k = 斜距 58,310 < 吸附半径 75,000,
    真值仍落在估计位置的吸附圈里 —— 量的是圈的大小,不是读没读真值,当场假红。

### 两处没有牙的地方(记下而不是假装有)

1. `lodBuild` 改读 `contactPos` 是**纯解耦**,今天行为逐位不变(它本来读的就是 `covB.x/y`),
   所以**没有任何变异能抓到它**。它的价值是"以后只有一个出处",不是修了什么。
2. `82-ship-icons` 里那道旧的 `!(s.covB&&s.covB.fix)` 门**已经恒不成立**(同样的判断折进了 `contactPos`)。
   源码里就地标了 ⚠,**等确认后删** —— 两道同义的门正是这次要消灭的东西。

## SN5 雷达关系不变量:一个数都没改,补的是看着它的东西(2026-09)

这一轮的产出是【一条不变量 + 一条探针 + 两处订正】。**`SENS` 与 `WPN` 里一个数都没动。**
值得记的是它原本要改数,而改数被自己的验证否掉了 —— 否掉的过程比结论有用。

### 一、原本要改什么,为什么撤回

起因是手算发现一格越界:**CA 的照射圈 259,808 越过了一艘【侧推中】的 CA 的光学圈 254,558**。
于是提了「CA 的 `emit/recv` 从 3.0/3.0 降到 2.5/1.6」。三条 blocker 把它按死:

1. **靶场开局主炮会彻底哑火。** 三靶到 CA 的**斜距**是 `202,237 / 219,317 / 250,000`(不是 x 向差值的 20 万),
   而 CA 照 DD 靶(合成反射 0.42)的量程今天是 `209,153` —— 只够得着靶·B。降到 `170,773` 之后**一个都够不着**,
   而 `fireMAC` 首行就是 `if(q<3)return`。要够到最近那个靶,`emit x recv` 必须 `>= 7.87`(今天是 9)。
   **任何有意义的削减都撞这条。**
2. **动机本身站不住。** 对一艘**熄火静默**的冷目标,主动大幅先于被动是**设计意图** ——
   `IR_REF` 的锚点注释白纸黑字写着"一艘完全静默的船,要等到进了主炮射程才刚被光学发现",
   而 `FLOW52_COLD` 存在的全部意义就是守这条的反面。真正越界的只有**侧推**那一格,**超 2.1%**。
   为一个 2.1% 的边界把雷达量程砍掉 18%(收发乘积砍 56%),杠杆用错了尺寸。
3. **连带面比动机大得多。** `macRadar` 要跟着从 250,000 掉到 205,000,而 `DEFAULT_ENEMY` 的两艘叛军巡洋
   走同一个 `macEffRange` —— 敌方 AI 的交战距离一起缩 18%。这在原动机里一个字都没提。

**教训:一个 2.1% 的边界违规,正确的反应是把边界重新定义对,不是去改被测的量。**

### 二、订正后的不变量:界划在【主推】档,不划在侧推

> **一艘开着主推的船,永远先被看见、后被照到。**
> **熄火静默的船反过来** —— 那是雷达唯一无可替代的活(找暗船),`FLOW52_COLD` 守的就是它。
> 中间的**侧推**档是过渡区,不强求 —— 侧推是最弱的一档动力,几乎就是冷目标。

按这条口径,今天的数**全部满足,而且余量很大**:

| | 主推档光学 | 最强照射 | 余量 |
|---|---|---|---|
| 打 CA | 360,000 | 259,808 | +27.8% |
| 打 DD | 301,197 | 209,153 | +30.6% |
| 信标打 CA(最薄那格) | 360,000 | 300,000 | +16.7% |

⚠ 算信标对 DD 的量程时**别忘了乘目标的合成反射 0.42**:那是 `241,510`,不是 `300,000`。
`300,000` 是对【标准目标 反射 1.0】那一档 —— 我第一版注释就写错成 0.4% 余量,是探针的读数把它抓出来的。

### 三、`FLOW53_RADAR`:五条 + 一条反向对照

之前这几条关系**一条探针都没有**。CA→CA 越界 2.1% 是手算发现的,六十条判定一条没红 ——
「两张表相乘出来的关系」是本项目最容易静默漂移的一类,因为每一处单独看都对。

- **①** 被动先于主动(界=主推档),**全组合枚举含信标为照方**,20 组。实测最薄余量 16.7%。
- **①b 反向对照**:把界换成**侧推**档就必须**有**格子越界 —— 实测 9 格(CA/BB/CV 互相)。
  没有这一条,①「全过」可能只是因为界定得太松,判据就没有区分度。
- **②** 基准舰锚点:`actRangeOf(DD, 1.0)` 必须**恰等于** `ACT_REF`、`hearRangeOf(DD paint, 1)` 必须恰等于 `LIS_REF`。
  这两条今天只活在 `20-signature` 的注释里,而整张表的推导链都挂在它们身上。
- **③** 武器表:每件主炮的 `macRadar` 必须落在 `[macRange, 该舰对标准目标的照射圈]` 之内。
  超出就是规格条虚标(玩家永远拿不到火控级),而 `fcGate` / 目标轮盘 / hover 圈三处都照着它画。
  实测 `DD 150000/150000`(**恰好相等,边界**)、`CA/BB 250000/259808`。
- **④** `emit`/`recv` 随体型单调不减;**手电系数 `4*(emit/recv)^(1/4)` 不许低于 4**(等价 `emit >= recv`)。
  后者是「开雷达永远是我看得更清、但对方更早发现我」这条灵魂的**充要条件**:
  `recv` 一旦超过 `emit`,那个舰种就会反转成「雷达看得比被听见还远」,而前三条没有一条会红。
  实测四舰种全是 `4.000`(恰好取等号)。
- **⑤ 靶场几何**:开局直落那个场景,蓝方 CA 开照射后至少要有一个靶够得到火控级。
  **这一条最有牙齿** —— 它把 `SENS` 与 `90-envs` 的坐标**乘**在一起,任何一边动了都会红。
  坐标从 `TEST_ENVS[0]` **现读**,不抄死数:靶挪了探针自动跟。实测 `靶A 219k lit0 / 靶B 202k lit3 / 靶C 250k lit0`。

### 四、两处注释订正(都是真的变成了假话)

- `90-envs.js` 的「x 相距 20 万,CA 传感器 25 万开 LADAR 能把三靶都点到火控级」——
  **三件事全错**:那个字段 SN4 就删了;判据吃的是**斜距**不是 x 向差值;开局只有**一个**靶够得着。
- `51-defs.js` 的 `macRadar: 250000` 注释补了一句:它只对【标准目标】可达,打 DD(反射 0.42)时
  照射量程只有 209,153。这是 `stealth` 在起作用的正确结果,不是 bug,但读注释的人推不出来。

### 五、顺带发现的一个缺口(未修,记下)

**靠静听单独点亮到探测级的接触,地图上什么都不画。**
`updateESMFixes` 的门是 `litBlue<1`,等级一到 1 椭圆就被删;而图标那边 `seenBluePos` 仍是 null
(它只由光学或照射刷新),被 SN2c 的 fail-closed 守卫挡掉。于是玩家只看到等级从 0 跳到 1、
地图上一个像素都没变。方向是对的(不许凭空画出位置),但那一格是空的 ——
要么让椭圆continue 画到 `lit>=1`,要么给它一个别的表现。

这个缺口是写演示页 `态势感知.html` 时被它自己的自检抓出来的:那一页原来也按【等级】决定画不画不确定区,
于是等级一到 1 就落到「按最后已知位置画图标」那一支,而那个位置是 null、回落成**真实坐标** ——
纯靠听就拿到了敌舰精确位置。演示页已改成按**有没有位置定位**判(与引擎里 `seenPos` 只由光学或照射刷新同源)。
**判据要问的是「我有没有它的坐标」,不是「等级到几了」。**
