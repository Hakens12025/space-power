# js/formation

编队系统(`js/formation/`)的历史备忘。总览、跨系统约定与文件地图在仓库根 `CLAUDE.md`。

## FM1 编队系统重做 备忘(2026-09)

### 一句话

**编队不再有自己的航线。编队的路径就是旗舰的 `s.orders`。**

### 为什么要重做

改前编队走 `F.queue` —— 一套**平行于 `s.orders` 的第二航线结构**(`F={id,dest,curType,queue,fmAng,arrived}`)。
后果是编队被隔离在运动内核之外,**四样已经调好的东西一样都吃不到**:

| 内核能力 | 改前编队 | 拦截点 |
|---|---|---|
| `routeCap` 速度倒推(RF13) | ✗ | 只在 `s.orders` 的 pass 分支里接 |
| `cornerSpd` 曲率限速(RF21) | ✗ | 同上 |
| `rrStart` 航线细化(RF14) | ✗ | `32-route-refine.js` 里 `\|\| ship.formation` 直接 return |
| `face` 到达朝向(RF11/RF22) | ✗ | `addWaypoint` 的编队分支根本传不进 face |

它同时也是四层补丁的根源:**`F.dest` 是玩家看不见也管不着的隐形点**,于是要 DS186 收口、DS193 锚点跟随 + 队长模式、DS194 到位判定补丁、KIMI151 清残留。四层叠完仍然留着"渲染锚 `F.dest`、仿真锚 `flag.pos`,两者只在锚点跟随生效那一瞬才对齐"的分家。

### 新架构:五层,职责单一

```
40-slots.js     几何纯函数   不读全局 ships/groups,不写船状态。参数由调用方传入
41-groups.js    编组名册     只管 groups[g]={ships,flagship,name,fm}
42-formation.js 生命周期     建/散/换旗/重排/调参。F={id,gid,P,fmAng,n,flagId}
43-step.js      每 tick 结算  stepFormation(F,dt)->{flag,ca,sa,spd,w,maxDev,formed}
44-orders.js    命令层       【唯一】写 s.orders 的地方,散船与旗舰共用同一套原语
```

`F` 里**没有** `dest/queue/curType/arrived`。删掉的还有:`rotAng` `formationRot` `formationOff`
`formationTargets` `formationOffsets` `findFlag` `moveFormation` `rebuildFormations`
`setFan` `setSpacing` `setFormationPreset`,以及三个全局参数 `formationFan` `formationSpacing` `fmGap`。

`31-step-ships.js` 的编队分支现在**只剩"成员跟随"一件事**:旗舰走的是和散船一模一样的 orders 分支,
只在限速链上多接一句 `if(FC)cap=Math.min(cap,FC.spd)`(组速=组内最低档)。
旗舰专用导引、旗舰转向那支 `continue`、`leaderMode` 全部删除 —— 那支 `continue` 的注释里记着一次真实事故
(旗舰永卡该分支 → 编队不机动 / 冲过目标点不停),现在它连同产生它的结构一起消失了。

### 三条刻意的行为变化(不是 bug)

1. **编队 ⟺ 编组一一对应**。改前 `moveFormation` 的 else 支会把"异编队+散船的混合选择"强行重排成一个
   **没有编组号的无名编队** —— 书签栏拿不到它,玩家也没法再选中它。现在混合选择一律各自散船移动,
   要成队请先 `Ctrl+数字` 编组。
2. **阵型参数每编队一份**(`F.P={fan,spacing,gap}`)。改前是三个全局变量,调一下扇面**全场编队一起变**。
3. **走完不解散**。改前队列走完做"原子解散 + 成员各发落位令";现在旗舰令空了就停,成员继续跟旗舰实时位置,
   队形自然保持。语义上等价于 v137 的"到位待命保留阵型",但不再需要 `arrived` 这个状态位。

### 保住的核心思想(七条,都是踩坑换来的,动它们要有理由)

1. 一个编队一个共享对象,每 tick 只结算一次(`formTickCtx`)—— KIMI146 从 O(船²) 副本同步救回来的
2. 旗舰即编队原点(`recenterSlots` 归零),导引/绘制/成形判定共用一个锚 —— DS189
3. 成员用**拦截前置点**而不是纯追踪(`slotVel*tau`)—— 纯追踪横移槽位必画追踪圈,DS195
4. 阵型旋转限速按**最远槽位半径**缩放(`ω=1500/R`)—— 固定 0.5rad/s 会让远槽位以数万 km/s 横扫,成员物理追不上
5. 组速取组内最低(`speedCmd===0` 拉停全队,`-1` 不参与 min)
6. 阵型按 `CLS_ROLE` 三桶算出来(主力横队/护卫弧线/侦察外扇),不是玩家手摆
7. 换旗兜底:名册是旗舰唯一真相源,`fmFlag` 找不到才顺位并回写,随后 `fmReslot` 按新锚点重排

### 渲染锚点统一

`fmOffOf(s)`(42 层)取代 `formationOff`,锚点改成**旗舰实时位置** —— 与 `31` 里成员真正在追的目标同锚。
改前渲染锚 `F.dest`、仿真锚 `flag.pos`,**画出来的阵位点不是船在追的点**,靠 DS193 锚点跟随才偶然对齐。

### 编队 UI 是从零补的,不是改的

`js/core/01-state.js:48` 的 `SIMPLE_UI=true` 让右键菜单(`72-context-menu.js:6` 首行 return)、
底部快捷栏 `#qbar`、舰队面板 `#fleet`、设置遮罩 `#overlay` **全部不可见**。
也就是说重做之前**编队没有任何可见 UI**,玩家只能靠 `Ctrl+数字` + 画布右键盲操作。
新增的左轨编队书签栏 `#fmBar` + 编队菜单 `#fmMenu`(`js/render/87-fmbar.js`)是唯一入口。

两条几何坑:
- `84-scene.js` 每帧在**固定屏幕坐标** `fillRect(10,72,168,18)` 画"🔭 已点亮 N 艘敌舰",
  正好落在左轨车道(left:10 / top:68 / width:260)里。已把它右移到左轨之外。
- `.fm-tab` 的 `transition` 是**全项目唯一一条** —— `css/app.css` 原本零 transition,hover 一律瞬时换色。
  这条是用户明确要的"书签往右移动突出一下",别顺手给别的选择器也加。

### 代价:换旗必须换航线(对抗式复核抓到的头号回归)

"路径 = 旗舰的 orders" 有一个必然推论:**旗舰换人时,航线必须跟着换人**。第一版没写这段交接,于是三条路径全炸:

| 路径 | 症状 |
|---|---|
| 旗舰战损(`55-damage`) | `s.orders=[]` 把航线连同旗舰一起清掉,顺位新旗舰 orders 为空 |
| 设为旗舰(`setFlagship`) | 只改名册,新旗舰无令 |
| 旗舰单舰脱队(`fmLeave`,长按定向/G 倒车/单选右键三处共用) | 同上 |

三者的共同结局:新旗舰落到 `31-step-ships` 最后那个 `else` → `steerToVel(0)` → **整队在航线中段原地停死,航线无声蒸发,事件流一条日志都没有**;同时旧旗舰以成员身份继续持令,地图上画一条谁也不飞的幽灵航线,解散那一刻它独自飞走。改前 `F.queue` 属于编队实体,换旗天然不丢航线 —— 这是重做**引入**的回归,不是继承的。

修法是 `42-formation` 的 `fmTakeRoute(to,from)`:**整条 orders 数组换主**(不是逐条复制),`pass/stop`、`face`、`pt`(提前起转锁存)一并带走,新旗舰接着当前这一段继续飞。三个调用点 + `43-step` 的换旗兜底(`F.flagId!==flag.id` 时从旧旗舰取)。探针 `FLOW26_FMHANDOFF`,做过反向对照:删掉那两句立刻变红成 `令=0 速度=0`。

### 另外两条被复核钉死的不变量

1. **成员不持令**。`31-step-ships` 的成员分支排在 orders 分支【之前】,所以写给成员的令永远不被消费、也不递减 —— 它冻在那里,直到脱队/解散那一刻突然复活,舰船自己飞向几分钟前的旧目标;`82`/`83` 还会照着它画幽灵航线。`fmMoveTo`/`fmAppend` 本来就清,漏的是**入队**这条路径(`fmEnsure`/`fmSyncGroup`,"就地成形"正走它)—— 现在统一走 `fmClearMemberOrders`(连 `patrol` 一起清)。
   同源问题:`bots/60-tasks` 的五处 `!s.orders.length` 会给成员写任务令 → 加 `taskCanOrder(s)` 谓词,**编队里只有旗舰接任务令**,整队跟着它走。

2. **不许有僵尸 F**。编队实体挂在 `groups[g].fm` 上,只清 `s.formation` 会留下一个零成员的 F:`fmGet` 恒真 → 书签栏永远显示"已成队",而整队停车/阵型参数按钮全都静默空转(`fmFlag` 返回 null)。三个漏点已堵:`fmOnDeath`(人数塌到 2 以下当场解散,兜住"最后一批同拍全灭"——`31` 那条兜底进不去)、`fmSyncGroup`(从别组挖人时先 `fmLeave` 摘旧 F)、`72-context-menu` 的"移动"(原来裸写 `s.formation=null`,`fmLeave` 因此当场早退,两个 F 都摘不掉)。

### 已知未修(报给用户,没动)

`40-slots` 的护卫弧线在 `nFri===2` 与 `nFri>2` 两支**张角口径不一致**:2 艘用 `±fan/2`,3 艘以上用 `±fan`。默认 `fan=±120°` 时,第 3 艘护卫入列会让原有两艘从 ±60° 甩到 ±120°,槽位瞬移约 2.9 万 km(`fmAng` 有 `wMax` 限速,**槽位重排没有**)。这是改前就有的几何,`_backup_before_tier_p2_p3` 里一模一样;但 FM1 新增的"人数变化即 `fmReslot`"让它从潜伏变成了每次战损都会触发。要修得先定 `fan` 到底是半角还是全角 —— 改哪一支都会挪动所有现存编队的形状,属于数值/手感调整,留给用户定夺。

### 验证

- **散船运动路径逐位不变**:`tools/train/bench_all.js` 改动前后都是 `5.8607`(拿 `git archive HEAD` 跑的对照)。
  这条是本次重做最重要的护栏 —— 编队接进内核**不许动散船那条已经调了七轮的曲线**。
- 编队专项探针见 `tools/verify.sh` 的 `FLOW23_FMCORE`(接内核) / `FLOW24_FMSLOT`(成员保位) / `FLOW25_FMFACE`(到达朝向) / `FLOW26_FMHANDOFF`(航线过继·带反向对照) / `FLOW27_FMBAR`(书签栏走真实 DOM 事件,13 个按钮全点一遍)。
  改前**唯一**的编队探针是 `FORM`(一行 `moveFormation`,不步进不判定不进总判定),从基线到今天数值一字未变。

## FM2 编队改成 RTS 语义 + 终点静态分配 备忘(2026-09)

用户两条反馈,都指向同一件事:**编队不该有"实时"的东西**。

### 一、选中什么就命令什么

`expandToFleet`(选中编组里任何一艘 → 命令整组)**整个删除**。单独选中一艘僚舰右键,不该把全队指挥走。
配套把 `sameGroupShips` 改成**严格全等**:list 必须恰好是某编组的全部活船才算编队命令 ——
改前只要求 `list ⊆ grp.ships`,选 3 艘里的 2 艘也会被判成编队命令、连带指挥没选中的那一艘。

**派走的那一艘不脱队**。编队成员身份与"这一次去哪"无关,下次全队下令时它照常拿到自己的阵位终点自动归位
(RTS 控制组语义)。所以 `moveShips`/长按定向/G 倒车三处的 `fmLeave` 全部拿掉。

### 二、终点在下令那一刻算死,不实时跟随

FM1 是 leader-follower:成员每 tick 追 `旗舰实时位置 + 旋转槽位`。用户原话"其他船的终点路径会随着旗舰偏移,
很奇怪"。FM2 改成 **assign-then-go**:`fmSpread` 在下令那一刻把编队级目标点展开成每艘船的绝对终点
(`dest + 自己那个已旋转的槽位偏移`),写进各自的 `s.orders`。

连锁收益比预想的大:

| 删掉的东西 | 为什么能删 |
|---|---|
| `31-step-ships` 的成员跟随分支 | 成员现在走散船那条分支 |
| `43-step` 的 `fmAng` 平滑旋转 + `wMax` 限速(DS195) | 阵型朝向只在下令时算一次 |
| 拦截前置点 `slotVel*tau`(DS195) | 没有移动的槽位要拦截了 |
| `fmTakeRoute` 航线过继 + `fmOnDeath` 的过继半边 | 每艘船有自己的航线,旗舰死了不影响别人 |
| `fmClearMemberOrders`(以及"成员不持令"这条不变量) | 成员**应该**持令 |
| `60-tasks` 的 `taskCanOrder` 编队分支 | 任务令对成员照常生效了 |
| `82-ship-icons` 的成员读旗舰 orders 特例 | 散船画法天然画出每艘船的终点 |

**四样内核能力现在对每一艘船生效**,不再只有旗舰:`routeCap` / `cornerSpd` / `rrStart` / `face`。
探针 `FLOW25` 实测 face 展开到全部 3 艘;`FLOW23` 实测编队与散船同航线**拐点速度差 = 0**。

顺带治好的老毛病:FM1 时 180° 掉头,槽位切向速度按 `1500/R` 算出来是 1500km/s 而 DD 只能跑 800,
成员追不上,实测掉队 **4.8 万 km**。现在成员飞的是固定点,这个量纲上就不存在了。

### 三、编队速度 = 加权平均(不是组内最低)

`fmSpd(F)` = 各舰当前速度档的**按舰数加权算术平均**(`Σ cruiseOf(s)/n`)。
改前取组内最低,一艘慢船把整队拖到它的速度。现在多数快船不会被个别掉队者拖死;
慢船本来就跑不到平均值(`cruiseOf` 把它钳在自己档位上),它只是**晚一点到自己的终点,终点位置不受影响**。
`speedCmd===0`(定速停)仍拉停全队;`-1`(不限速)不参与平均,全员 -1 时返回 `Infinity`(不加上限 ——
改前这里回退 500,是个没来由的降档)。

### 四、`F` 里剩下什么

`F = {id, gid, P:{fan,spacing,gap}, ang, dest0, n, flagId}`

`ang` 是**上次下令算出的阵型朝向**(不是每 tick 平滑量);`dest0` 是**上一个编队级目标点**,
只用来算下一段的阵型朝向(追加路径点时阵型跟着新航段转)。两个都不是航线 —— 航线在各船自己的 `orders` 里。

### 五、探针改写

`FLOW23_FMCORE` 判据从"旗舰3条令/成员0条"翻成"各舰 3/3/3 + 终点=目标点+自己的旋转槽位";
`FLOW24_FMSLOT`(成员保位)→ `FLOW24_FMSTATIC`(**终点静态**):反向对照是**把旗舰硬拽走 20 万公里,
终点漂移必须是 0** —— FM1 那套实时槽位会当场跟着漂 20 万;
`FLOW26_FMHANDOFF`(航线过继)→ `FLOW26_FMRTS`(选中什么命令什么 + 归位 + 战损无影响 + 无僵尸 F);
`FORM` 从"成员持令须 0"翻成"各持 1 条令 + 终点几何正确"。

**踩过的坑**:改 `FLOW25` 时 `s.replace("&&held===0&&", ...)` 全局替换,把 `FORM` 里同名变量的判据也改了 ——
判据碰巧变正确,但**文案还写着"须0"**。字符串替换插探针时,锚点在文件里出现几次一定要先数。

### 六、新失效的死代码(未删,等确认)

`isFlagship`(41-groups)与 `setGroupName`(41-groups)现在**零调用点**。前者随 `expandToFleet`/旧渲染特例一起失去了
调用方;后者是给"重命名编队"预留的,书签菜单还没做这个入口。两个都留着没删。

## FL1 一层化 + 通用跟随层 + UI 分工 备忘(2026-09)

### 一、编组层删除,编队是唯一的一层

全局 `groups` 与 `js/formation/41-groups.js` **整个删除**。改前是「编组名册 `groups[g]` + 编队实体 F」两层,
靠 `fmSyncGroup` 来回同步,还带出一个**"编组存在但编队不存在"的中间态** —— 侦察数出 12 处代码在处理它
(未成队 / 就地成形 / 不足2艘 / 解散只散实体保留名册 / …)。现在:

```
formations['1'..'4'] = F = {id, name, ships[], flagship, P, mode, follow, ang, dest0, n, flagId}
编队存在 ⟺ formations[k] 存在 ⟺ 名册里至少 2 艘活船
```

`Ctrl+数字` 直接 `fmCreate(k, 选中舰)`,少于 2 艘就清掉这个槽位。中间态没了,「就地成形」退化成「重排阵位」。

连带删掉的旧 UI:`87-fleetcards` 的编组卡整套(SIMPLE_UI 下本就不可见,DOM 照建事件照挂每 20 帧照算读数)、
`72-context-menu` 的 12 条编组菜单项(全部走 `showCtx`,而它首行 `if(SIMPLE_UI)return`)。
`41` 这个编号空出来给了跟随层。

### 二、通用跟随层 `41-follow.js`

**本层不认识"编队"**,只回答"这艘船跟着谁、保持什么相对位置":`s.follow = {tid, off, ang}`。
三种用法是同一个原语的特例:

| 用法 | 怎么写 |
|---|---|
| 船跟船 | `followSet(a, b, [dx,dy,0])` |
| 成员跟旗舰 | 编队 `mode='follow'` 时,每个成员 `followSet(m, flag, m.fmSlot)` |
| 编队跟编队 | 跟随方每艘 `followSet(m, 目标旗舰, 队间偏移 + 自己的阵位偏移)` |

两条设计要点:
- **`off` 在目标的局部系里**,按目标航向旋转。所以"跟在正后方"在目标掉头后仍然成立(探针实测:A 先朝 +x
  再转 +y,跟随者绕到了新航向的后方,而不是留在世界系 -x)。
- **`ang` 存在跟随关系上**(不是目标舰上):同一编队的成员输入相同、限速相同,演化天然同步,又不污染被跟随者。

### 三、分支必须排在 orders 【之后】

`31-step-ships` 的顺序:`brake → orders → follow → turnTarget → patrol → lockedTarget → else`。

FM1 把成员跟随排在 orders **之前**,于是写给成员的令永远不被消费、冻在那里、脱队那一刻突然复活 ——
"成员不持令"那条不变量就是为这个打的补丁。排在**后面**,语义变成【有令先走令,令空才跟随】:
给跟随中的舰单独下个令,它去办完再自动跟回来(探针 FLOW28 的核心断言),不产生僵尸令,那条不变量随之消失。
`stepFollow` 返回 false(目标没了)时整个条件为假,自然落到下一分支,不会把船卡死。

### 四、拦截前置点是错的 —— 删掉它

FM1 的成员跟随用了拦截前置点 `aim = p + v·tau`,`tau = err/(brakeCurveSpd(err)+50)`,
理由是"纯追踪追一个横移的点必画追踪圈"。

**那个理由的病根其实是 `vT` 传错了** —— 它传的是旗舰速度 `flag.vel`,而不是**跟随点自己的速度**
(要带 `ω×r` 那一项)。侦察查出前置点用 `slotVel`、`vT` 却用 `flag.vel`,两处口径分家。
`vT` 传对之后,在跟随点的运动系里 `want_rel = dir·brakeCurveSpd(err)` —— 对 err 单调收敛的一阶系统,
**根本不需要前置量**;而前置量自己会形成稳态偏差:

```
平衡条件 brakeCurveSpd(d) + 50 = |v|  ⇒  d = CFG.arrive + (|v|-50)²/(2·thrust·GUIDE_EFF)
巡航 800 km/s 时 d ≈ 2.1 万 km
```

探针 `FLOW28` 第一次跑就抓到了:跟随者该跟 3 万,实测顶到只剩 2 万。删掉前置点后:

| 读数 | 有前置点 | 无前置点 |
|---|---|---|
| 跟随态航程中最大离位 | 15214 km | **357 km** |
| 跟随态到位后离位 | 400 km | **90 km** |
| 编队跟编队全队离跟随点 | — | **397 km** |

**教训**:一个补丁("加前置点")掩盖了另一个 bug("vT 传错"),而补丁本身带来了新的稳态误差。
修好根因之后要回头问一句:当初那个补丁还需要吗?

### 五、限速常数绑到实际能力

DS195 的槽位切向限速 `wMax = max(0.05, 1500/R)` 里,1500 是**硬编码的线速度上限(km/s)**,
而 DD 巡航只有 800 —— 这正是 FM1"180° 掉头掉队 4.8 万 km"的直接来源。
现在 `stepFollow(s, dt, tipV)` 的 `tipV` 由调用方给:编队传编队速度(`fmSpd`),散船传自己的巡航档。

## FL3 阵位态槽位重配对 / 跟随速度上限(2026-09)

### 一、多点航线不再交叉:每段重新配对槽位

用户报的现象:"本来 船A-旗舰-船B,下一个路径点变成 船B-旗舰-船A",两条航线在中间交叉。

根因:**槽位所有权是认死的**(`s.fmSlot` 建队时分好就不动),而 `fmSpread` 每段按航向旋转它 ——
航向反转 180° 时左翼槽位转到了世界坐标的右边,两艘僚舰于是必须互换位置。

解法把它当**欧氏指派问题**:平面上若两条指派线段相交,交换这两个指派**必定使总长变短**
(三角不等式,两次严格不等相加)。所以反复做"能降低总代价就交换"直到无可改善 —— **不动点必然无任何交叉**。
N 很小(一支编队几艘船),O(n²) 扫几轮就收敛,不需要匈牙利算法。`fmReassign`(42-formation)。

两条约束:
- **只在同角色桶内换**(`CLS_ROLE`)。跨桶换会让驱逐舰去占主力舰的横队位,阵型形状当场变样。
- **旗舰不参与**。`recenterSlots` 保证旗舰槽位恒为 `[0,0,0]`(它是阵型锚点),换给别人就没锚了。
- 配对结果**落盘**(改写 `s.fmSlot`),否则跟随偏移与 UI 离位读数跟不上。

探针 `FLOW32_FMCROSS` 用严格跨立的线段相交判定,并带一条**必须为真**的对照:
同场景下"不重配对"的朴素终点必须相交 —— 否则说明探针没测到东西(摆位不对时两条断言会同时 false 而"通过")。

### 二、跟随速度上限 = 跟随者自己的巡航档(钳总速度)

FM1 给 `guideTo` 传 `cap=Infinity`(理由:"成员必须能超速才追得回队形"),追赶时跟随者会飙到远超档位。
用户要求去掉:"跟随时速度使用被跟随舰的速度,如果被跟随舰的速度很快,那追不上就追不上"。

**不能只改 `guideTo` 的 cap** —— 它的 `vT` 前馈那一项不受 cap 约束(cap 只限制接近项),
所以 `stepFollow` 自己合成 `want` 再整体钳一次。`speedCmd=-1/0` 两条既有语义自然继承。

### ★ 必须知道的后果:同档位的编队,航程中收不拢

`want` 的总速度被钳在 `cruiseOf(跟随者)` 上,而跟随点以旗舰速度移动,所以
**closing speed = 跟随者档位 − 旗舰速度**。当两者档位相同时这个差是 **0**:

- 跟随态编队若在**散开状态**下起步,航程中那份初始散开**永远收不回来**;
- 只有旗舰停下(跟随点不动)时才收拢 —— 探针实测:航程中离位 29716km 稳住不变,到位后 400km。

这是"速度不超自己档位"的数学必然,不是 bug。混合舰种时有余量(CA 700 领队 / DD 800 跟随 → 100km/s 追赶),
同舰种同档位时没有。`FLOW29_FMMODE` 的判据因此从"离位<20000"改成"**航程中不发散 + 到位后收拢**" ——
**刻意没有把阈值放宽了事**,那会留下一条永远不会变红的判据。

想让同档位编队也能成形,唯一的杠杆是**让旗舰让速**(RTS 里的标准做法:队形没成形时领队减速等)。
那是一条新的设计决定,没做,已报给用户。

## FL4 跟随态折返不再交叉;"旗舰让速"被否掉(2026-09)

### 跟随态的交叉:根因不在跟随层

用户报"跟随模式下依然有交叉航线"。实测确认:折返时两条世界轨迹严格跨立 1 次。

**根因与阵位态是同一个** —— 槽位所有权认死。成员追的是 `旗舰位置 + rotSlot(自己的 fmSlot, 平滑航向)`,
航向转过 180° 时那个点画着圆弧扫到对面去。关键在于:

> **想让僚舰"保持在旗舰的同一侧",在世界坐标里就【必须】穿过对方。**

实测读数把这一点说得很清楚:修之前两艘僚舰相对旗舰的左右**没变**(一直是右/左),而轨迹交叉了 1 次。
所以"不交叉"的代价就是**允许换边** —— 每艘船去占离自己最近的那个槽位,谁也不用穿过谁。

`fmFollowReslot`(42-formation,由 43-step 每 tick 调):与阵位态的 `fmReassign` 同一个 2-opt,区别是
- 阵位态在**下令那一刻**配一次(每段一次);跟随态没有"段",必须**连续**配;
- 因此需要**迟滞**:只有收益超过 `MARGIN = max(500, R*0.1)` 才换。临界点是两个候选代价相等处
  (对称阵型即航向转过 90°),迟滞把它变成一条 2×MARGIN 宽的带。没有迟滞的话航向在临界角抖一下就来回换槽位。

实测:整段折返槽位易主 **1 次**,直线航行对照 **0 次**,折返后离阵位仍是 400km。

探针 `FLOW34_FOLCROSS` 四条判据缺一不可,其中第 ② 条是关键的**防自欺**:
"相对旗舰的左右确实换了" —— 没换就说明根本没重配、第 ① 条的"交叉 0 次"只是没测到。

### "旗舰让速"被否掉

FL3 报的"同档位编队航程中收不拢",我提的解法是让旗舰在队形没成形时减速等。
**用户否掉了,理由是"旗舰让速不就是阵形模式了吗"** —— 跟随态就该是被动跟随,让速会把两种模式的区别抹掉。
所以这个后果保持原样:同档位编队散开起步就一路散着,只有旗舰停下才收拢。这是设计选择,不是待修项。

## FL5 速度档位在两种模式下都严格生效(2026-09)

用户实测报:"档位在跟随的时候有用,在阵位的时候没用"。**观察准确**,实测印证:

| 档位设为 | 改前·阵位态峰值 | 改前·跟随态峰值 |
|---|---|---|
| 800 / **250** / 800 | 616 / 250 / **616** | 616 / 250 / **800** |
| **400** / 800 / 800 | **400** / 666 / 666 | 400 / **800** / **800** |

阵位态里两艘 800 档的船被 `fmSpd`(全队档位的加权平均 617)压到 **616**,个体档位完全没体现。

根因是 FM2 加的那道"编队速度上限",理由写的是"途中保持队形"。但**两种模式都不需要它**:
- **阵位态**每艘船有自己算死的终点、各飞各的,队形在【终点】成形 —— 途中允许拉开正是 FM2 那个设计;
- **跟随态**是被动跟随,拿它去压旗舰等于变相的"旗舰让速",而那条已被用户明确否掉。

删掉之后每艘船只吃 `cruiseOf(s)`,设多少跑多少(实测 800/250/800 → 800/250/800)。

`fmSpd` 保留,但只当两件事用:
1. 编队菜单的读数 —— 标签从"编队速度"改成"**平均档位**",免得让人以为调它能改速度(它是算出来的,不是设的);
2. 跟随态槽位旋转限速的 `tipV` —— 那里**需要一个全队统一的值**,否则各成员转速不同、阵型会在转弯时扭曲。

探针 `FLOW35_FMGEAR` 双向:① 每艘峰值必须等于自己的档位(不被拉到全队平均);
② 反向对照 —— 把一艘调慢它必须真的慢,否则"删掉上限"会退化成"谁都不限速"。

## FM3-1 方法3 固定模式(snapshot 槽位来源)(2026-09)

编队三模式重构的阶段 1:第二个槽位来源 **snapshot** 落地,用户的"方法3 固定 = 保持建队时的相对位置与朝向"。**建队默认改为 snapshot+static → `F.mode='fixed'`**(FM3-0 时恒 generated → 'slot')。

### 一、槽位来源是纯函数,两种来源同形

- `40-slots` 新增 `snapshotSlots(list, flagId)`:`off_i = rotSlot(pos_i − flag.pos, cos(−h), sin(−h))`,`hdg_i = wrap(θ_i − h)`(h/θ 一律取 **facing** 船头角,不取速度矢量:建队那一刻船可能静止,而"固定"固定的是船头)。返回 `[{s, offset, hdg}]` 与 `formationSlots` 同形。`fmWrapAng(a)` 归一到 (−π, π]。
- **旋转符号**:拍时转 −h、`44-orders` 展开时 `rotSlot(off, cos(ang), sin(ang))` 转 +ang,二者互逆 —— ang=h 时原样还原当前布局,这是 FLOW36 的第一条判据(几何不变量,不抄实现公式)。
- 每舰现在有两个槽位字段:`s.fmSlot`(偏移,旗舰局部系)+ **`s.fmHdg`**(相对旗舰的朝向差,弧度)。旗舰恒 `[0,0,0]/0`;generated 源下 `fmHdg` 恒 0。`fmDetach/fmDelete` 清 `fmSlot` 时顺带清 `fmHdg`。

### 二、`F.snap` 是建队快照,`fmReslot` 只读它

- `F.snap = {shipId:{off,hdg}}` 在 `fmCreate` 时由 `fmSnapTake` 拍一次(以建队时的旗舰为原点)。
- `fmReslot` 按 `F.src` 分发:snapshot → 从 `F.snap` 重算,**绝不从实时位置重拍**(战损/换旗时形状不能变);generated → `formationSlots` 照旧。
- **换旗重心化现场算、不改写快照**:新旗舰 `[0,0,0]/0`,其余 `fmSlot = rotSlot(off_i − off_new, cos(−hdg_new), sin(−hdg_new))`、`fmHdg = wrap(hdg_i − hdg_new)`。快照仍以建队旗舰为原点,所以换旗再换回来精确可逆。
- `fmSetSrc(F,'snapshot'|'generated')` 新增:切到 snapshot 时**重拍**当前相对位置与朝向为新快照 —— 这是"玩家手调完各舰位置再按固定"的入口,也是唯一改写 `F.snap` 的地方。切到 generated 不动 `F.snap`。
- `fmSetParam/fmSetPreset`(扇面/密度/档位)在 snapshot 源下**无可见效果**(`fmReslot` 不读 `P`),按钮仍在、改的 `F.P` 仍留着,切回阵型模式即生效。刻意未藏。

### 三、`fmSpread` 的两条行为差异(固定 vs 阵型)

1. **snapshot 源下不调 `fmReassign`** —— 谁站哪认死。阵型模式的槽位是条令算出来的可互换位置,固定模式的槽位就是"这艘船建队时在旗舰的哪儿",换给别人就不是固定了。折返时航线会交叉,这是固定模式的定义决定的,不是 bug。
2. **snapshot 源下每舰令带 `face_i = [cos(ang+hdg_i), sin(ang+hdg_i)]`**,即到达朝向 = 阵型朝向 + 自己的朝向差。零新机制:`31-step-ships` 到位补转(RF11)本来就吃每舰令上的 `face`。generated 源刻意**不**走这条(沿用调用方传入的 `face`,通常 null → 到位不转,与 FM3-0 前一致)。调用方传入的 `face` 在固定模式下暂被 `face_i` 覆盖 —— 今天没有调用方会对编队传 face(`ghostArm` 多选早返),阶段 3 编队虚影会改成"有 face 时 ang 取 face 方向",届时统一。

### 一、站位算法(`40-slots`)

- `screenBearings(n)`:步长 360/n,从 000 起**左右交替向后**展开 `[0, 360−step, step, 360−2step, …]`,次序 = 填充优先级(已与 USF 10B 1945 表 N=4..9 逐位核对)。

## FM4 能力插槽 + 最优指派 + 舰队编组控制页(2026-09)

把独立沙盘《阵型控制台》的编成模型整体接进游戏。**唯一的接入点是 `40-slots formationSlots(list,P,anchorId)`**,返回形状不变,
下游(`fmReslot` → `s.fmSlot` → 运动/跟随/绘制)一行未动。

### 一、为什么换掉防空环

FM3-2 的条令站位按**单一维度**(`inner×innerIntercept`)降序填一个圆环 —— 那是贪心:一艘舰在"通道"上最强、在"贴身"上垫底,
单维排序看不见这件事,它照样被排到贴身站位去。沙盘上实测(异构舰队):**贪心比最优平均差 8.2%、最坏 25%,96% 的轮次不是最优解**。

### 二、模型层 `js/formation/39-fmcaps.js`(新文件,纯函数)

| 块 | 内容 |
|---|---|
| 能力维度 `FM_DIM` | **9 维**,全部由【配装实例字段】算出,与舰种 tag 无关:贴身/通道/主炮/红外/射频/隐蔽/网络/电战/生存 |
| 站位模板 `FM_STANCE` | 四套:固定模板 14 槽 / 空中为主 12 槽(圆形屏护)/ 水面为主 11 槽(收拢集火)/ 水下为主 12 槽(宽而不深) |
| 带半径 `fmBandRadii` | 五条带 core/close/body/screen/picket,半径全从**护卫自己的近防射程**算,旗舰不参与 min |
| 插槽扩容 `fmGenStations` | 插槽数**不随舰数变**;多出来的舰沿同一插槽方位向两侧轮转(off=0,−1,+1,−2,+2),超 16 艘分任务群 |
| 最优指派 `fmHungarian` | Kuhn–Munkres 最大权二分匹配,O(N³)。探针 `FLOW37` 用穷举对小编队钉死"差恰为 0" |
| 可互换签名 `fmSwapKey` | 九维读数 + inner 全同才同签名 —— 下游两处槽位重配对的分桶键 |

**曾有 13 维,砍掉齐射/照射/机动/信标**:它们在本作里是舰种常量(全队只有两档取值),且齐射↔照射、机动↔信标的秩相关都是 1.000,
从模板里删掉总契合度**损失 0.0%**。保留九维的影响力排序:通道 > 贴身 > 主炮 = 红外 = 网络 > 电战 = 生存 > 射频 > 隐蔽。
**贴身与通道不能合并**:秩相关只有 0.675,且几何相反(贴身要求站位落进该舰 inner 之内,通道要求沿环摊开)。

### 三、`fmReassign` / `fmFollowReslot` 的分桶键必须跟着换(否则最优解被静默推翻)

这两处按欧氏距离重配对槽位以消除航线交叉(FL3/FL4)。防空环时代的桶是"居中/环上 + 能力分",在能力插槽下**粒度不够**:
每个站位各要一种能力,按距离自由交换等于当场推翻匈牙利的解,而且**结果落盘进 `s.fmSlot`**,到下一次 `fmReslot` 才恢复。
现在两处都改用 `fmSwapKey`:**同签名交换是目标函数中性的**(总契合度分毫不变),消交叉的收益照拿;不同签名一律不换。
同型护卫(最常见)照旧可换,FL3/FL4 的收益全保留 —— 反向由 `FLOW36` 的 `gSwap>=2` 守着。

### 四、参数与状态

`F.P` 从 `{spacing}` 扩成 **`{stance, spacing, slots}`**:`stance` 选四套站位之一;`slots` 是**每编队一份**的自定义插槽表
(编组控制页方位盘改出来的,null = 用站位预设)。`fmSetStance(F,k)` 换站位时把 `spacing` 拨到该站位的预设 gap 并丢掉 `P.slots`
(它是按上一套布局改的,套到新布局上没有意义),**自带"值没变就整个返回"的空操作守卫**(同 `fmSetSrc`,免得反复点把已成形的编队踢翻)。

- **`FM_LIMIT.spacing` 上界 2 → 3**:空中为主的预设 gap 是 3.00,不放宽的话切过去会被 clamp 成 2.00。
- **新增展示字段 `s.fmStn = {nm,cap,band,fit,r}`**:`fmReslot` 的 generated 分支写、snapshot 分支清(**两条分支都要清,旗舰那条早退分支曾漏过**)。
  纯展示,任何逻辑分支都不许读它 —— 它保证"画出来的站位"与"船真正要去的站位"是同一份数据。

### 六、行为变化(不是 bug,但请复核)

1. **舰少时航母会被派上屏护环**。固定模板的前 5 个插槽全是屏护(通道),而插槽按次序填 —— 4 舰编队只生成 3 个站位,全在屏护带,
   CV 无处可去。改前 `fmDoctrineSplit` 是**按舰种谓词**强制把无主炮的舰放居中。匈牙利会把它放进三个里最不要害的那个(优先级最低),
   但它确实上了环。要改的是**插槽表次序**(把 body 带的槽提前),那是设计决定,没动。
2. **贴身站位的几何门几乎不触发**。`close = 0.9 × bm × min(inner)`,而 `min(inner) ≤ 任何一舰的 inner`,所以 `bm ≤ 1.111` 时它对谁都不生效 ——
   固定/水面/水下三套(bm=1.00)恒不生效,只有空中为主(bm=1.15 ⇒ close = 1.035×min)会把内圈最小的那几艘拦在贴身站位外。
3. **水下为主的编队很大**:哨戒带 = 2×屏护半径,再乘扁率 1.85,8 舰编队横向铺到约 ±18.5 万 km。这是"宽而不深"的直接后果。
4. **匈牙利是 O(N³)**,只在 `fmReslot`(建队/战损/加员/换旗/调参)跑,不在每帧路径上。20 舰约 8000 次内层运算,200 舰约 8×10⁶ —— 后者会有可感的一拍卡顿。

## FM6 跟随下沉为标准控件 / 五个几何旋钮开放 / 编队级虚影(2026-09)

用户四条定案,一次做完。**跟随不再是编队的一种模式**,它下沉成一个通用控件;**五个几何参数全部交给玩家**;
**编队级长按右键定阵型朝向**(FM3-1 备忘里预告的"阶段 3")落地。

### 一、跟随:一个函数,两端各自可以是单舰或编队

用户原话:"跟随逻辑不是解耦的么?跟随应该就是一个函数,a target b,只是这个 a 和 b 可以用在单舰船和舰队上面。"
第一版实现按源侧分了叉(编队走 `fmFollowShip`、散船走 `followSet`),**那不是解耦**。现在先把两端归一:

> **单舰 ≡ 成员只有自己、半径 0、内部阵位偏移 [0,0,0] 的编队**

归一之后偏移只有一个公式,四种组合都是它的特例:

```
off_i = [−(半径(A) + 半径(B) + FOLLOW_GAP), 0, 0] + A 内部第 i 位的阵位偏移
```

`followUnitOf(list)`(跟随方)与 `followAnchorOf(target)`(被跟随方)各自把一端归一,`followAssign` 只写一遍公式。
`fmFollowShip` 随之**变成一行转发** —— 它改前自带一份 `-(fmRadius(F) + tfRadius + 50000)`,与散船那条路各算各的,
同一个"队间距"概念两处实现。探针 ④b 直接把这条主张量出来:单舰→单舰 `50000` = GAP,
单舰→舰队与舰队→单舰都是 `100000` = R(F) + GAP —— 半径为 0 的那一端自动退化。

**作用域按【选中集合】判,不按 `fmOf`**:选中恰好等于某支编队的全部活船才算编队源,与右键移动"选中什么就命令什么"(FM2)同一条口径。
被跟随方则按 `fmOf` 判(点编队里任一艘 = 跟随那支编队,即它的旗舰),沿用 `fmFollowShip` 的既有口径。

两条守卫:**同队算自跟随一律拒绝** —— 不拦的话会走到散船分支,而它为了让跟随不被 `fmApplyFollow` 覆盖会先 `fmDetach`,
于是"让本队一艘去跟本队旗舰"这个看起来无害的操作会**静默把它踢出编队**;单舰去跟别队时那次脱队是真的,所以打日志说清楚。

入口从编队菜单搬到**底栏** `#cmdBar`(`cbFollow`/`cbUnfollow`,88-selpanel)。两个钮**刻意不进 `cmdList`** ——
那张表是"每舰一个布尔开关"的形状(get/set + 全选统一置值),而跟随是一次性动作、作用域是整个选中集合,
硬塞进去会像 RF8 那个大序列钮一样在 `if(!cmd.set)return` 那行被静默吃掉。
`pendingFmFollow` → **`pendingFollow`**,语义随之变:不再预存编队 id(选中一变就过期),作用域按点下去那一刻的 `selected` 现算;
`#cmdTip` 的提示也把当前作用域写出来(四种组合里最容易搞混的就是"这一下是整队跟还是这一艘跟")。

### 二、编队的跟随模式整个删除

`F.motion` 这个轴、`fmSetMode`、`fmFollowReslot`(跟随态每 tick 连续重配槽位带迟滞)、
`fmApplyFollow` 的内部跟随分支、`43-step` 与 `44 fmSpread` 的两处 follow 分发 —— 全部删除。
编队只剩"下令那一刻把编队级目标点展开成每艘船的绝对终点"一种运动方式,`fmModeOf` 退化成 `F.src` 的别名。
**通用跟随层 41-follow 一行未削弱**,它是底栏控件的地基;编队整体跟随(`F.follow`)也照旧。
探针 `FLOW29_FMMODE`(两种模式互为反向对照)与 `FLOW34_FOLCROSS`(跟随态折返不交叉)随之整条删除 ——

### 三、五个几何旋钮开放给玩家

`F.P` 从 `{stance, spacing, slots}` 扩成 **`{stance, spread, spacing, bm, widen, bstr, slots}`**,站位预设只是初值 ——
`fmSetStance` 切站位时把整组拷进 `P`,之后逐项手调的是编队自己那一份。`FM_LIMIT` 给每一项配区间(越界防线只在 `fmClamp` 一处)。

**取数唯一定义点是新增的 `fmGeoOf(P)`**(39-fmcaps):几何计算 `fmPlanStations`、地图绘制 `84-fmplot`、
编组控制页的方位盘与**拖动反解** `89-fmpage` 必须全部走它。任何一处直接读 `fmStanceOf(P).bm` 都会与玩家调过的值分家 ——
盘上拖到哪、船就站到哪,靠的正是这三处同源。

UI 两处、状态一份:编组控制页五个滑块(`data-fpk`),编队菜单**另放一个带半径滑块**(`data-fmk="bm"`,随阵型模式显隐)。
用户的判断是对的 —— 带半径是五个里唯一**恒生效**的(spacing 只在舰数超过插槽数时有效,spread/widen 改的是形状不是尺度),
所以给它一条快捷通道。两处写的是同一个 `F.P.bm`、同一个 `fmSetParam`,不存在两份状态。

三个实现细节都对着已知陷阱:①`fmSetParam` 加"值没变就整个返回"的空操作守卫 —— 不守的话拖滑块每帧都 `fmReslot`,
而它会把 `44 fmReassign` 落盘的同签名配对抹回原序,离位读数当场乱跳(FM3-2c 第二轮那个坑);
②滑块走 `input` 事件但**拖动中不整页重渲** —— 那会把正在拖的 `<input>` 换成新节点、拖拽当场断掉(RF7c 那条),
松手时补一次;③`updFmBar` 每 20 帧回写滑块 value 时判 `document.activeElement` —— 不判的话玩家拖到一半会被弹回,手感是"拖不动"。

### 四、编队级长按右键定阵型朝向

**这个功能从来没有过,不是回归**:`ghostArm` 从 RF11 落地起就是 `if(sel.length!==1)return false`,备忘里也写着"仅单舰"。

只画旗舰一个船影的话,玩家看到的承诺(一艘船朝某个方向)与实际发生的事(整队按该朝向摆开)对不上。

## FM6c/FM6d 编队菜单三处布局修复(2026-09)

### 一、「编组控制」钮永久不可见(FM6c)

装「随模式显隐」的块用了 **`data-fmm` 当字典键**,而阵型模式下有**两块**同键(编组控制 / 带半径滑块),
后写的把先写的顶掉 —— 编组控制那一块从此不在表里,`fm-hide` 永远摘不掉:按钮建得出来、
`dispatchEvent` 点得到、就是永远 `display:none`。改成数组,按元素自己的 `data-fmm` 判显隐。

**两条把它放过去的判据一并订正,这比 bug 本身值得记**:

- `FLOW27` 原本写死「可见的那串必须恰好是 `fixed` / `slot`」—— 这句话把**一个模式只有一块**当成了前提。
  阵型模式实际声明两块,真相应该是 `slot,slot`;而当时的代码恰好只显示得出一块,
  **判据与 bug 互相印证,一起绿着发了版**。现在改成与块数无关的两条不变量:可见块全部同名 + 个数等于声明数。
- `FLOW38` 原本只断言「钮存在」。**`dispatchEvent` 对 `display:none` 的元素照样生效**,所以死钮天生免疫这条 ——
  同 FM5d 那个「有钮无 case」是一类。现在问浏览器 `offsetParent`,并把两块显隐一起验成互斥。

### 二、模式分段控件只铺满 2/3(FM6d)

`.fm-seg` 的列数写死 `repeat(3,1fr)`,而 FM6 把「跟随」那一段删掉之后 CSS 没跟着改 ——
两段各占 1/3、右边空着一格。改成 `grid-auto-flow:column` + `grid-auto-columns:1fr` 按子元素个数自适应,
**以后加减模式段不必再回来动 CSS**(那正是这次出问题的耦合)。
判据只能问 `getBoundingClientRect`:类名写对了、CSS 里列数写了几,都不等于屏幕上真的铺满了。
用比例不用绝对像素(轨宽随视口变):铺满率须 >95%(旧 3 列时是 66.7%)、两段等宽率 >90%。

### 三、公共区并成一排三钮 + 带半径滑块移回编组控制页(FM6d)

### 四、新增「原地重排」(reform)

**为什么需要它(实测,不是推断)**:改几何参数只会重算槽位,**船一步都不会动**——
把 `bm` 由 1.0 拖到 2.0,离位从 92km 跳到 73742km,空转 120 秒位移为 0,只有下一次移动令才把新阵型落到地上。
这个钮就是那条「不用挪窝的移动令」:目标点取**旗舰当前位置**,其余全交给 `fmSpread` ——
目标点与锚点重合(距离<1),`fmAngOf` 沿用 `F.ang`,阵型朝向原地不变;固定模式走它自己的分支
(不重配对、到达朝向 = 阵型朝向 + 各舰建队时的朝向差),所以**固定态按它 = 回到建队快照的布局,
阵型态按它 = 摆成算出来的插槽站位,一个函数两种模式都对**。零新机制。
副作用照旧按「这是一条移动令」来:`resetForNewOrders` 会解除刹车,整队停车之后按它船会重新动起来。

FM4b 的删除清单里曾有「就地成形」,现在以 `reform` 之名回到公共区 —— 当时菜单里还没有任何几何旋钮,

## FM6h 自定义轮带(2026-09)

用户令三条:删掉「能力与带都选了才会出现在阵型图上」那句提示、插槽设置不许换行、
**轮带可以新增**(不再固定那几条),新带默认叫「自定义轮带」且可以改名。

### 一、数据模型:每编队一份 `P.bands`

```
P.bands = [{ k, nm, mul }]        // 只存自定义的,内置五条不进这里
k    唯一键 u1/u2 —— 不能与内置五条或 BR 上的 baseGap/gap/widen/step 撞名(它们与带同住一个对象)
mul  屏护半径的倍数
```

**半径用倍数不用绝对公里数**,这是本节唯一需要辩护的决定:内置五条全都随「带半径」滑块(`bm`)
整体缩放,写死公里数会出现「拖 bm 别的带都动、就它不动」的分裂。而哨戒带本身就是 `screen × 2`,
自定义带用同一套口径,读起来一致。新带默认 `1.5` —— 落在屏护(1.0)与哨戒(2.0)之间的空档里,
一加出来就看得见一条新圈,不会和现成的圈重叠到看不出加没加。

三个查询函数收在 39-fmcaps:`fmBandKeys(P)` / `fmBandNm(P,k)` / `fmBandNewKey(P)`。
`fmBandRadii` 多收一个 `P`,把自定义带算进 `BR`;`fmPlanStations` 里算 `step`(同带内第 2、3 艘船的
展开角)的那个循环必须从 `FM_BANDS` 换成 `fmBandKeys(P)` —— 漏了的话自定义带上的展开角是 `undefined`。

### 二、内置五条只列不给编辑

它们的半径**全部来自护卫自己的近防射程**(贴身 = 罩得住旗舰、屏护 = 外圈直径…),
改了就不再是「够得着」的意思。所以轮带条里内置带是只读芯片,只有自定义带带名字框、倍数框与删除。

### 三、删带时必须把引用它的插槽 band 置空

不置空的话槽指向一条不存在的带 ⇒ 半径查成 `undefined` ⇒ 坐标 NaN,与 FM6g「带留空」是同一类事故,
只是发生得更晚更难查。置空之后那些槽变回「未完成」,会出现在插槽设置的未完成标签里,玩家看得见。

`fmSlotReady(sl, P)` 另外加了一道**带还在不在**的守卫。它在正常操作里走不到(上面那条路径已经主动置空),
守的是「槽引用了一条不存在的带」这件事本身 —— 旧存档、别的代码路径都可能造出来。

### 四、插槽设置不许换行

`.fp-cfg` 改 `flex-wrap:nowrap` + `overflow-x:auto`:挤不下时整条横向滚动,而不是折成两行把方位盘往下顶。
**轮带那一条例外**(`.fp-bands` 覆盖回 wrap)—— 带可以一直加,不给它换行等于加到第五条就看不见了。

`bench_all` **5.8607** 不变;`verify.sh` ✓ 全部通过,`SYMS_TOTAL=712`,`ERRORS=none`。
FLOW37 的 `fmParamsNew` 键表加了 `bands`(键集合确实变了,是判据跟着改,不是放宽)。

## FM6k 自定义轮带改成绝对半径 + 两态编辑(2026-09)

用户令三条:半径**默认不填**(填了才上视图)、数字直接填「千公里」(去掉后面那个 k 读数)、
红叉左边加一个**绿勾**当确认键,确认后收成小卡片(和内置的「贴身 7k」同形),点卡片再展开。

### 一、半径口径改了:倍数 → 绝对值

FM6h 我选的是「屏护 × 倍数」,理由是内置五条都随「带半径」滑块(`bm`)整体缩放,
写死公里数会出现「拖 bm 别的带都动、就它不动」的分裂。**用户定案用绝对值**,所以那条分裂现在是既定行为:

> 自定义带**不跟着 `bm` 走**。拖 `bm` 时内置的四个圈会动,自定义的不动 —— 这是「玩家填了 150 就是 150」的必然结果。

|---|---|---|

## FM6l 方位盘可平移可缩放(2026-09)

用户令两条:盘面可以拖动但**要有限位、不能整个拖没**,且限位要**对不同阵型都适用**;
盘的右上角加一根**竖直滑块**(上 `+` 下 `−`)当缩放。

### 一、限位为什么写成「贴合半径的倍数」

不同阵型的尺度差着两个数量级:三舰的固定模板与横向铺到 ±18 万公里的水下为主。
但基准缩放 `k = FP_FIT / maxR` 恒把当前编队**撑满到同一个半径 `FP_FIT`** ——
所以限位写成 `FP_FIT` 的倍数,对任何阵型、任何舰数都自动成立,不需要按公里数分档。

```
half = FP_FIT × zoom                 内容半径(svg 单位)
lim  = half + FP_C − FP_KEEP         可平移的最大距离
FP_KEEP = FP_FIT                     至少留一个「贴合半径」的内容在视口里
```

取 `FP_KEEP = FP_FIT` 有个好性质:`zoom=1` 时 `lim` 正好 `= FP_C`,即**阵心最远只能拖到视口边缘**,
永远看得见半个阵型;放大之后 `half` 变大、`lim` 跟着变大,所以**放大了照样拖得到外圈去看**。
(试过 `FP_KEEP=120`:允许把阵型拖到只剩一条弧,十四个插槽圈里只剩一个 —— 算「没消失」但没什么用。)

**按半径钳,不按两个轴各自钳。** 盘上的内容是一张圆盘不是方块:逐轴钳住的话,沿对角线拖到底会落在
包围盒的角上,而那里在最外圈之外 —— 实测 `zoom=2/4` 时十四个插槽圈一个都不剩,画面全空。

### 二、缩放滑块

竖直方向靠 CSS `rotate(-90deg)` 得到,**不用原生的竖直 `range`** —— 那个在不同 Chrome 版本上
min/max 的上下方向不一致(`-webkit-appearance:slider-vertical` 与 `writing-mode:vertical-*` 两套语义),
旋转是确定的:上 = max = 放大。滑块**放在 `<svg>` 外面**的包装 div 里,
所以拖缩放时 `fmPgDialSync()` 只换 `#fpDial` 的 `innerHTML`,滑块节点不会被换掉(同 FM6f 那条)。

### 三、自己的判据抓到自己两个 bug

写探针的过程中翻出两处实现错误,都是「第一版看着能用」:

1. **带圈 / 正前方向标 / 旗舰记号原本写死在 `FP_C` 上**,加了平移之后它们钉在原地不动,

## FM6n 内置四条轮带也可调 + 它们与算法的耦合实测(2026-09)

用户问了一句很要紧的话:**这四条环带是否和布阵算法强相关?改了会不会出问题?**
先量,再改。

### 一、实测:四条里只有【贴身】进算法,另外三条是纯几何

带半径在 `fmPlanStations` 里一共有四个去处:

| 去处 | 性质 |
|---|---|
| `st.lx / st.ly` 站位坐标 | 纯几何 |
| `BR.step[band] = 2·asin(gap / 2r)` 同带内第 2、3 艘船的展开角 | 纯几何,自适应 |
| `2 × BR.screen` 任务群横向错开(>16 舰才有) | 纯几何 |
| **`fit()` 里的 `aaClose` 几何门** | **真耦合** |

那道门是 `if (k === 'aaClose' && st.r > ciwsOf(s).inner) have = 0` —— **阶跃,不是渐变**。
9 舰编队实测(护卫 `inner = 8000`):

```
贴身半径    总契合   贴身站位的契合度
自动 7200    7.600    [1.00, 1.00]
     8000    7.600    [1.00, 1.00]
     8001    5.600    [0.00, 0.00]   ← 一公里之差,整片归零,指派跟着重排
    40000    5.600    [0.00, 0.00]
```

另外三条:屏护取 10k / 50k / 300k,**总契合逐位相同**(`2.000000`),只有站位坐标在动。
`baseGap`(同簇展开的弦长)来自护卫的 `inner`,不来自带半径,所以完全不受影响。

**结论:改被护/屏护/哨戒只动画面与队形尺度,不动"谁站哪";改贴身会。**
自动值刻意取 `minIn × 0.9`(留 10% 余量)就是为了永远落在门内。

### 二、据此设计

内置四条与自定义带共用同一个两态控件(小卡片 ↔ `名字 | 半径 | K | ✓ | ↺`),两点差别:

- **内置带不可删**,第二个钮是「**↺ 恢复自动**」。四套站位预设里的插槽全按 `close/body/screen/picket`
  这几个键写死,删掉等于把所有预设插槽一次性作废。
- **贴身带带超限提醒**:半径越过护卫最小的近防内圈就把卡片标黄,`title` 写明"贴身站位的契合度会整片归零"。
  **不拦**(玩家可能就是想那么摆),只提醒。

半径覆盖是绝对值,**不再乘 `bm`** —— `bm` 是"把算出来的整体缩放",玩家写死的数不该再被缩放一次。
覆盖按**推导链逐级代入**:改了屏护,哨戒的自动值(`= 屏护 × 2`)跟着走;玩家把下游也填了就以他填的为准。

### 三、路上修掉自己三个 bug

1. **`fmBandNm` 先看常量再看覆盖** —— 内置带改名一点反应都没有,名字存进去了、读的时候被常量挡在门外。
2. **内置带的覆盖条目被渲染两遍** —— `fmPgBandCfg` 里取的是 `fmBandsOf`(全量)而不是 `fmBandUser`,
   于是那条带在内置循环里出现一次、在自定义循环里又出现一次,两个卡片指向同一条带。
3. **探针自己**:`⑥c` 取自定义带用的是 `.fp-bd-on` 的第一个,而 FM6n 之后内置四条也是 `.fp-bd-on`,
   于是它开始测「贴身」。改成按键取。

### 四、验证

`bench_all` **5.8607** 不变;`verify.sh` ✓ 全部通过。FLOW38 新增 ⑥d,**六个变异逐条对照**
(覆盖不生效 / 覆盖不走推导链 / 改名读不到 / 只改名就把半径钉死 / 内置带给了删除钮 / 超限不标黄)。

那条耦合判据是**双向**的:改贴身要在「全是贴身插槽」的表上**掉下来**(`2.000 → 0.000`,门真的咬住),
同时在固定模板那张表上**一位不变**(`1.640000 → 1.640000`,那张表里没船站贴身带,本来就不该受影响)。
只测前一半的话,"把 close 接到别处去了"也能过。
另:这支探针编队只有两艘护卫、都落在屏护带上,**贴身站位根本没被填过** ——
所以要用 `slotsOverride` 临时换一张全是贴身的插槽表,把门摆到必经之路上。


## FM6o 原地重排:切模式那条路本来是死的(2026-09)

用户实报「原地重排有问题,不知道它的功能是啥」,并说明了本意:
**在固定队列与阵型队列之间切换之后,手动把队列更新成「固定」或「阵型」该有的样子。**
照这个用法实测,那条路确实是死的,而且死因不在这个钮身上。

### 一、根因:「固定」这个模式钮会把快照当场重拍

`fmSetSrc(F,'snapshot')` 改前**无条件重拍**(FM3-1 写的是"玩家手调完各舰位置再按固定"的入口)。
于是 阵型 → 固定 切过去的那一瞬,**此刻的散乱位置被钉成新队形**:离位恒为 0、船已经"在位"了,
按原地重排什么都不会发生。存了半天的建队队形被一次切换抹掉,而 FM5d 之后重拍本来就有了
显式的「重新固定」钮 —— 两个入口做同一件破坏性的事,其中一个还是玩家最常点的模式钮。

**改法**:`fmSetSrc(F, src, retake)` 加第三参,重拍**只走「重新固定」**(`retake=true`)。
三个钮各司其职:

| 钮 | 做什么 |
|---|---|
| 固定(模式钮) | 切回**已存的**快照队形,不改快照 |
| 重新固定 | 把**此刻**的相对位置拍成新快照 |
| 原地重排 | 让船去它们此刻**该在**的位置 |

`retake` 为假但编队还没有快照时仍要拍一次(兜底;正常路径里 `fmCreate` 已经拍过)。

### 二、顺带:原地重排不会更新阵型朝向

不传 `face` 时 `fmAngOf` 因为"目标点与锚点重合"而沿用 `F.ang` —— 那是**上一道移动令留下的行进方向**,
与玩家眼前看到的船头没关系。实测:把旗舰船头拧过 90° 再按原地重排,整队仍按老朝向摆(`F.ang=0°`)。
改成传旗舰此刻的船头:阵型态整队转到船头方向;固定态是刚体,整个队形绕旗舰转过去,
各舰再按自己建队时的朝向差归位。

### 三、改后实测(五个场景)

```
建队队形 = -20,-12 -28,12 -36,-12 -44,12 -52,-12
A 固定→阵型→原地重排   离位 85612 → 497,摆成插槽站位
B 阵型→固定→原地重排   切固定后离位 82226(快照还在),重排后【一字不差回到建队队形】
C 重新固定              切固定后离位 82225 → 按重新固定 → 离位 0(此刻成了新快照)
D 旗舰拧 90° 再重排     F.ang 0° → 90°,整队跟着转
E 连点两次              第二次一字不差(空操作)
```

B 这一条改前是完全死的。

### 四、验证

`bench_all` **5.8607** 不变;`verify.sh` ✓ 全部通过。三个变异逐条对照:

| 变异 | 转红的那一条 |
|---|---|
| 切 snapshot 退回无条件重拍 | 切到固定后离位=0、重排后偏差 49009km |
| 「重新固定」钮不传 retake | 重排后偏差 120009km(快照从此再也拍不了) |
| 原地重排不传 face | `F.ang=0°`(须 90±3) |

判据两处:
- **FLOW36** 那条"切回 snapshot 重拍"是照**改前的语义**写的,现在拆成两半 ——
  模式钮那条路要"快照一个字都没动 + 离位 > 0",「重新固定」那条路才要"重拍 + 离位归零"。
  只留后一半的话,改前的无条件重拍照样全绿。
- **FLOW27** 新增一段走用户那条路:切固定 → 离位 > 0 → 原地重排 → 回到固定那个队形 → 拧船头再按一次 → `F.ang` 跟到 90°。
  参照**自己钉**(先按一次「重新固定」把此刻定成基准)—— 这支编队在前面几段里飞过、改过 `bm`、切过模式,
  "建队那一刻的队形"早就不是眼前这个,拿它当参照必错;队形比对也走**逐舰最大偏差**而不是字符串逐字比
  (到位容差本来就有几百公里,四舍五入到千公里会在边界上翻一格,那不是行为问题而是比法问题)。


## FM6p 站位图:把「画不画」从副作用改成一条写下来的规则(2026-09)

用户实报:固定→阵型 会冒出一堆"终点目标线",阵型→固定 又没有;并问这是不是逻辑与显示混在了一起。
**是的,而且症状正是那个混淆的直接产物。**

### 一、先定位:那不是航线终点线

实测(令数是关键读数):

```
切到阵型   src=generated  各舰令数=0,0,0,0,0,0  站位→实船连线=5
切回固定   src=snapshot   各舰令数=0,0,0,0,0,0  站位→实船连线=0
```

**令数全程为 0** —— 切模式一条令都不下,所以那不可能是航线层画的。
它是 `84-fmplot drawFmStations` 的「站位 → 实船」细线。

### 二、混在一起的到底是什么

`s.fmStn` 是**写在仿真对象上的展示数据**,由 `fmReslot` 落:generated 分支写它,snapshot 分支清它。
于是 `drawFmStations` 实际上是在问「有没有人写过这个字段」来决定画什么 ——
**两种模式的可视化差异,是哪个分支恰好跑过的副作用,不是任何人写下来的规则**。
用户看到的不对称就是这个。

`s.fmStn` 这个缓存本身**不改**:FM4 特意这么做,是为了让"画出来的站位"与"船真正要去的站位"
是同一份数据(在渲染层重算一遍几何,两处必然漂移;而且那意味着每帧跑一次匈牙利)。
错的从来不是缓存,是**没有人把显示规则写下来**。

改法两条:

1. 判据收成一个具名谓词 `fmpShowsStations(F)`,理由写在它头上 ——
   站位图是**能力站位**的可视化(方位 + 能力 + 带 + 契合度),这几样只有阵型模式有;
   固定模式的队形是一张刚体快照,它的槽位没有能力、没有带、也谈不上契合度,
   **那里没有"站位"可画,不是忘了画**。以后固定模式若要画别的,另写一个谓词,
   不要再靠"字段被写过没有"来决定。
2. **「站位→实船」的连线删掉**(用户令)。它画的是"还没到位",而玩家会把一条从船拉向远处的线
   读成"它正要去那儿" —— 切一下模式就冒出五条长线,而那一刻谁也没在去哪儿。
   「正在去哪儿」由航线层画(有令才有线);「离位多少」是个读数,在右栏。

### 三、判据为什么不走像素

那条线是 1px、35% 透明,压在会变的星云/网格上。实测采样:有线 508、无线 512,
**平行偏移 6px 的本底是 581** —— 线比本底还暗,像素法在这里根本测不准。

改走 **canvas 指令级**:把 `ctx.moveTo/lineTo` 代成记录器,跑一次 `render()`,
数有多少条线段的两端恰好是(某个站位, 某艘实船)。这个量是确定的、没有噪声。
站位小圈那个信号倒是干净的(实心描边、位置固定),所以它仍用像素:阵型 406 / 固定 39。

新探针 `FLOW41_FMPLOT`,场景隔离(只留两艘、清空弹丸/特效/火控序列,同 FLOW31 那条规矩)。
两个变异逐条对照:把连线加回去 → `站位→实船的线段=1条`;谓词恒真 → `固定态 站位小圈亮度=109`。


## FM6q 二元的 face 会把到达朝向【静默】关掉(2026-09)

用户实报:固定→阵型→原地重排,船到位了但**不调整方位,方位一致又没了**。

### 一、根因:`V` 是三维库,喂二元数组回 NaN

FM6o 给原地重排传的 face 是 `[fl.facing[0], fl.facing[1]]` —— **两元**。
而 `V.dot` / `V.len` 都读 `a[2]`,二元进去 `V.angle` 返回 **NaN**;
`31-step-ships` 消费 face 的两处都是 `V.angle(...) > 阈值` 的形式,**NaN 比出来恒为 false**:

| 位置 | 本该做什么 | 二元 face 下 |
|---|---|---|
| 提前起转(RF11) | 剩余航程时间 ≤ 转向时间就开始转 | 不触发 |
| 到位补转 | 到了还没对上就原地转 | 不触发 |

于是:**令上明明挂着 face、船就是不转、一个错都不报**。实测 `0 -23 -9 -88 16 81`(该全 0)。
固定模式没事,因为它那一支用的是 `[cos, sin, 0]` —— 三元。

### 二、修在唯一构造口,不去数调用点

`mkOrder(w, type, face)` 是"一条令的唯一构造口",补齐放这儿:

```js
if (face && type !== 'pass' && isFinite(face[0]) && isFinite(face[1]))
  o.face = [face[0], face[1], isFinite(face[2]) ? face[2] : 0];
```

顺带挡掉非有限值 —— **NaN 的 face 比没有 face 更糟**:它让那两处判据永远为 false,而且查不出来。
(去每个调用点数元素个数的那种改法迟早再漏一个;全库现在只有 `ghostMove.face` 与本次这一处在造 face。)

### 三、判据:不能只看 `F.ang`

FLOW27 原来只断言 `F.ang` 跟到了 90° —— 而**阵型朝向是对的、每一艘船的朝向是错的**,
那条判据对这个 bug 完全免疫。补上"**全员船头离 `F.ang` 的最大偏差 < 5°**"。
FLOW25 另加四条直接打 `mkOrder`:二元补齐 / 三元的 z 保留 / NaN 不许挂 / pass 型不挂。

三个变异:

| 变异 | 结果 |
|---|---|
| `mkOrder` 退回 `face.slice()` | FLOW25 ⑤ 转红(`二元→[0,1]`、NaN 挂上去了) |
| 只把调用点退回二元 | **仍然全绿** —— 这正是 `mkOrder` 那道防线在起作用 |
| 两个都退回(改前的真实状态) | FLOW27 `全员船头离阵型朝向最大=45.1°`,用户的症状复现 |

`bench_all` **5.8607** 不变。


## FM7 一艘船可归入多个编队(命令覆盖)+ 单舰编队 + 测试用加船小条(2026-09)

用户定案的语义:**A 同时在编队1、编队2 里,谁最后下令它就跟谁走。**

### 一、把单值反向引用一分为二

```
s.fms       = [F, …]   归属:它在哪几个编队的名册里          ← 新增
s.formation = F        当前听谁的(单值,语义从"属于谁"变成"谁最后指挥了它")
s.fmSlot    = 按 s.formation 算出来的那一个槽位
```

**为什么不能真的同时站两个位置**:一艘船只有一个 `fmSlot`,而 `31-step-ships:18` 每 tick 就是靠
`s.formation` 决定"这艘船听谁的"(`FC = stepFormation(s.formation, dt)`)。
所以多归属完全活在**名册层**,运动内核看到的永远是单值 —— **它一行都没改**。

**认领发生在下令那一刻**,不是建队那一刻:`44 fmSpread` 开头调 `fmClaim(F, mates)`,
把名下的船改成听 F 并按 F 重算槽位。`fmClaim` 自带"没换主就不重排"的守卫,
所以没有多归属时它是空操作 —— 单编队路径行为一位不变(不守的话每次下令都 `fmReslot`,
会把随后 `fmReassign` 落盘的配对抹回原序)。

编辑队形那几条路(切模式 / 改几何 / 原地重排)也认领:不认领的话你改了编队1 的阵型,
船却还按编队2 站着,眼睛看到的和改的东西对不上。

### 二、连带要改的四处(都是"从一个名册摘"变成"从每一个名册摘")

| 位置 | 改什么 |
|---|---|
| `fmDetach(s, F)` | 加第二参,只摘指定那一个编队;摘的若是当前主,顺位到 `fms[0]`,槽位跟着清 |
| `fmDelete` | 按**在册**(`fmHasShip`)摘,不能只看 `s.formation` —— 一艘正听别队的船漏摘就留下悬空引用 |
| `fmOnDeath` | 遍历 `s.fms` 的**副本**逐个摘(`fmLeaveOne` 会改 `s.fms` 本身) |
| `fmSameShips` | 现在可能同时匹配多个编队(名册一模一样是合法的)。平手取**这批船正在听的那一个** |

## FM7b 方位盘内外圈切换(2026-09)

编组控制页的方位盘右上角、缩放滑块之上,加一个两态钮:

| 视图 | 基准贴合半径 | 看得见什么 |
|---|---|---|
| 外(缺省) | 最远的站位/插槽 | 四条带都在画面里 |
| 内 | **被护带** × 扁率 | 屏护与哨戒被挤出视野,贴身与被护那几个插槽摊开 |

**为什么需要**:带半径是从近防射程算出来的,贴身 5k 与哨戒 60k 差着十几倍 ——
全塞进一个盘里时,内圈那几个插槽挤在中心一小撮,方位读不出来、更别说拖。
实测切到内圈后插槽横跨从 301px 变成 1094px。

**为什么贴 `body` 而不是 `close`**:只贴 close 的话被护带整圈落在视野外,画面像"图裂了"(实测只剩 1 条圈在视口内);
贴 body 时贴身与被护两条都完整,屏护恰好在边缘露一段,还能看出自己在整体的什么位置。
这条判断已经钉进判据(`rInN >= 2`)—— 只判"圈变少了"抓不到它。

它改的是**基准贴合半径**,不是缩放倍数,所以玩家拖过的 `zoom` 在切换之后仍然生效,两者叠乘(实测 2437→4874)。

### 判据与两个坑

判据打【画出来的圈】而不是状态字段 —— "字段改了但 `fitR` 没接上"才是这类改动的典型坏法(变异一即此,转红)。

**探针自己踩的坑**:点完切换钮走的是 `fmPageRender()`,整页节点都换过了,
早先查到的那个 `<input data-fpz>` 引用已经悬空,对它赋值等于往脱离文档的节点上写 ——
第一版"内圈下 zoom 仍叠乘"两次读数一模一样(2437→2437),看着像功能坏了,其实是探针自己拿着旧引用。

## FM8 「能力偏向强度」是空操作,合并成「要害偏好」+ 每群容量滑块 + 方位盘比例尺(2026-09)

用户说「能力偏向维度和要害站位偏好这两个效果不好,看能不能融合」。先量,结论比"效果不好"更硬。

### 一、`bstr` 不是效果不好,是【数学上的空操作】

四套站位 × `bstr` 0→2,八条实测:

```
固定模板  boost={}                          总契合=[7.000000 ×5]  指派逐位相同=true
空中为主  boost={aaChan:1.6,aaClose:1.6,…}  总契合=[6.500000 ×5]  指派逐位相同=true
水面为主  boost={gun:1.8,surv:1.4,c2:1.2}   总契合=[7.550000 ×5]  指派逐位相同=true
水下为主  boost={esm:1.8,ir:1.6,stealth:1.3} 总契合=[7.000000 ×5]  指派逐位相同=true
```

**原因**:每个可指派站位的 `req` 只有一个键,而 `fit = Σ(w·have)/Σw` ——
单键时 `= (w·have)/w = have`,**权重整个被约掉**。唯一有两个键的「阵心」由旗舰固定占据、不参与指派。
所以这个滑块从 FM4 上线起就一直是装饰。

### 二、融合:偏向从 `fit` 挪到 `prio`

乘在契合度权重上会被归一化约掉,乘在**站位重要性**上不会。于是两个东西本来就是同一件事的两半:

```
imp(站位) = 实测影响力 w(cap) × 本站位表的 boost(cap) × 次序衰减 1/(1+k·0.10)
prio     ×= 1 + pref·(w·boost − 1)        ← 一个滑块「要害偏好」
```

`pref = 0` 时 `wEff` 恒为 1 ⇒ **prio 与改前逐位相同**,默认值不动任何既有行为;往上拖才开始把好舰往要紧的站位塞。

**影响力 `w` 不是我编的**,是 FM4 那次沙盘实测(删掉该维全部插槽的总契合损失)按通道归一:
通道 1.00 > 贴身 0.44 > 主炮/红外/网络 0.36 > 电战/生存 0.24 > 射频 0.11 > 隐蔽 0.06。
这就是用户问的"能不能和能力优先度挂钩" —— 现在挂上了,而且挂的是实测数据。

实测 `pref=1` 时站位重要性:`正前屏护 1.000 / 后方屏护 0.714 / 左贴身 0.293 / 电战位 0.141`。

### 三、另外三样

- **每群容量** `gcap` 从写死的 `FM_GROUP_CAP=16` 变成每编队可调滑块(整数,4~32)。实测 4/8/16 → 3/2/1 个任务群。
- **「站距」→「同簇间距」**(用户令:站距不清楚)。"同簇" = 挤在同一个插槽上的那几艘。
- **方位盘加比例尺**(左下角)。用户实报:*没有比例尺,差点以为带半径滑块没起作用*。
  这张盘的缩放是自适应的 —— 换编队、切内外圈、拖缩放,像素与公里的换算就变一次,
  没有比例尺时"圈变大了"到底是半径变了还是视野变近了根本分不出来。
  长度取 1/2/5 × 10ⁿ 里第一个撑到 80px 以上的,读数永远整齐(10k/50k/100k),不会出现 87k。
  **主地图早就有一条**(81-background,v111),所以"带位置/相对距离的地方要有比例尺"这条规矩现在两处都守住了。

### 四、判据

判据不打状态字段,打**算出来的量**:

- `pref`:`pref=0` 与 `pref=2` 的指派必须不同;`pref=1` 时通道站位的**最低** prio 要高于最轻那个站位的 2 倍以上。
- `gcap`:4/8/16 的任务群数必须递减且 16 时为 1。
- 比例尺:拿**哨戒圈的像素半径 ÷ 它的真实公里半径**反推 px/km,与"条长 ÷ 标注公里数"比,四档视图下都要一致(<2%)。
  这一条比"元素存在"强得多 —— 把标注写死成 50k,元素还在、判据立刻转红。

四个变异逐条对照:`pref` 不接上 / 影响力权重全设 1 / `gcap` 不接上 / 比例尺标注写死 —— 各自打红对应那条。

**一个探针自己的坑**:9 舰只生成 8 个站位(n−1),固定模板前 8 个里**没有哨戒带**那几个,
所以第一版拿"最轻的隐蔽/射频"去比时取不到值(`pDim` 停在 1e9)。改成与本次真的生成出来的那些里最轻的比。
另:每群容量是整数滑块(`step=1`),FLOW38 那条"逐个拖动"给它 +0.5 会被浏览器吸附回整数,
`F.P` 与 `want` 对不上,判据会误报"滑块没接上" —— 整数滑块要用整数增量。


## FM9 / FM9b / FM9c 三件(2026-09)

### FM9 内外圈 = 各舰自己的防空圈,三个钮,不在缩放那一列里

我上一轮把「内外圈」读成了视野预设(贴合到哪条带),**读错了**。用户指的是沙盘
`阵型控制台.html` 里那三个钮:**内圈 / 外圈 / 标注** —— 画出每艘舰【自己的】近防内圈与外圈。

照搬过来,连配色都取沙盘那一套(外圈青 `rgba(79,224,255,.035)`、内圈绿 `rgba(110,231,168,.06)`)。
三点实现要注意:
- 覆盖圈**画在最底下**、`pointer-events` 全关 —— 它是大面积半透明区域,盖住谁都不好,更不能抢插槽圈的拖拽;
- 只画**真的开着近防**的舰(`s.ciwsOn`),关了还画是骗人的;
- 圈开着时要把圈**算进贴合半径**,不然一开就有半个落在画面外(沙盘也是这么处理的)。

三个钮**单独一条横排**在盘的右上角,缩放滑块让到它下面(用户令:从缩放滑块里移出来)。

### FM9b 编组控制页显示的编组与地图上的实际站位不一致(用户实报)

实测:建队后 0/7 不一致,**下过一次移动令之后 6/7 不一致**。症状很好认 ——
**名字对得上、坐标对不上**:`盘上=正前屏护(30,0)　实际=正前屏护(21,-21)`。

两个独立的 bug 叠在一起:

1. **`fmReassign` 交换 `s.fmSlot` 时没有一起换 `s.fmStn`。**
   下令那一刻它按欧氏距离在同签名舰之间重新配对(消航线交叉)并落盘槽位,
   而展示元数据(名字/能力/带/契合度)留在原地 —— 于是一艘船顶着交换【前】那个站位的标签,
   走向交换【后】那个位置。`84-fmplot` 与编组控制页都读 `s.fmStn` 画标签,两处标签一起错。
2. **编组控制页现算一遍 `fmPlanStations` 当配对用。**
   站位**表**是确定的(只由 `P` 决定),但"哪艘船去哪个站位"会被 `fmReassign` 改过并落盘,
   现算拿到的是交换【前】的那一份。这正是 `84-fmplot` 头上那条规矩说的
   *"不在这里重算一遍几何,那样两处必然漂移"* —— 编组控制页违反了它。
   修法不是不算(页面还需要那张完整的站位表,含没人去的空槽),而是算完之后按 `s.fmSlot`
   把配对**对回去**(`fmPgSyncPairs`,按坐标匹配而不是按名字 —— 名字可能重复)。

修完:四种时刻(建队 / 一次令 / 反向令 / 再一次)**坐标与名字都 0/7 不一致**。

### FM9c 统一方位失效(用户实报)

`42-formation` 的注释白纸黑字写着「条令站位:**全员船头随阵型朝向**」,而实现只在固定模式下
按 `ang + fmHdg` 给到达朝向,阵型模式直接用调用方传进来的 `face` —— 而**普通右键移动不带 face**
(只有长按虚影才带)。于是阵型态飞完之后各舰船头是各自的行进方向,实测 `3 −2 −4 −4 −6 −9 −5 −4`,散着。
**文档与实现分家了。**

统一成同一个式子,没有副作用:阵型态 `fmHdg` 恒 0 ⇒ `ang+fmHdg = ang`;
而调用方给了 face 时 `fmAngOf` 的 face 优先分支已经让 `ang` = 那个方向(FM6),
所以**虚影那条路逐位不变**,只是普通移动令现在也对齐了。
实测三次不同方向的移动令:船头全部对齐到 `F.ang`,最大偏差 1.0°;固定态仍是 `F.ang + 各自建队朝向差`。

**两条负对照把 bug 当成了期望值**,一并订正:
- `FLOW36` 的 `带face的令=0(须0)` → 现在要求**每条令都带 face,且等于阵型朝向**;
- `FLOW25` 的「不带 face 对照」原来拿编队做,而编队现在恒给 face —— 改用**散船**。
  那条判据要测的性质(没有 face ⇒ 全程不转头)换成散船照样测得到,而且更纯粹。


## FM10 编队走 Shift 路径点时一路不成形 —— 按弧长配速(2026-09)

用户实报「舰队情况下的 Shift 路径点运动感觉不太对」。

### 一、根因不是档位,是几何

先排除了档位:**全队同型同档照样散**(途中峰值离位 103~136k km,而屏护半径才 50k)。
真因是 FM2 的「下令即算死终点、各飞各的」在多段航线上的必然结果 ——
**转弯时外圈那几艘的折线明显更长**,大家都跑 800 ⇒ 内圈先到、外圈落后,
而中间航点上没有任何东西把他们重新对齐,于是一路散到最后一个点才成形。

判据要打【到达时间差】而不是【离位】:多段航线里"此刻的理想队形"本身在两段朝向之间过渡,
拿任一端去比都会把过渡本身算成误差 —— 第一版就是被自己这把尺子骗了(峰值只从 136k 降到 97k,看着像没效果)。

### 二、只对【追加的航段】配速

`pace = 这一段自己要走多远 ÷ 全队最长那一段`,写在令上,`31-step-ships` 里乘进速度上限。

**新航线(`mode==='move'`)一律不配速**,这一条是试出来的:
按"各自离终点多远"配速 = 让全队等最掉队的那一艘,实测编队掉头航线**峰值 705→288、用时 +57%**,
而且把 FL5 那条「档位逐舰严格生效」也压没了(800 档的船峰值只剩 742)。
**归队本来就该各自尽快赶到,不该互相等。**
追加航点则不同:起点是上一段的航点,也就是各舰已经在队形里的位置,
这时"谁走得更远"纯粹来自转弯几何,正是该配速的那一种。

**这不是 FL5 删掉的那个"取全队最低档"**:档位仍是各自的上限(`cruiseOf` 没动),
只是内圈本来就不需要跑满。FLOW35 的 `档位800/250/800 → 峰值800/250/800` 原样通过。

### 三、效果(从【已成形】的编队出发,即真实用法)

```
有配速    各航点到达时间差 = [20  31  37]s   全程 1385s
关掉配速                  = [20 186 254]s   全程 1311s
```

最后一个航点的前后差从 **254s 收到 37s**,代价是全程 +6%。

**能做到什么、不能做到什么要说清楚**:配速让各段【时长相等】,所以它能防止时间差继续扩大,
但**不能把已经存在的时间差收回来**。从散乱位置直接走航点时,第一段(不配速的那一段)留下的
约 145s 差会一路带着走 —— 实测 `[145 148 148]` vs 对照 `[145 178 296]`:不再扩大,但也没收回。
真要收回得靠每 tick 的反馈(谁跑到队形前面就收油),那正是 FL5 删掉的编队速度上限,没有重新引入。

### 四、散船一位不变

`pace` 只写在编队的令上(`44 fmSpread`),散船那条路恒 `undefined` ⇒ `31-step-ships` 按 1 处理。
`bench_all` **5.8607** 不变就是靠这条,FLOW43 里也直接断言了「散船的令不带 pace」。
