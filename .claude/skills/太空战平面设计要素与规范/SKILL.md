# 太空战平面设计要素与规范

出处与原文摘录见同目录 `references.md`。本文里"必须"是硬规矩,"建议"是默认做法(用户拍板可改)。

## 0 一句话

**舰种等级用"有序 + 前注意 + 冗余"的通道编码,并且必须落在剪影(主形)上;风格只换主形的母题和表面,不碰等级信号。** 缩小后还能分档,靠的是长度、宽长比、可数的大特征、门槛处换形,而不是炮塔样式、面板线这类细节。

## 1 理论依据(每条:结论 → 对舰标意味着什么)

| 理论(业内名字,出处) | 结论 | 对舰标的要求 |
|---|---|---|
| 视觉变量与组织层级(Bertin《图形符号学》1967) | 只有尺寸、明度、纹理粒度是**有序**变量;形状、色相、朝向是**选择性 / 联想性**的,不表达先后 | 舰种等级(有先后)用有序变量;阵营、风格(无先后)用形状 / 色相 |
| 前注意加工(Treisman;Healey 归纳的特征表) | 不聚焦就能瞬间分辨的只有少数特征:尺寸、长度、宽度、数量、闭合、朝向、明度、曲率等 | 一眼区分只能靠这些;炮塔款式、舰桥造型、面板纹理**不是**前注意特征 |
| 瞬时计数 subitizing(Kaufman 等 1949) | 1~4 个元素不用数就知道个数(约 300~400 ms,1~4 一样快) | 4 档等级正好可以用"可数的大特征 1 / 2 / 3 / 4 个"编码 |
| 绝对判断容量(Miller 1956;Eriksen & Hake 的方块尺寸实验) | 单维度绝对判断约 2~3 bit;尺寸约 2.2 bit ≈ 5 档 | 单靠大小分 4 档已在极限边上,小尺寸下更不够 —— 必须叠别的通道 |
| 史蒂文斯幂定律(面积指数约 0.7)+ 分档符号(Flannery;Meihoefer 1969) | 面积差被系统性低估;连续变化的大小读不准,分成几个明显跳变的档才读得准 | 相邻档的尺寸要"跳":长度比建议 ≥ 1.25(面积约 1.6 倍) |
| 冗余编码(Nothelfer 等 2017;北约标号的"形状 + 颜色"双重编码) | 同一信息用两个通道同时编码,分组与搜索更快,也抗色盲 / 单色显示 | 等级至少用 2 个通道同时编码;阵营除颜色外要有形状线索 |
| 剪影可读性(Mitchell 等《Illustrative Rendering in TF2》2007) | 九个兵种只看剪影、没有内部明暗也认得出 | 舰种的区分必须在**纯色剪影**里成立 |
| 主次细三级形状(概念设计通则,Neil Blevins) | 主形 : 次形 : 细节 ≈ 1 : 5~10;眯眼时只剩主形 | 等级信号放主形,风格放次形,质感放细节 |
| 造型语言(方 = 稳重、三角 = 危险、圆 = 亲和) | 基本几何母题自带情绪 | 用来区分阵营 / 风格,不用来区分等级 |
| 语义缩放 / 符号抽象(制图综合;最高指挥官的战略图标;本引擎的 MARK 换记号) | 不同比例尺显示不同层级的信息,小到读不出轮廓就换抽象记号 | 每个尺寸档只承载它读得出的信息(见第 4 节) |

## 2 先例拆解(都是"类别一个通道、等级另一个通道")

- **北约联合军事标号(APP-6 / MIL-STD-2525)**:框形 = 敌我(友方矩形、敌方菱形、中立方形、不明四叶形,颜色同时编码,单色也能读);框内图 = 功能;框外的**编制级别标识**(echelon amplifier)= 规模:点 → 竖杠 → X,档内靠**数量**递进,到门槛**换记号族**。
- **最高指挥官(Supreme Commander)战略图标**:外形 = 单位大类;图标下方小横条 1 / 2 / 3 = 科技等级;内图 = 武器。
- **Beyond All Reason**:外形 = 单位类型;点数 0 / 2 / 3 = 科技等级;内图 = 武器;400 多种单位不用背。
- **EVE Online 图标策略**:形状优先、颜色只做辅助(照顾色盲);同一类按大小分档时用"敦实程度"(bulkiness)区分;角色画在右上角小角标里;小尺寸下单独微调保证可认。
- **本引擎现有轮廓**(`js/ships/10-hull-geometry.js`):每个舰种一个大特征 —— 驱逐"细身 + 十字桅杆"、巡洋"一侧凸出舰桥"、战列"两侧长翼"、航母"方长 + 侧岛";Tier 只改尺寸与明度。思路对,问题见第 6 节。

## 3 通道分配(本游戏的规范)

| 信息 | 通道(主 + 冗余) | 规矩 |
|---|---|---|
| 阵营 / 敌我 | 颜色(蓝 / 红)+ 形状线索 | **必须**:去色后也能分敌我。记号层已有(我方小箭头、敌方接触小菱形);轮廓层建议加不随舰种变的阵营线索(如描边样式),不得占用等级通道 |
| 舰种等级(护卫→驱逐→巡洋→航母) | 长度 + 宽长比 + 可数大特征 + 门槛换形 | **必须**同时用 ≥ 2 个;具体规则见第 5 节 |
| Tier(T1~T3) | 明度(现有 `TIER_LIGHT`)+ 小幅尺寸(现有 `TIER_SCALE`) | 不得与舰种等级抢同一个信号;要再加只用小记号(点 / 短杠),放在剪影外 |
| 角色 / 武器(以后) | 剪影内的小记号或角标 | 不改外形(同 EVE / BAR) |
| 阵营风格(人类 / 其他阵营) | 主形的几何母题、次形、材质、细节纹理 | **不得**改动第 5 节的档位骨架 |
| 识别状态(没认出) | 通用轮廓 `UNK` + 固定 T2 尺寸 | **必须**:没认出不泄露舰种 / 等级(引擎 `shipIdentHull` / `shipIdentTier`);换记号的时机只看全场同一个系数 |

## 4 尺寸预算(本引擎现状,2026-10-05 读码)

舰标长度 = 轮廓长(单位)× `HULL_BASE` × Tier 系数(1.00 / 1.13 / 1.28)× `shipZoomF`(= `hullZoomF` × `SHIP_K` 0.6,范围 0.27~1.14);低于 `HULL_ZOOM.MARK` 全体换 7 px 记号。T1 时的屏幕长度:

| 舰种(轮廓) | 换记号前最小 | 战术落点 | 最大 |
|---|---|---|---|
| 护卫 FF(DD 轮廓) | ≈ 4.7 px | ≈ 5.7 px | ≈ 19.8 px |
| 驱逐 DD(SC 轮廓) | ≈ 5.0 px | ≈ 6.1 px | ≈ 21.1 px |
| 巡洋 CA | ≈ 6.0 px | ≈ 7.4 px | ≈ 25.5 px |
| 航母 CV | ≈ 7.9 px | ≈ 9.7 px | ≈ 33.5 px |

**战术层尺寸**(跳层落点:`hullZoomF` = `LAND` 0.55,`shipZoomF` = 0.33;81-art 的 `artZ` = 1.92 × 0.33 ≈ 0.63)—— 演示页的默认尺寸就用这一组:

| 舰种 | 舰长 T1 / T2 / T3 | 宽(T1,含凸出) |
|---|---|---|
| 护卫 FF | 5.7 / 6.5 / 7.3 px | 2.2 px(舰体 1.0) |
| 驱逐 DD | 6.1 / 6.9 / 7.8 px | 1.9 px |
| 巡洋 CA | 7.4 / 8.3 / 9.4 px | 2.6 px |
| 航母 CV | 9.7 / 11.0 / 12.4 px | 4.5 px |

按尺寸档决定画什么:

| 档 | 舰长 | 能读出的 | 画什么 |
|---|---|---|---|
| L0 记号 | — | 位置、敌我 | 7 px 箭头 / 菱形(已有) |
| L1 剪影 | 5~12 px | 长度、宽长比、1 个大凸起 | 纯色剪影;等级信号必须在这一档成立 |
| L2 主形 | 12~30 px | + 可数大特征、负空间 | 剪影 + 主特征分色 |
| L3 细节 | 30 px 以上(特写窗、选中放大) | + 次形、材质 | 倒角、台体、舰窗等 |
| L4 肖像 | 底栏 / 资料卡 | 全部 | 侧视图 |

**必须**:L1 档两两可分。**必须**:任何区分职责不能只放在 L3 / L4 才出现的细节上。

## 5 分级递进规则(护卫 → 驱逐 → 巡洋 → 航母)

1. **同一骨架,逐档加东西**:四档共用一套档位骨架,每升一档至少改变一个前注意特征,母题不变(家族相似)。
2. **长度跳档**:相邻档长度比建议 ≥ 1.25(面积约 1.6 倍)。现状护卫 → 驱逐只有约 1.07,只能靠形状分,要么拉开,要么让形状差异足够大。
3. **越大越"敦实"**:宽长比随档增大(EVE 的 bulkiness)。建议量级:护卫 1 : 4.5 → 驱逐 1 : 3.8 → 巡洋 1 : 3.0 → 航母 1 : 2.2(风格可整体平移,档间差保持)。
4. **可数大特征 1 → 2 → 3 → 4**:选一种在 L1 / L2 档看得见的特征按档计数(尾部引擎束、侧向外伸对数、炮塔 / 模块组数、散热板对数……)。每个特征在 L2 下限(12 px)时 ≥ 2 px,间隔 ≥ 1 px。
5. **门槛换形**:航母必须有其他三档都没有的剪影特征(长直甲板边、甲板开口 / 负空间、侧岛),同北约"到门槛换记号族"。
6. **细节不承担区分**:面板线、铆钉、舰窗、炮塔款式只在 L3 以上出现,只负责质感和风格。
7. **风格换皮守骨架**:新阵营 / 新风格先对齐档位骨架(第 2~5 条的数值与特征位置),再设计母题和表面;骨架不过检验就不进入细化。

## 6 反例与现状问题(本项目)

- 演示页 `demos/ships/人类阵营舰标.html`(5b684b6)的 **1 海军战列** 与 **4 隐身棱面**:四档主形是同一个母型(细长梭形 / 菱形飞翼),宽长比几乎不变,档间区别只有尺寸和细节(炮塔数、面板线)。缩小到 L1 后炮塔糊掉,只剩长度一个通道,四档难分。违反第 3、4、6 条。
- 同页 **3 工业改装**、**5 硬科幻桁架** 区分更好:靠外伸部件(吊臂、集装箱、散热板)改变剪影;但等级还没有系统地计数编码(第 4 条)。
- 引擎现状:护卫与巡游舰共用 `DD` 轮廓和同一 `HULL_BASE`,地图上完全无法区分;护卫 → 驱逐长度比约 1.07(第 2 条)。
- 引擎导弹(`js/render/81-art.js` 的 `artMsl`,2026-10-05 读码,另一会话未提交的版本):战术层单枚弹长 5 px(≈ 护卫的 0.9 倍),3 / 5 枚一组的外框约 7×6 / 9.5×10 px,比巡洋舰(7.4×2.6)还大;弹长有 4.5~5 px 的下限,拉远时反超护卫(4.7 px)。敌我只靠弹体灰色的微小色偏 + 约 1 px 的阵营色环带,尾焰两方同为橙色 —— 用户原话"现在的导弹我完全不知道是自己的还是别人的"。违反第 10 节。
- 按缩放切换(`shipMarkMode()`,即 `MARK`)现在有:舰船(箭头 / 菱形记号)、石头(小方块)、自己的浮标(蓝圈,10-05 另一会话加的);弹类(83-hud `projMark`,10-05 起)。

## 7 检验方法(交付前必须做)

1. **剪影测试**:只填纯色剪影,在第 4 节 L1 下限(护卫约 5 px)、战术落点、最大三个尺寸各渲染一遍,四档两两能分。
2. **眯眼测试**:再加约 1 px 高斯模糊,仍能分档。
3. **去色测试**:灰度下仍分得清敌我和等级。
4. **两两混淆度**:把每对舰标按游戏尺寸、同一锚点叠放,算剪影差异(1 − 交并比)。建议门槛:L1 下限尺寸时每对 ≥ 0.25(经验值,首次使用时用户试看后校准)。
5. **同屏测试**:地图模拟里多舰混排、缓慢转向、蓝红两色同时出现,光照方向不跟船转。
6. **迷雾测试**:没认出的接触与各舰种同尺寸对比,确认通用轮廓不泄露信息。

## 8 工作流程

0. **先看引擎现状**:做任何新美术资产前,先读第 10 节的画风基线,再打开游戏(或读对应文件)看一遍当前各部分的样子,新东西放进去不能格格不入。
1. 先定**档位骨架**(长度、宽长比、可数特征、航母换形),只画纯色剪影,跑第 7 节 1~4。
2. 骨架过了再做**风格皮**(母题、次形、材质、细节),画法对齐第一版图标页:材质色 + 阵营描边、左上光、边缘倒角、台体投影、凹槽内阴影、舰窗铆钉、引擎光晕。
3. 演示页先行(不加载引擎,放 `demos/ships/` 或 `demos/美术/`),截图自查后交用户挑。**演示页默认尺寸 = 战术层尺寸**(第 4 节第二张表;缩放滑块默认 `hullZoomF` 0.55,不是 1);放大看形状的列可以另加,但打开页面第一眼看到的必须是游戏里的大小。
4. 进引擎时预渲染成按朝向分桶的贴图缓存(直接逐帧画太慢),换记号与打码规矩照第 3 节。
5. 改了任何舰标:回到第 7 节重跑,并把新反例补进第 6 节。

## 9 两套显示模式:真显示 / 代表显示(2026-10-05 用户定)

- **代表显示**:拉远到切换点以下画的简易记号 —— 舰船:我方箭头、敌方接触菱形(拉远后船就显示箭头,中间不留简易轮廓档);石头小方块;自己的浮标蓝圈;弹类(83-hud `projMark`,10-05):导弹 1~3 个点(按枚数,第一颗朝飞行方向)、拦截弹同形调亮、主炮弹沿飞行方向 5 px 短划、雷空心方块(不用菱形,免得和敌方接触混)、诱饵紫点 + 阵营色圈,外框都 ≤ 6 px、阵营色。
- **真显示**:切换点以上画的美术资产 —— 细节舰船(演示页 `demos/ships/人类阵营舰标.html`,未进引擎;进引擎前切换点以上仍是 `drawHull` 纯色轮廓)、细节导弹 / 炮弹 / 尾焰 / 行星 / 石头 / 残骸 / 浮标(`js/render/81-art.js`)。
- **必须:只按缩放切换,不做单独开关;切换点 = 舰船换箭头的那个点**(`shipMarkMode()`,即 `hullZoomRaw() < HULL_ZOOM.MARK`;10-05 用户定)。一个切换点、两档;全场同一个系数,所有物体在同一个缩放上一起换,不看任何单个物体的字段(换的时机不泄露体型 / 分级)。
- **必须**:切换时位置不变;切换不多给情报 —— 两套都守第 3 节的通道分配与打码,真显示不能画出感知层不知道的东西;记号读不出的(如舰种)本来就不画。记号的大小照现在舰船箭头的规矩(固定像素尺寸,不跟舰标缩放)。

## 10 美术资产的尺寸、阵营色、画风(2026-10-05 用户定)

1. **物品比船小**(必须):内核里的船本来就不大(第 4 节战术层表:护卫 5.7 px、巡洋 7.4 px),所以有真实美术资产的物品(导弹、拦截弹、炮弹弹头、雷、浮标、诱饵罐……)不能跟船一样大,至少要小一点 —— 既看得见,大小关系也合理。先例:浮标最长处 = 最小舰 T1 舰长的 0.8 倍(另一会话 10-05 按用户"比船小一点点"定的)。
   - 要在整个缩放范围(`MARK` ~ `MAX`)里都成立:给物品设像素下限时,下限不能让它在拉远时反超船。
   - 成组画的(导弹一组 3 / 5 枚)**整组外框也要比船小**(10-05 用户定;基准同上,按最小舰 T1 舰长)。
   - 尾焰、拖影、爆炸、发光晕这类效果**不算物品**,不受这条限制(10-05 用户定)。
2. **阵营色**(必须):有归属的美术资产一眼看得出是谁的。阵营色要落在战术层尺寸下读得出的部位(弹体主色、整圈描边、外发光等),不能只靠 1~2 px 的环带、标记(同第 5 节第 6 条:细节不承担区分);去色后最好也能分(第 3 节)。颜色沿用 `ART_SIDE`:蓝 `[90,167,255]`、红 `[255,107,107]`、中性 `[160,170,185]`;归属没认出的画中性色,不泄露。
   - 真显示的细节舰船同样适用:材质灰 + 阵营色描边的画法,缩到 6 px 时阵营色可能只剩一圈细线,要在第 7 节的测试里专门看敌我。
3. **画风一致**(必须):做新美术资产前先看引擎当前各部分的美术效果,不要格格不入。现行基线(81-art 文件头):
   - 手画矢量 + 预渲染贴图;渐变、噪声只在建贴图时做,每帧只贴图;发光用 `'lighter'` 叠加。
   - 固定光向 `ART_L`:左上 −125°,不跟恒星走,也不跟物体转(行星亮面例外:朝恒星)。
   - 尺寸跟舰标同一个缩放系数(`artZ` = 1.92 × `shipZoomF`)。
   - 尾焰按用途分色:主推蓝、反推橙、侧推黄、导弹橙、拦截弹青。
   - 界面动画走墙钟,不跟倍速。
4. **演示页默认按战术层尺寸**(必须):以后的美术展示页,舰船默认就按战术层大小显示(第 4 节第二张表),物品跟它摆在一起比,作为参考。
5. **美术整体缩放**(必须,10-05 用户定):所有真显示资产(船、尾焰、导弹 / 拦截弹、主炮弹、雷、诱饵、浮标、命中 / 击沉、近防火花、护盾受击、残骸)共用一个总系数;想让船大一点就调这一个数,其他跟着一起大,武器对船的倍数不变。代表显示的记号(固定像素)和行星(照实际大小)不跟。
6. **特效随缩放**(必须,10-05 用户定):命中 / 击沉、近防火花、护盾受击的大小 = 战术落点上的大小 x 船的不钳系数开平方(船缩 0.5 → 特效 0.71);用不钳的原始系数,拉过切换点船换了记号,特效照样慢慢变。挂在物体上的尾焰、主炮弹拖影跟物体走,不在此列。
7. **边界羽化**(10-05 用户定):比例尺 1.5 万 km 起渐入、3 万 km 满,船 / 残骸 / 导弹 / 雷 / 诱饵整体带最多 0.5 px 的轻微模糊,抹掉几像素大小时明暗台阶的锯齿和转向时的闪;先画进离屏再整张模糊(逐笔模糊会让描边和填色各糊各的);尾焰、爆炸、行星本来就软,记号不羽化。代价:一两像素宽的东西会略暗。
